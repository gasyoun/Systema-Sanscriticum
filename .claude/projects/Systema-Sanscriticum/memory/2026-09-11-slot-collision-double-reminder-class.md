# Две живые строки расписания в одном слоте — класс «задвоений», который не ловит ни одна прежняя гвардия

_Created: 11-09-2026 · Last updated: 11-09-2026_

## Факт (инцидент 11-09-2026, курс 348, чат -1001907383186)

Перенос занятия на слот, где уже жила другая строка серии (1489 «#76» + 1490 «#77», оба 11.09 20:00) → обе строки вошли в T-60 окно → **два поста «Скоро занятие» в одну секунду**. Ни одна из прежних гвардий это не ловит by design:

- `TelegramSendGuard` — sha256(чат+текст): тексты различаются только номером титула «(#76/#77, …)»;
- `zapisi_reminded_at` — построчный дедуп диспатча;
- cross-guard PR #2109 — между фичами (zapisi↔autopost), не между строками;
- `dm_suppressed_when_group_chat` — ЛС vs пост, не строка vs строка.

## С 11-09 закрыто кодом (PR #2499, прод b30d2317)

- `ScheduleMover::reschedule` — throw на занятый слот своей группы; `cancelAndShiftWeek` — отказ на пред-коллизию в цепочке (иначе +7 катает дубль вечно). ВАЖНО: внутрислотные цели нормального каскада — норма (цепочка сдвигается атомарно), не «ломать» их проверкой на все строки.
- Все три продюсера напоминаний (`zapisi:remind-classes`, `classes:post-group-link`, `classes:remind-upcoming`) группируют по (группа, старт): один пост на слот, помечаются все строки слота.

## Правило

1. При любом трогании `ScheduleMover` или продюсеров напоминаний — регресс-тесты коллизий обязательны (ScheduleMoverTest, RemindZapisiClassesTest: «two rows in one slot»).
2. «Задвоилось» ≠ сразу ретрай/вторая фича: сначала свип `GROUP BY group_id, start` (tinker), потом форензика каналов.
3. Номер занятия живёт в титуле «(#N, DD.MM.YY)» и парсится `LessonSeriesInfo`/`WeeklyFinishReport` — при сдвигах строк перетитуловывать номер, иначе «N-е из M» в анонсах отмен врёт.
