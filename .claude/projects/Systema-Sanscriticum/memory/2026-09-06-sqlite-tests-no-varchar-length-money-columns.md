# Sqlite-тесты не проверяют длину varchar — деньги ловит только прод-MySQL (06-09-2026)

`RefreshDatabase`-тесты Systema гоняются на sqlite, который **не enforced'ит varchar(N)**.
Прод — MySQL в strict-mode: лишний символ = `SQLSTATE[22001] Data too long` и падение
команды посреди записи (первый `--apply` H4200: `ip_expense_audits.action` varchar(16)
vs `imported_statement` — 18 символов; 1 строка записалась, аудит упал).

Правила:
1. Новая константа действия/enum-строка, пишущаяся в varchar-колонку, — сверить длину с
   колонкой ДО тестов; sqlite их не поймает.
2. Миграция `->change()` для уже проиндексированной колонки — **без `->index()`**:
   индекс переносится rebuild-ом (sqlite) / переживает MODIFY (MySQL), повторное
   create index падает («index already exists», CI 06-09).
3. Команды, пишущие N строк + аудит на каждую, держать готовыми к до-прогону:
   import_hash-идемпотентность покрывает дозапись, но строка, записанная до падения,
   остаётся без аудита — нужен документированный бэкфилл (см. changes._note аудита id 378).
