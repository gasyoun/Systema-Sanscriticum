# Деньги P0: закрыты открытые пробелы D1–D22 под одним флагом волны `PAYMENT_FIX_WAVE1` + отчёт затронутых строк `money:p0-wave-report` (H5442, Opus 5.5 `claude-opus-5-5`, 24-09-2026)

Повторная проверка `main` и H5007 (PR #2624) показала: из решений реестра [DECISIONS_MONEY_LEDGER_AND_RECONCILIATION_2026.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/DECISIONS_MONEY_LEDGER_AND_RECONCILIATION_2026.md) открытыми оставались сверка суммы PayPal-заявки, стабильный ключ повтора, повторное удержание возврата, двойной пакет выплаты блока, EUR мимо авансов и отрицательный итог в рублях. Все правки — только при `PAYMENT_FIX_WAVE1=true` (по умолчанию выключено).

- PayPal-заявка (D4/D20): сумма и валюта сверяются с ценой тарифа; ±5% — автоподтверждение доверенному ученику, недоплата — уведомление на экране и в письме; вне допуска или без цены в валюте — `pending` на ручную проверку. Проверка пишется в `claim_meta.amount_check`.
- Повтор заявки: стабильный `payments.claim_replay_key` (txn глобально, иначе пользователь+тариф+дата+валюта+центы) с уникальным индексом — гонка двух отправок даёт одну строку.
- Возврат удерживается из выплаты один раз (D11, аудит MEDIUM #12); один пакет выплаты на блок через `teacher_payouts.settlement_key` (D13, MEDIUM #15).
- RUB — источник истины (D14): EUR выводится из итогового RUB после авансов и прямых поступлений (MEDIUM #13); отрицательный итог и отрицательная база прошлых блоков → 0 + типизированное исключение сверки.
- Доступ fail-closed: волна включает `grant_access_fail_closed`; доверенная заявка на курс без групп остаётся `pending` с исключением `no_access_groups`.
- `php artisan money:p0-wave-report [--json=]` — отчёт затронутых строк внутри откатываемой транзакции с подсчётом записей (любая запись → выход с ошибкой).
- Тесты: `MoneyP0WaveTest` (19), каждый дефект воспроизводится при выключенном флаге.
