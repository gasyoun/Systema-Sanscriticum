- **H3952 (Opus 5 `claude-opus-5`, 02-09-2026): сбой per-account fresh-link в ZOOM 1.4 больше не выглядит как «вебхук не пришёл» — прогон падает и называет причину.** H3687 29-08 построил сам per-account fresh-link (реестр аккаунтов, свитчи, пары нод «Свежая ссылка (Цыди)/(Гасунс)»), но НЕ сделал его отказ наблюдаемым, и три пути по-прежнему завершались `success` при недоставленной записи: (1) `neverError:true` превращал Zoom `3301`/`401` в обычный выход, а `Code in JavaScript1` всегда отдаёт непустой `download_url`, поэтому гард «Есть запись?» пропускал прогон дальше и сломанный cred не оставлял вообще никакого следа — он всплывал через несколько дней, когда replay >24 ч упирался в тот же cred; (2) «TG: replay недоступен» был терминальным узлом — алерт уходил, exec заканчивался зелёным; (3) false-ветка гарда была тупиком. Добавлены «Диагноз fresh-link» (классифицирует исход, payload пропускает без изменений, при деградации шлёт `⚠️ Fresh-link деградировал` в ops-пульс), «Стоп: запись не получена» (HEAD по вебхук-токену → «Вердикт fresh-link» → TG → `throw`, повешен и на false-ветку гарда, и на error-выход «DOWNLOAD свежая (…)») и «Стоп: replay невозможен». **`neverError:true` оставлен сознательно** — снять его значило бы ронять прогоны, которые ещё доезжают по подписанному ≤24 ч URL; хендофф прямо разрешает оставить флаг за явным ассертом. Вердикты разведены так, как требовалось: `credential_fetch_failure` (отказ авторизации, либо `3301` при ЖИВОМ вебхук-токене — запись есть, её не видит cred) против `webhook_missing`; `3301` без живого токена честно помечается `undecidable_3301`, потому что у Zoom этот код двусмыслен, и по ambiguity-policy считается провалом — ложная тревога дешевле тихого успеха. - **Найдено попутно (H3952): прод-ключ `N8N_API_KEY` протух — n8n-строка в `recordings:gap-watch` отдаёт `n8n HTTP 401`.** Проверено на .92 (`php artisan recordings:gap-watch --dry` печатает `n8n 1EIqqNzMl5NNIxST: n8n HTTP 401`), три ключа в базе n8n проверены по очереди: два отвечают 401, третий (`oxalpha-ops`) живой, но у него нет скоупа `execution:retry`, поэтому подменить им ключ нельзя — сломается лента `--retry-failed`, включённая на проде (`RECORDING_GAP_RETRY_FAILED_ENABLED=true`). Пока ключ не заменён, строки `↳ вердикт:`/`↳ вебхук-токен:` на проде не покажутся: логика запинена тестами, но живой алерт слеп. Нужен человек: n8n UI → Settings → API → новый ключ с полным набором скоупов (включая `execution:retry`) → в прод-`.env` → `php artisan config:cache`. Через API ключ не завести — ни у одного существующего ключа нет скоупа `apiKey:create`.
