# Слот-гвардии расписания: перенос на занятый слот — ошибка, один пост на слот (OxAlpha zai-coding-plan/glm-5.3-flash via opencode, 11-09-2026)

Инцидент 11-09 (курс 348 «Избранные главы из Бхагавадгиты 4 цикл», чат -1001907383186): перенос занятия лёг на существующую строку серии — две живые строки (1489 «#76», 1490 «#77») на одном слоте 11.09 20:00 ушли **двумя** «Скоро занятие» в одну секунду (msg 3030/3031). Все прежние гвардии прошли by design: TelegramSendGuard — по sha256(чат+текст), а тексты различались номером титула; `zapisi_reminded_at` — построчно; cross-guard [PR #2109](https://github.com/gasyoun/Systema-Sanscriticum/pull/2109) — межфичевый (zapisi↔autopost), не межстрочный; `dm_suppressed_when_group_chat` ([PR #2156](https://github.com/gasyoun/Systema-Sanscriticum/pull/2156)) — ЛС vs пост, не строка vs строка.

- **[ScheduleMover](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Schedule/ScheduleMover.php)**: `reschedule` бросает `InvalidArgumentException` при переносе на занятый слот своей группы (все админ-пути — Filament «Перенести», бот-reply, `schedule:cancel` — идут через него); `cancelAndShiftWeek` отказывается каскадить цепочку, в которой уже есть две живые строки в одном слоте (иначе +7 воспроизводит коллизию вечно). Внутрислотные цели нормального каскада не задеваются (цепочка сдвигается атомарно).
- **Слотовая группировка продюсеров**: `zapisi:remind-classes`, `classes:post-group-link`, `classes:remind-upcoming` группируют работу по ключу (группа, старт) — ровно одно уведомление на слот, помечаются ВСЕ строки слота, кросс-гвардии проверяют любую строку слота. Даже заведённая руками дубль-строка больше не доходит до студентов дважды.
- **Data-fix на проде (tinker, до деплоя)**: schedule 1490 soft-delete, хвост 1491–1504 перетитулован #78–#91 → #77–#90 (номер из титула парсится [LessonSeriesInfo](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Schedule/LessonSeriesInfo.php) — консистентность номеров чинит и «N-е из M» в анонсах отмен), дубль-пост 3031 удалён из чата ботом (ok:true), строка из `telegram_chat_posts` подчищена. Свип-2026 по группам и чатам: других коллизий нет; 04-09 логи — одиночная отправка (промежуточной коллизии #75+#76 не было).
- Тесты: гвардии Mover (throw + данные не тронуты + слот чужой группы не блокирует + чистый каскад зелёный), слотовый дедап всех трёх продюсеров, зеркальный skip autopost при помненной zapisi любой строки слота. CI полный зелёный (PHP 8.3 tests 5m56s), Pint clean. Прод `52444f7a → b30d2317` (deploy.sh, смоук сайт 200 + кабинет OK).
