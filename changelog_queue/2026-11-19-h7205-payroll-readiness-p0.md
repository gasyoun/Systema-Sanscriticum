# Payroll readiness: P0-закалка — экспорт write-once и открытые исключения сверки

Независимый кросс-семейный ревью 22-10 нашёл в слое готовности октябрьских выплат два P0: приватный экспорт писался в путь, привязанный к дате среза, поэтому повторный запуск молча затирал утверждённый артефакт (в поле это уже случилось с реестром 28-09), а «свежая» сверка игнорировала открытые денежные исключения — один COMPLETE-прогон на дату среза открывал бы выплаты при необработанных расхождениях.

Теперь:

- Повторный экспорт на уже занятый путь отказывает с ненулевым кодом и называет оба отпечатка — incumbent и live; переутверждение — сознательный акт (артефакт убирается вручную или экспорт идёт в уникальный путь).
- `--expect-fingerprint` читает артефакт с диска: подменённый артефакт ловится сам по себе, а не только через дрейф живых данных.
- Любое ОТКРЫТОЕ `MoneyReconException` держит каждую строку переписи (hold `reconciliation_open_exception:<type>`), даже когда COMPLETE-прогон сверки существует на дату среза; открытые исключения — часть решения о выплате, а не только отчётное поле.
- Манифест доказательств обязан называть файл каждого источника (`path`), байты перехэшируются против заявленного sha256, а хеш, уже принадлежавший другому манифесту, отклоняется (приватный сайдкар `evidence-hash-ledger.json`, пишет только команда при свежем манифесте).
- Относительный путь вида `public/payroll.json` больше не проходит мимо запрета публичных путей; команда отказывает при выключенном флаге `teacher_payroll_readiness`; read-only proof видит UPDATE существующих платежей (суммы amount/amount_foreign входят в денежный отпечаток).

Семантика переписи 23 преподавателей, диспозиции, порядок финансирования каналов и политика прямых поступлений не изменились; флаги остаются default OFF; денежные таблицы не затрагиваются.

Следствие для оператора: отпечатки меняются с этим кодом — действующие утверждения после деплоя нужно переутвердить, а манифест доказательств готовить с полем `path` у каждого источника.
