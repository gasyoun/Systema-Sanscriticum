# H4978 follow-up: catch `\ImagickException` in certificate JPEG download (Sonnet 5 `claude-sonnet-5`, 17-09-2026)

Re-running PR #2625's CI against a fixed `origin/main` (after H5033 landed) surfaced a new, real `PHP 8.3 — tests` failure in H4978's own new smoke test: `StudentControllerPhase1SmokeTest::test_download_certificate_image_route_resolves_without_crashing` got HTTP 500 instead of the expected `[200, 302]`.

- **Root cause:** the CI runner has the `imagick` PHP extension loaded (it is not in `.github/workflows/ci.yml`'s explicit `setup-php` extension list, but present via the base tool-cache image regardless) with its ghostscript PDF delegate missing. `Imagick::readImageBlob()` inside `CertificateService::pdfToJpeg()` then throws `\ImagickException`, which extends `\Exception` directly — not `\RuntimeException` — so `downloadCertificateImage()`'s `catch (\RuntimeException $e)` let it propagate uncaught to a 500.
- **Fix:** widened the catch in `app/Http/Controllers/Concerns/ManagesCourseResources.php` to `catch (\RuntimeException|\ImagickException $e)` — both failure modes now degrade the same way (`back()->with('error', $e->getMessage())`), matching the method's existing intent that any JPEG-generation failure should be a graceful redirect, not a crash.
- **Scope note:** this narrows H4978's "no behavior change" claim for this one method only — every other moved method in that pass is still byte-identical. Everything else in H4978 stands as delivered.
- **Verification:** `php -l` clean, Pint clean, `phpunit --filter StudentControllerPhase1SmokeTest` 4/4 pass locally. A union catch type with one nonexistent class (this Mac has no `imagick` extension, so `\ImagickException` doesn't exist as a class here) is safe as long as the thrown exception matches the other listed type — confirmed via a local repro before relying on it.
