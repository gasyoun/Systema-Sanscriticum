# «Участники по блокам»: напоминание об оплате и канал «от имени аккаунта»

На экране «Участники по блокам» (финансы) появился блок «Напоминание об оплате»: выбираете блок, видите список должников — участников групп курса, у которых нет доступа ни к одной половине блока, — отмечаете нужных, выбираете каналы и отправляете.

Должники считаются из групп курса, а не из матрицы «студент × блок»: в матрице только те, кто хоть что-то оплатил, а первый адресат напоминания — как раз тот, кто не заплатил ни разу.

Три канала, у каждого в интерфейсе видно, скольких из должников он реально достаёт:

- **от имени аккаунта** — через Telegram Business: сообщение уходит не от бота, а от аккаунта школы, в тот диалог, который у студента уже есть. Правило Telegram: бизнес-бот пишет только в существующие диалоги, поэтому канал достаёт тех, кто сам писал школе;
- **от бота школы** — по `users.telegram_id`, то есть тем, кто запускал бота;
- **на почту** — через обычное письмо-напоминание.

Дедуп общий с «Реактивацией»: один и тот же студент не получит два напоминания про один блок за 24 часа, с какого бы экрана их ни отправили. Каждый контакт пишется в `debt_reminders` с источником `block_participants`. Отправка от имени аккаунта синхронная — по ней видно фактический ответ Telegram, а не «поставили в очередь и надеемся».

Проверки: пины на канал (`TelegramAccountChannelTest` — резолв чата по `telegram_support_chats.linked_user_id`, отказ для групп и для соединения без права ответа), на рассылку (`BlockReminderSenderTest` — дедуп, журнал, недостижимый получатель) и на экран (`BlockRemindersPageTest` — список должников, отправка отмеченным, отказ без каналов).

Чего канал не делает: он не открывает новых адресатов. Сейчас из 204 должников аккаунт достаёт 20, бот — 32, почта — всех. Числа в скобках у галочек считаются по выбранному блоку, чтобы это было видно до отправки, а не выяснялось по тишине после.
