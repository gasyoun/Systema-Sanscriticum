- **M9 — [`HttpPaypalWebhookSignatureVerifierTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Payments/HttpPaypalWebhookSignatureVerifierTest.php), 20 тестов.** Класс — ДЕФОЛТНЫЙ биндинг `PaypalWebhookSignatureVerifier` в `AppServiceProvider`, то есть это и есть продовый гейт доверия вебхука, а не вспомогательный хелпер. Зафиксировано: skip-флаг закорачивает в TRUE без единого запроса; любой из трёх отсутствующих креденшлов (`webhook_id`/`client_id`/`client_secret`) ⇒ FALSE без сети; провал OAuth (401) ⇒ FALSE + warning `paypal_subscriptions.oauth_failed` со статусом, verify-эндпоинт не дёргается; ответ OAuth без `access_token` / с пустым / с не-string ⇒ FALSE; не-2xx от verify ⇒ FALSE + warning `…webhook.verify_http_failed`; `verification_status` регистронезависим для `SUCCESS` и любой иной статус (`FAILURE`, `PENDING`, `success-ish`, пустой, отсутствующий) отвергается; заголовки PayPal, `webhook_id` и декодированное событие уходят в PayPal дословно, а `Authorization: Bearer` — тем токеном, что вернул OAuth; битый JSON тела деградирует в `webhook_event = []` без фатала; `base_url`-override и выбор live/sandbox-хоста управляют ОБОИМИ вызовами. Отдельный тест пинит контейнерный биндинг интерфейса на HTTP-класс — если биндинг подменят, money-матрица перестанет мерить то, что думает.
- **M10 — [`ClaimTrustPolicyTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Payments/ClaimTrustPolicyTest.php), 11 тестов.** Хотя бы один PAID-платёж даёт доверие независимо от возраста аккаунта; `success` считается PAID наравне с `paid`; `pending`/`failed`/`cancelled`/`refunded` доверия не дают; платёж ЧУЖОГО пользователя доверия не даёт (анти-отмывка); возраст ≥ порога включительно (`lte`), моложе — нет; `created_at = null` не доверяется; порог берётся per-channel (`services.paypal` / `services.bank_claim`); порог 0 и отрицательный (зажим `max(0, …)`) доверяет любому persisted-аккаунту.
- **Находка важнее цифры: `ClaimTrustPolicy` — сирота.** На `origin/main` класс не вызывается ни из одного контроллера: `git grep` по репозиторию даёт только его собственное определение и два комментария в [`config/services.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/config/services.php). Живые каналы используют `User::isEstablishedClaimStudent()` (`PaypalClaimController:118,288`, `BankClaimController:65`, `GasunsPayClaimController:67`) — то есть 100 % покрытия политики есть покрытие библиотечного класса, а не продового предиката. Второе: docblock класса обещает неймспейс `'paypal'` / `'bank_claim'`, а реальные ключи лежат под `services.paypal` / `services.bank_claim` — голое имя молча падает в дефолт 24 ч, и заданный в `env` порог был бы проигнорирован (ловушка зафиксирована отдельным тестом, а не «исправлена» в этом PR). Решение wire-or-delete — за человеком (GTD `@DECIDE`); headline аудита 3/5 этим PR не пере-скоривается, для этого нужен свежий полный прогон.
