# H4672: money-axis SLI — daily mocked synthetic pay + hourly silent-grant reconcile, no live bank charge (Sonnet 5 `claude-sonnet-5`, 14-09-2026)

Original mission asked for a daily LIVE payment through the real production Tochka gateway. No Tochka sandbox exists in this codebase (confirmed) — an autonomous agent executing a real bank charge is out of scope (executing a financial transaction is a prohibited autonomous action). MG ruling 14-09-2026: redesign the synthetic-pay leg as a **mocked webhook**, signed with a dedicated SLI-only keypair that is never the real Tochka bank key; a live bank charge/refund stays a human-triggered ops action.
- **`money:sli-synthetic-pay`** ([app/Console/Commands/MoneySliSyntheticPay.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Console/Commands/MoneySliSyntheticPay.php)): creates a `Payment` (amount=0) for a dedicated hidden fixture user/course/group ([MoneySliFixture](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Support/MoneySli/MoneySliFixture.php), H1946 naming convention — `@example.invalid`, never `@example.com`), signs a Tochka-shaped JWT with `MONEY_SLI_WEBHOOK_PRIVATE_KEY` and POSTs it at the real `/api/webhooks/tochka` route, asserting `payment.status===paid` **and** the buyer actually landed in the course group — the exact `Payment::grantAccess()` path a real purchase exercises. Flap-tolerant (3 attempts, mirrors `probeOutboundPaymentTls`): a single transient blip does not page. `finally{}` always revokes the group and reverts `paid`→`canceled` (mock-equivalent of auto-refund+revoke — no real refund needed, amount is always 0), so the probe leaves zero standing footprint.
- **`WebhookController::tryDecodeWithSliKey()`** ([app/Http/Controllers/WebhookController.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Http/Controllers/WebhookController.php)): additive-only SLI-key fallback, tried **only** after the real bank key fails to verify, gated behind `features.money_sli_synthetic_pay` + a configured `services.tochka.sli_webhook_public_key`. Real Tochka webhooks succeed or fail entirely on the first (unchanged) attempt against the real key — this path never sees them.
- **`money:sli-hourly-reconcile`** ([app/Console/Commands/MoneySliHourlyReconcile.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Console/Commands/MoneySliHourlyReconcile.php)): read-only — webhook success-rate over the window (`payment_webhook_events.decision`, with a `min_sample` gate against low-traffic noise) plus an H2085-class silent-grant scan (a `paid` payment on a course that needs groups whose buyer never actually landed in one). "Balance deltas" from the mission is deliberately scoped down to paid-payment volume in the window — a full wallet/referral/deposit ledger reconciliation would be its own handoff, flagged as a known limitation.
- **SLI logging + two-tier paging**: both commands append a row to `storage/app/money_sli/money_sli_daily.tsv` ([MoneySliAlerter](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Support/MoneySli/MoneySliAlerter.php)), ping a Better Stack heartbeat (drop-in `docs/UPTIME_BETTERSTACK_MONITORING.md` contract, success/`../fail`) and, on failure, page the critical TG chat with a cooldown fingerprint state file ([MoneySliAlertState](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Support/MoneySli/MoneySliAlertState.php), H3197 pattern — a JSON file, not Laravel Cache, so `optimize:clear` on deploy can't cause a spurious re-alert) — per MG's 14-09-2026 ruling that money+prod always gets Better Stack + TG, never soft-only.
- Both commands default **OFF** (`MONEY_SLI_SYNTHETIC_PAY` / `MONEY_SLI_HOURLY_RECONCILE`, `config/features.php`) and are wired as their own crontab lines ([`scripts/server_guards/cron/app-user.crontab`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/scripts/server_guards/cron/app-user.crontab)), never inside Laravel's `Schedule::command()` — same "a long job must not share the scheduler's fate" reasoning as `cabinet:probe` (H1917).
- Tests: [`TochkaWebhookSliFallbackTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Webhooks/TochkaWebhookSliFallbackTest.php) (4 — flag-off rejection, SLI-key acceptance+grant, real bank key unaffected, an unrelated third key still rejected), [`MoneySliSyntheticPayCommandTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Console/MoneySliSyntheticPayCommandTest.php) (3 — healthy grant+revoke, transient failure recovers within the retry budget, sustained failure exhausts all attempts and hits the fail heartbeat + TG — the mission's explicit "a stopped webhook is caught by the probe" requirement), [`MoneySliHourlyReconcileTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Console/MoneySliHourlyReconcileTest.php) (2 — H2085 silent-grant flagged, healthy no-false-positive). 972 tests in the combined webhook/payment/checkout/deposit/referral/access suite green, no regressions. Pint clean. `docs/ENVIRONMENT_VARIABLES.md` regenerated for the new `env()` keys.
- **Prod activation stays a human step** (DEPLOY_QUEUE): generate the SLI keypair on the VPS, set the `MONEY_SLI_*`/`TOCHKA_SLI_WEBHOOK_PUBLIC_KEY` env vars, create the two Better Stack heartbeat monitors, prove one manual green run of each command, only then flip the two feature flags and install the updated crontab.
