# Telegram /кабинет self-provision (OxAlpha z-ai/glm-5.3-flash, 02-09-2026)

Telegram bot self-provisioning command `/кабинет <email>`: unlinked student creates their own cabinet in one step from a private chat with @samskrtamru_bot and receives a one-time magic login link — no human involvement (motivating case: lena_mast / zimushka@list.ru in @rusamskrtam).

- New [CabinetProvisionBotCommand](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Bot/CabinetProvisionBotCommand.php), wired into [TelegramWebhookController](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Http/Controllers/TelegramWebhookController.php) as its own else-chain branch (private chats only; groups already return early).
- Same contract as guest self-register (H3643): random password never sent, `AttributionService::applyToNewUser()` + `signup_source=telegram`, `FreeTierLessonGranter->grantSignupFor()` (free playlists), `telegram_id` bound at creation, login via one-time `MagicLinkToken` (purpose `tg_login`, TTL 15 min).
- Guards: flag `telegram_cabinet_provision` default OFF (`TELEGRAM_CABINET_PROVISION=true` + `config:cache` to enable, sub-flag of `telegram_cabinet_login` era); ≤1 creation per `telegram_id` forever (cache cap, tested after unlink); existing email NEVER overwritten or bound by bare email knowledge (takeover risk) — soft refusal; linked user gets a login link, not a second account; non-email argument gets a usage hint; group messages ignored.
