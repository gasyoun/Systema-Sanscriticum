- **Атрибуция «клик по офферу кабинета → подтверждённая оплата» за флагом `cabinet_offer_attribution` (default OFF) + агрегат в cabinet baseline-отчёте (H7968, PR [#4321](https://github.com/gasyoun/Systema-Sanscriticum/pull/4321), merged 19-11-2026).** Минимальная наблюдательная связка без единого изменения платёжной обработки и выдачи доступа: [`PaymentTelemetryObserver`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Observers/PaymentTelemetryObserver.php) (read-only, отдельный обсервер по прецеденту `PaymentAuditObserver`) читает состоявшийся переход `status→paid` (created + updated, включая born-paid) и зовёт [`OfferPurchaseAttribution`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Activity/OfferPurchaseAttribution.php) — сервис самогуардируемый, никогда не бросает исключение в платёжный поток. Правило связки явное и не-причинное: user + оффер + окно (`cabinet_offer_attribution_window_days`, default 7 сут) + `Payment::PAID_STATUSES`; клик с course-идентичностью должен совпасть с `payment.course_id` — иначе «unrelated», лестничные клики без course-идентичности вяжутся только по user+окну; клик старше окна на момент подтверждения = «expired»; берётся последний подходящий клик; **ровно один** `offer.purchase` на `payment_id` — повторные/перевёрнутые webhook-callbacks дубля не дают (дедуп по payment_id). Unpaid/failed/refunded-before-confirmation до paid не доходят — событие не пишется. Новое значение события в [`ActivityEvent`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Models/ActivityEvent.php): `OFFER_PURCHASE = 'offer.purchase'` (server-only, НЕ в `CLIENT_CABINET_EVENTS`). Конфиг — [`config/features.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/config/features.php): `cabinet_offer_attribution` = `env('CABINET_OFFER_ATTRIBUTION', false)` — **выключен по умолчанию, прод не активирован**; env задокументирован в [`docs/ENVIRONMENT_VARIABLES.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/ENVIRONMENT_VARIABLES.md). Отчёт [`CabinetBaselineReport`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Console/Commands/CabinetBaselineReport.php) получил агрегат-секцию: attributed purchases (COUNT/DISTINCT), unmatched-клики (ноль — тоже результат), определение окна и явный дисклеймер «НАБЛЮДАЕМЫЕ атрибутированные конверсии, НЕ причинный revenue lift». PII-минимально: агрегируемые скаляры (id/счётчики/окно), без сумм, контактов и экспортов. Тесты [`OfferPurchaseAttributionTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Activity/OfferPurchaseAttributionTest.php) 8/8 (18 assertions): ровно одна эмиссия, дедуп повторных callback'ов, born-paid путь, unpaid/failed/refunded не считаются, unrelated и expired клики не считаются, flag-OFF сохраняет прежнее поведение байт-в-байт, отчёт различает наблюдаемое и причинное; смежные money/access-пояса зелёные (CheckoutPrice/SalesFunnelReport/CabinetTelemetry/HybridShellTelemetryBeacons 25/25 + TochkaWebhook/TeacherSalaryService 47/47), CI merge-state зелёный, включая «MySQL 8.4 — finance/webhook transactions». Честная оговорка: флаг OFF, код на проде дремлет — живого замера нет; активация — human-gated (`CABINET_OFFER_ATTRIBUTION=true` + `php artisan config:cache`), post-activation canary и one-week benefit baseline запланированы строкой GTD `YMR` (Uprava); обещать revenue lift от инструментации нельзя — только наблюдаемые атрибутированные конверсии после активации.
