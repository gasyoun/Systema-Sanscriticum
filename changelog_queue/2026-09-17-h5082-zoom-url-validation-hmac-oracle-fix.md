### Fixed

- **Zoom-вебхук перестал быть неаутентифицированной HMAC signing oracle (OxAlpha `zai-coding-plan/glm-5.3-flash`, 18-09-2026, H5082; находка [H5046 run-1](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/changelog_queue/2026-09-17-h5046-security-audit-run1.md)).** `endpoint.url_validation` в [ZoomWebhookController](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Http/Controllers/Webhooks/ZoomWebhookController.php) отвечал `hash_hmac('sha256', plainToken, ZOOM_WEBHOOK_SECRET)` на любой анонимный POST: plainToken выбирает атакующий, а v0-подпись participant-события — это HMAC того же секрета над `v0:{ts}:{body}` — выбрав `plainToken = "v0:{ts}:{body}"`, получал готовую валидную подпись для подделки событий посещаемости. Теперь проверка `x-zm-signature` (v0) выполняется **до** ветки url_validation для всех событий: Zoom подписывает челлендж тем же v0-заголовком (санционированный паттерн — indico `vc_zoom` проверяет подпись на всех событиях вкл. url_validation), формат ответа `plainToken`+`encryptedToken` не изменён; forged-события получают 403 и ни байта HMAC (byte-match оракула невозможен). Пустой секрет по-прежнему 503 до любой проверки. Тесты: [ZoomWebhookTest](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Webhooks/ZoomWebhookTest.php) 9/9 (+2 регресса: unsigned url_validation → 403 без plainToken/encryptedToken; forged-signature с plainToken=`v0:{ts}:{body}` → 403 без encryptedToken), ZoomAttendanceTest+ZoomServiceTest 7/28, WebinarProviderSeamTest 7/22. Pint clean. PR-only (прод-репо), деплой отдельным шагом MG — после мержа перерегистрация эндпоинта в Zoom не нужна (формат ответа тот же, подпись Zoom и так шлёт).
