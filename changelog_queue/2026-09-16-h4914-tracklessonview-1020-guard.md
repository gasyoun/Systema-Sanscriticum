# TrackLessonViewJob переживает ER_CHECKREAD 1020 после aborted connection (OxAlpha z-ai/glm-5.3-flash, 16-09-2026)

Инцидент 15-09-2026 ≈13:32–13:51 UTC: два `Aborted connection ... user: 'sail'` — и MariaDB 11.8.6 отдала `SQLSTATE[HY000]: General error: 1020 Record has changed since last read in table 'lesson_views'` / `'user_sessions'` 12 раз за burst на `TrackLessonViewJob` (user_id=6476), self-recovered. Корень: job едет read-then-INSERT/UPDATE по соединению с протухшим row-handler после абортов; все 208 таблиц InnoDB (MyISAM-гипотеза снята). Handoff [H4914](https://github.com/gasyoun/Uprava/blob/main/handoffs/H4914-OxAlpha_Systema-Sanscriticum_tracklessonview-1020-ercheckread-guard_15.09.26.md).

- [TrackLessonViewJob](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Jobs/TrackLessonViewJob.php): выделенная ветка для ER_CHECKREAD 1020 в `handle()` — лог-маркер `retryable ER_CHECKREAD 1020` и ретроу наружу: Horizon ретраит по backoff [10, 30, 60], а failed_jobs пишется только при исчерпании `tries=3` — успешный ретрай строки в failed_jobs не даёт. Детектор проверяет и `errorInfo[1]`, и текст драйвера («1020 … Record has changed since last read») — обёртки не во всех путях доносят errorInfo. Ловится `\Throwable`, а не только `QueryException`: Laravel сам признаёт «Record has changed since last read» concurrency-ошибкой и под вложенной транзакцией оборачивает её в `DeadlockException` (установлено тестом на CI).
- **Идемпотентность под ретрай закреплена кодом, не надеждой**: транзакция атомарна (откат 1020 убирает и счётчики), а оставшуюся гонку «двое увидели „строки нет“» разруливает catch duplicate-key (SQLSTATE 23000/1062 по unique `user_id+lesson_id`): перечитали строку → считаем существующим просмотром, `total_lessons_opened` не инкрементится второй раз; 1062 без видимой строки — честный ретрой.
- Аудит прочих писателей по таблицам: [CloseStaleSessionsJob](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Jobs/CloseStaleSessionsJob.php) — `tries=1`, сессионные сбои глотаются построчно, транзакция атомарна, следующий такт cron'а добивает сам; [HeartbeatController](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Http/Controllers/Api/HeartbeatController.php) — синхронный HTTP без очереди, инкремент SQL-side (`DB::raw`). Паттерн «ретраибельный queue-job + read-then-INSERT в одной транзакции» больше нигде не повторяется — guard расширенного внедрения не требует.
- Не тронуто: конфиг очередей и лимиты Horizon — как приказал handoff.
- **Тесты**: [TrackLessonViewJobTest](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/TrackLessonViewJobTest.php) — 5 кейсов: чистый прогон считает всё по разу; 1020 на последнем стейтменте транзакции → наружу, откат атомарен (0 строк/0 счётчиков), ретрай → ровно один раз; duplicate-key гонка → без double-count; 1062 без видимой строки → ретрой; повторный просмотр не задваивает уникальный счётчик.
