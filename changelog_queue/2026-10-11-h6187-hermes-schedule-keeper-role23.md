- **Hermes W1 роль 23 `schedule-keeper`: актуальный ответ о расписании из канонического источника (H6187; executed by GLM `zai-individual-coding-plan/GLM-5.3`, ~1 ч wall).** Первая роль волны W1 пакета hermes-24-01a10bca (ростер V2, канонический ID 23). Новый [`ScheduleKeeperService`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Support/ScheduleKeeper/ScheduleKeeperService.php): детерминированный ответ-черновик для human-send ТОЛЬКО из таблицы `schedules` + строк групп — без LLM, без записи в расписание, роль OFF по умолчанию (`features.hermes_schedule_keeper`, env `HERMES_SCHEDULE_KEEPER`; включение — deploy-шаг человека, гейты запуска волны остаются за E026). Контракт ответа: время наблюдения (в черновике и в `facts.observation_time` ISO-8601), ближайшие ≤3 занятия, изменения за 14 дней с честным разделением видов — `cancelled` (soft-delete, H3790), `added`, `moved` (прежнее время нигде не хранится, формулировка «изменилось — сейчас в расписании …», паритет с `SupportAnswerFactResolver`); двойное время для не-МСК студентов по H4434 `effectiveTimezone()` («11:00 МСК (13:00 ваше)», с локальной датой при смене дня; невалидная зона → только МСК); устаревший источник не молчит и не уверяет: пустое расписание без каникул (`no_upcoming_lessons`), каникулы без даты возобновления (`vacation_unknown_resume`) или с ней (`vacation_schedule_pending`), ближайшее занятие дальше 45 дней без активных каникул (`next_beyond_horizon`) — всё это `requires_human_verification=true` с машинно-читаемой причиной; дальнее занятие ВО ВРЕМЯ каникул свежо. Тесты: [`ScheduleKeeperTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Support/ScheduleKeeperTest.php) 13/13 (43 assertions, SQLite, `Carbon::setTestNow`): синтетический золотой случай с полным сравнением текста черновика (ближайшие + перенос + отмена одной пиной датой), дуал-время со сменой дня (Владивосток), инвалидная зона, все четыре stale-причины, no-write гард (счётчики `schedules`/`groups`/`group_user`/`users` и `max(updated_at)` неизменны после вызовов), роль OFF → `reason=disabled`.
