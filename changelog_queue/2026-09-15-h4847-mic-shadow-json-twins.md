- **MIC shadow-классификатор перестал падать на каждом входящем (H4847, Opus 5 `claude-opus-5`, 15-09-2026).** Прод-лог писал `mic_shadow_classify_loader_failed {"error":"Class \"Symfony\\Component\\Yaml\\Yaml\" not found"}` несколько раз в час: [`MicShadowClassifier`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Support/MicShadowClassifier.php) звал вендоренный YAML-лоадер, а symfony/yaml в проде нет (dev-only dep через laravel/sail) — таблица `mic_shadow_classifications` не получала ни одной строки. Теперь правила берутся из прекомпилированных близнецов `rules/v1/*.json` (отклонение 1 в [VENDOR.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tools/message-intent-classifier/VENDOR.md) — тот же источник, что у `support:rules-sync`), порядок правил тот же (priority, затем порядок загрузки). Флаг `MIC_SHADOW_CLASSIFY` OFF теперь значит «лоадер не запускается вовсе» (раньше он грузился и падал даже при выключенном флаге); сбой загрузки запоминается на процесс — один WARNING, а не на каждое сообщение. Зависимость symfony/yaml в прод не добавлена. Тесты: [`MicShadowClassifyTest`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Support/MicShadowClassifyTest.php) +4 (флаг OFF — ноль логов; сборка из копии пакета без единого `.yaml`; пакет без JSON — громкий отказ; паритет порядка правил JSON ↔ YAML-лоадер по всем 7 плоскостям).
