- **Synthetic ДЗ-upload check in `cabinet:probe` (H37xx): closes the blind spot behind three repeated «постоянно ломается подача ДЗ» incidents (silent 64MB wall, PDF-assembly OOM, H3524 duplicate-resubmit) — every existing probe surface was a GET, none touched the real upload path.** New `probeHomeworkUploadSynthetic()` writes/reads/deletes one file through the SAME `HomeworkService::recordSubmission(finalize: false)` the student form uses, on a dedicated sandbox lesson (`CABINET_PROBE_HOMEWORK_COURSE`/`_LESSON_ID`, empty = skipped, non-blocking). Idempotent — the fixture is always reset to empty in `finally` regardless of pass/fail. **Known scope gap, documented not silently claimed:** this is an in-process call inside the artisan process, not real HTTP through nginx/php-fpm — it cannot catch a `client_max_body_size`/`upload_max_filesize`/`post_max_size` drift (the exact class that caused the 04-08-2026 incident); a black-box HTTP probe for that class stays deferred, same as Playwright.
