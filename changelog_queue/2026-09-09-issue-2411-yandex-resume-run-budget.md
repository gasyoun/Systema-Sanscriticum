# #2411: докатка Yandex-частей уважает бюджет прогона — `systema-yandex-resume` больше не красится в failed на штатном «не успели за час» (Claude Opus 5, 09-09-2026)

Soft-alert `guards/failed-units` с fingerprint `6fd69840` открыл около тридцати issue ([#2411](https://github.com/gasyoun/Systema-Sanscriticum/issues/2411) — последний в серии). Замер прода `.92`: юнит умирал ровно в `:30:01` при такте таймера `:10`, то есть по `TimeoutStartSec=1200`, потратив **4 секунды CPU на 20 минут стены** и 287 МиБ из 768 — ни OOM, ни фатала, чистое ожидание сети. PR [#2457](https://github.com/gasyoun/Systema-Sanscriticum/pull/2457).

- **Root cause — арифметика, а не сбой.** Цикл `resumePendingGroups()` ([SplitUploadToYandex](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Listeners/Backup/SplitUploadToYandex.php)) не знал о бюджете юнита и начинал часть, которая заведомо в него не влезала: одна часть стоит до 300 с (`CURLOPT_TIMEOUT` в `AppServiceProvider::boot()`) плюс до 120 с свежепроцессного verify, а весь прогон — 1200 с. После 2–3 частей systemd рвал процесс SIGTERM'ом **посреди PUT**. Значит юнит вставал в `failed` всякий раз, когда докатывать было больше двух частей, — то есть после каждого крупного бэкапа. H3806 ([#2264](https://github.com/gasyoun/Systema-Sanscriticum/pull/2264), 31-08) вылечил вторую половину той же болезни (обречённые verify-сны), но не эту.
- **Фикс**: `split_upload.resume_budget_seconds` (`BACKUP_RESUME_BUDGET_SECONDS`, 900 — строго меньше 1200; `0` = поведение до #2411) в [config/backup.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/config/backup.php); константа `PART_SLOT_SECONDS` (300 + verify) и проверка `hasBudgetForPart()` **перед** каждой частью. Нет запаса на худший случай — прогон завершается штатно, с кодом 0 и громкой строкой «бюджет прогона исчерпан»; остаток добирает следующий часовой прогон. Прогресс сохраняется, юнит зелёный.
- **Глушения нет.** `FAILED_UNITS_ALLOWLIST` не тронут: разбор H3806/H3181 прямо запрещает глушить `failed-units` на бэкапной полосе — это заново открыло бы слепое пятно «off-site был ложно-зелёным». Свежесть по-прежнему меряет `ServerGuardsAuditor::auditBackupFreshness()` по ПОЛНЫМ группам, а сводка при остановке по бюджету честно называет остаток нижней оценкой («не меньше N групп»), а не полным списком. `scripts/server_guards/**` и таймер не менялись — ручной `server_guards_apply.sh` на проде не нужен.
- **Путь свежего бэкапа не тронут**: `handle()` → `upload()` живёт под `cron.service` со своим потолком, менять его поведение задача не требовала.
- **Побочно вылечен красный `main`**: `docs/ENVIRONMENT_VARIABLES.md` разошёлся с `config/` до этой ветки — гейт «Environment inventory» падал на `cb8013ac`, `7c3aa6fc`, `3153ba1e`, `53c68b4a` (с 08-09 20:47 UTC, четыре коммита подряд). Регенерация одной командой включена в PR. Ровно класс инцидента [#2088](https://github.com/gasyoun/Systema-Sanscriticum/pull/2088)/[#2093](https://github.com/gasyoun/Systema-Sanscriticum/pull/2093).
- **Тесты**: [SplitUploadToYandexTest](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Backup/SplitUploadToYandexTest.php) 14/14 (было 11). Три новых: часть не начинается без запаса и честно логируется как отложенная; бюджет режет ровно хвост, а успевшее доезжает (часы двигает сам PUT через диск-обёртку, без реального сна — H2541); `0` = старое неограниченное поведение. Pint clean.
