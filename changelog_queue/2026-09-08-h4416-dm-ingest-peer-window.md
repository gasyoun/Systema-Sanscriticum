# H4416: DM-ингест поддержки починен — окно пиров больше не глотает личные сообщения (OxAlpha z-ai/glm-5.3-flash, 08-09-2026)

Живой кейс: вопрос Елены Безрядиной (стоимость 3-го блока, группа Толчельникова в среду) в личке @rusamskrtam не породил ни черновика, ни хинта — суфлёр-контур его физически не видел. Root cause доказан пробой на проде `.92` 08-09-2026: `getDialogIds()` аккаунта-персоны возвращает **3199 диалогов в порядке, далёком от свежести** (топ-30 — старые июльские DM-чаты, свежий DM не попадал в окно никогда), а legacy-код брал `array_slice(ids, 0, dialog_limit=20)`. Личный DM-ингест стоял **с 31-08 по 08-09 при статусе «ok» каждую минуту** (`messages_seen=0`), группы доплывали только через allowlist `tech_group_peers`. Раньше DM добирали исходящие webinar-бласты 27-08/29-08, которые временно подняли DM-пиры в окно — их затухание и вскрыло дыру.

- **Союз пиров вместо одного окна** ([TelegramSupportSyncService::pollPeers](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/TelegramSupport/TelegramSupportSyncService.php)): активные известные чаты из БД (`telegram_support_messages`, положительные chat_id с любым сообщением за `TELEGRAM_SUPPORT_KNOWN_CHAT_WINDOW_DAYS`=14 дней, потолок `_POLL_LIMIT`=120, свежайшие первыми) ∪ allowlist `tech_group_peers` ∪ legacy MP-топ-20 (для бренд-новых чатов, которых в БД ещё нет). Дедуп по id; cursor по peer делает повторный опрос дешёвым. `peers_polled` пишется в лог каждого захода — DM-аутедж больше не невидимка на фоне status=ok.
- **Суточный catch-up**: `telegram-support:sync --catch-up-days=N` (N из `TELEGRAM_SUPPORT_CATCHUP_DAYS`=60) обметает ВСЕ известные чаты с активностью за окно — страховка для чата, ожило ли после долгой паузы и выпавшего из горячего окна; в расписании 05:37 (после суточного харвеста 05:15, без конкуренции за замок сессии). Тот же флаг — инструмент разового бэкфилла пропущенных DM (первый прогон после деплоя — 08-09, кейс Елены Безрядиной; результат — в Evidence handoff'а).
- **«Выход» не строился — он уже был** (reuse, не новое): хинт с готовым текстом Насте+MG, кнопка «Отправить как есть» с клеймом `TelegramSendGuard` и draft-only-отказом на деньгах/доступе, D-черновики с ценами из БД (`SupportAnswerFactResolver` public_pricing) — всё это H3765/H3999/H3393/H247. Связка не работала только потому, что вход стоял.
- Тесты: [TelegramSupportPeerWindowTest](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/Support/TelegramSupportPeerWindowTest.php) 5/5 (регрессия: известный активный DM-чат опрашивается даже вне MP-топа; чат вне окна достаёт catch-up; allowlist-пир опрашивается ровно один раз; окно 0 = наследное поведение; `peers_polled` в логе). Верификатор: `php artisan test tests/Feature/TelegramSupportAnalyticsTest.php tests/Feature/Support tests/Feature/MadelineSyncGuardsTest.php` — 465 passed, 2 documented skip (pcntl на Windows).
