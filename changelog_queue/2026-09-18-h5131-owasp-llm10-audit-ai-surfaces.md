# H5131: ночной аудит AI-поверхностей по OWASP LLM Top-10 (OxAlpha `opencode/z-ai/glm-5.3-flash`, 18-09-2026)

**Документированный аудит (docs-only, код не менялся).** AI-поверхности Systema (CuratorAi TG/VK/web-чат, StudentAgent, helpdesk-черновики, Reminder/Promise-детекторы, контент-генераторы, эмбеддинги) проверены по OWASP Top-10 for LLM Applications 2025 на статике, HEAD `37b88c00`, без live-нагрузок на прод. Вердикт: **Medium Risk, критики нет**; каждая несущая строка перепроверена по исходникам. Топ-находка **F1 (High, LLM10 Unbounded Consumption):** на `POST /api/telegram/webhook` и `/api/vk-webhook` нет throttle (соседние вебхуки все прикрыты), а per-user лимита на платные ответы куратора не существует — легитимный студент скриптом способен генерировать неограниченные биллинговые вызовы OpenRouter (`support_ai_daily_cap=100` закрывает только D/E/F-черновики, не куратора); фикс дешёвый — throttle на оба вебхука + суточный счётчик AI-ответов на пользователя. **F3 (Medium, LLM02):** `ReminderRequestDetector` сканирует ВСЕ `role=user` `ChatMessage` без фильтра по `source` — текст из email-канала уходит в OpenRouter вообще без privacy-флага, тогда как TG-support текст прикрыт `support_ai_include_telegram` (рулинг МГ 02-07-2026). Позитив подтверждён: чистое разделение ролей (текст пользователя только в `role:user`, вопрос — лишь ключ BM25-ретривала), whitelist-санитайзер вывода `SupportText::safeHtml`, жёсткий allow-list из 3 тулов + CONFIRM-гейт в StudentAgent, fail-closed вебхуки, запрет облачного фолбэка при локальной генерации, draft-only генераторы с человеком-публикатором. Ремедиация: Phase 1 (~полдня) — F1+F3+throttle `/dvaram/agent`; Phase 2 — фенсинг пользовательских реплик и jailbreak-регресс, редактирование тел ошибок провайдера в логах.
