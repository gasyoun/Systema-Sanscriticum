# Прод-проба перестала умирать на чтении off-site: backup-fresh читает один shallow-листинг вместо обхода 476 файлов (OxAlpha `glm-5.3-flash`, 16-09-2026)

Резидуал GTD 0bn. Класс: `cabinet:probe` убит watchdog-обёрткой на 120 с (`storage/logs/watchdog.log`: 14-09 08:17/08:32/12:17/12:32/17:02/20:02 UTC, 15-09 repro, 16-09 10:17/10:32/13:17/13:32/14:47 UTC). Каждый убитый такт = нет результата пробы и нет BetterStack-heartbeat, то есть слепое окно мониторинга.

- **Замер прода (tinker, реальные числа, не догадка).** `BackupDestination::isReachable()` = 4.6 с; `backups()` = **112.8 с** (spatie обходит 476 объектов); поштучные `sizeInBytes()` = **31.6 с**; итого cache-miss backup-fresh = **150.6 с** — и весь этот путь выполнялся внутри `CabinetProbeHealth`, пока сторож `*/15` считал свои 120 с. При этом ОДИН `adapter->listContents('Laravel', false)` отдаёт те же 479 файлов с path/size/lastModified за **2.8 с**.
- **Причина — наследование чужого потолка.** sabre-клиент диска `yandex_disk` носит `CURLOPT_TIMEOUT=300` (H3410, для PUT-канала выгрузки частей), и потолок применялся к ЛЮБОМУ запросу диска, включая propFind-листинг пробы. Подозрение из строки инцидента (медленный `git fetch` deploy-behind) снято чтением кода: `DeployDriftInspector` (H3803) принципиально локальный, сети не трогает.
- **Фикс, две ноги.** (1) `config/filesystems.php` + `AppServiceProvider`: читающий близнец `yandex_disk_readonly_probe` (driver `webdav_probe`) с `CURLOPT_TIMEOUT=45, CONNECTTIMEOUT=10, LOW_SPEED_TIME=30` — PUT-каналу боевого диска 300 с оставлены как есть. (2) `ShellSystemInspector::readBackupDestinations()`: аудит читает shallow-листинг адаптера (`FileAttributes` с метаданными) вместо spatie-обхода; WebDAV-диски аудита резолвятся в `*_readonly_probe` близнеца, строка отчёта остаётся под боевым именем. Timestamp берётся из ИМЕНИ файла (как `Backup::date()`) — `SplitGroupMath::timestampFromBasename()`, потому что mtime на WebDAV = время загрузки и свежесть поехала бы. Плюс бюджет на шаг `server_guards.backup_probe_budget_seconds` (45 с): не уложились — уходим без строк и повторяем следующим тактом, вместо ложной находки «нет архива».
- **Верификация на проде.** Cache-miss пробы: **155 396 / 153 111 ms → 7 248 / 7 323 ms** (`cabinet_probe_runs`), чтение листинга в изоляции 150.6 с → **3.5 с**. Крон-такт сторожа (www-data через `systema-watchdog-run.sh`, принудительный cache-miss): **7 248 ms, WATCHDOG TIMEOUT не сработал**; `watchdog.log` после деплоя чист. Семантика данных не изменилась: обе ноги видят ту же новейшую ПОЛНУЮ группу (2 796 299 761 байт, 2026-09-14 02:02), guards «Предохранители ОС на месте», heartbeat уходит.
- **Тесты.** `SplitGroupMathTest` +5 кейсов парсинга имени (single zip, split part, полный путь, мусор, имя без timestamp); `BackupScheduleTest` — probe-диск существует, driver `webdav_probe`, те же baseUri/prefix/username, не боевой `webdav`.
