## S0.4 — restricted push key

**Real infra blocker found and worked around (not anticipated by the plan):** `.92`
cannot reach `.91`'s **public** IP (`193.232.229.91`) on port 22/80/443 at all —
`nc`/`ssh` time out, even though ICMP ping succeeds (0.2 ms RTT). `.91`'s own
`iptables`/`nftables` INPUT chain has no blocking rule and its `eth0` carries only a
**private** address (`192.168.200.91/24`); `193.232.229.91` is a provider-side
floating/NAT address that appears to allow only specific management source IPs (this
workstation) — not VPS-to-VPS traffic. Confirmed `.92` has the matching private address
`192.168.200.92/24` on the same `/24`.

**DEFAULT applied:** used the private-network path (`192.168.200.91`) for the
`.92`→`.91` restic/SFTP leg instead of the public IP. This is strictly better than the
plan assumed (no public-internet exposure for this leg) and required no new
credential or firewall change — just addressing.

Built: unprivileged `restic-push` user on `.91`, owning `/srv/restic/systema`
(`/srv/restic` itself root:root 755, required by OpenSSH `ChrootDirectory`). Used the
**chroot + `ForceCommand internal-sftp`** approach from the S0.4 DEFAULT (not bare
`command=` in `authorized_keys`) because it composes more predictably with restic's
sftp backend path handling. `ed25519` keypair on `.92`
(`/root/.ssh/id_restic_push{,.pub}`).

**Verified (criterion 0.3):**
- Interactive: `ssh -i id_restic_push restic-push@192.168.200.91` → `This service
  allows sftp connections only.` (refused, exit 1).
- `restic -r sftp:restic-push@192.168.200.91:/systema init` (via the restricted key,
  `-o sftp.command=...`) → succeeded, repo landed at `/srv/restic/systema` on disk.

## S0.6 — backup wrapper

[`ops/backup/systema-restic-run.sh`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/ops/backup/systema-restic-run.sh) — dump → `restic backup
--tag systema` (DB dump + `storage/app` + `.env` + `/etc/nginx`, excluding the
incumbent spatie archives) → `restic backup --tag samudra` (`/opt/samudra/db` +
`/opt/samudra/corpus`) → one summary line per lane to `/var/log/restic-backup.log`.

**Bug found and fixed during S0.8 seeding:** the first version built the `-o
sftp.command=...` value as a plain string and word-split it when expanded unquoted
(`restic-push@192.168.200.91` was parsed as a positional restic subcommand). Fixed by
switching to a bash array (`RESTIC_ARGS=(...)`) and `restic "${RESTIC_ARGS[@]}" ...`.
Same fix applied to `restic-forget.service`, which was moved from an inline
`ExecStart=` (systemd also word-splits) to its own script,
[`ops/backup/systema-restic-forget.sh`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/ops/backup/systema-restic-forget.sh).

**DEFAULT applied (`.env`):** included per the plan's default — no payment secrets per
the prior audit, restic encrypts at rest, and a restore without it would be
incomplete.
