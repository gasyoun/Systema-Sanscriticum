## What shipped (repo-side half; owner-side residual below)

1. **`ops/backup/systema-restic-run.sh` extended** with the S3 leg, push order
   preserved (SFTP first, then S3 — a slow or failing S3 leg never costs the fast
   local copy). Contract:
   - reads `/root/.restic-s3.env` when present (`RESTIC_S3_BUCKET`,
     `RESTIC_AWS_ACCESS_KEY_ID`, `RESTIC_AWS_SECRET_ACCESS_KEY`; optional
     `S3_ADMIN_*` for verification only);
   - pushes both lanes (`systema`, `samudra`) to
     `s3:https://storage.yandexcloud.net/<bucket>/systema` with the same paths,
     tags and excludes as the SFTP legs;
   - per-lane per-destination status lines in `/var/log/restic-backup.log`;
   - **criterion 1.4 shape**: the summary line carries literal `sftp=` and `s3=`
     tokens; once provisioned, a failing S3 leg fails the run
     (`run_complete ... sftp=OK s3=FAIL`, overall_rc=1);
   - while unprovisioned it logs `lane=s3 dest=s3 status=SKIP reason=no-/root/.restic-s3.env`
     and does **not** fail the run.
2. **`ops/backup/systema-restic-s3-verify.sh`** — criteria evidence harness +
   one-shot bootstrap. Exit 2 = key can delete (handoff FAIL). Produces quoted
   `AccessDenied` text for criterion 1.1, object-lock retention output for 1.2
   (admin-delete refusal check 1.2b when admin creds supplied), and with `--init`
   initializes the repo, performs the first push, and prints `restic snapshots`
   from both repos for criterion 1.3.

## Marked defaults applied (logged per the autonomy contract)

| Situation | Default applied |
|---|---|
| S3 destination not yet provisioned (no bucket/key) | Plan stop condition "credential does not exist yet": record, skip the leg, continue — SKIP does not fail the run. Once the env file exists, failure semantics switch on fully |
| Bucket created but Object Lock left off | Wrapper/verify proceed; verify script prints NOT IMMUTABLE verdict — the destination must never be described as immutable until lock is on |
