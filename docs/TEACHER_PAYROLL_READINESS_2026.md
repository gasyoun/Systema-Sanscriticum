# Готовность выплат преподавателям — 1 октября 2026

## Обязательная связка Точка → ЛМС

Банк доказывает, что деньги действительно ушли; `teacher_payouts` доказывает,
из каких строк состоял утверждённый расчёт. Один источник не подменяет другой.

1. Один раз зарегистрировать подтверждённый ИНН или счёт преподавателя:
   `php artisan money:register-teacher-payout-identity TEACHER_ID inn VALUE`.
   Сначала dry-run, затем `--apply`. Хранятся только HMAC и последние 4 цифры.
2. Перед зарплатой получить все RUB-счета Точки токеном только с
   `ReadAccounts`, `ReadStatements` (и отдельно `ReadBalances`):
   `php artisan money:sync-tochka-teacher-transfers --from=YYYY-MM-DD
   --to=YYYY-MM-DD`. Сначала dry-run, после проверки — `--apply` при включённом
   `MONEY_TOCHKA_TEACHER_TRANSFERS=true`.
3. Фактической выплатой считается только `Booked Debit`. Pending,
   authorization, rejected, reversed, credit и повреждённые строки не считаются.
4. Импорт создаёт только неизменяемое доказательство и точное сопоставление по
   подтверждённому ИНН/счёту. Он никогда не создаёт `payments` или
   `teacher_payouts`; сопоставление по фамилии запрещено.
5. Более новая банковская операция всегда заменяет старую дату ЛМС в поле
   «последняя фактическая выплата». Пока человек не связал её с выплатой и
   замороженной построчной расшифровкой, строка остаётся `held` с
   `bank_transfer_unallocated`.
6. Связать проверенную существующую выплату:
   `php artisan money:link-teacher-payout-evidence PROVIDER_PAYMENT_ID
   TEACHER_PAYOUT_ID`; после dry-run применять только если преподаватель, сумма
   и дата совпали точно.
7. Исторический пакет обязан хранить payment ID, курс, группу, блок, ставку,
   тогдашнюю топологию блоков, авансы, зачёты и fingerprints источников.
   Пересчитывать прошлую выплату по сегодняшним изменяемым блокам запрещено.
8. Непосредственно перед переводом пересоздать приватный экспорт и сравнить
   fingerprint. После перевода снова синхронизировать выписку и связать
   появившийся `Booked`.

`mcp-server-tochka-bank` не является производственным мостом: вместе с чтением
он предоставляет создание платежей. Допустима лишь локальная диагностика без
write-разрешений. ЛМС использует прямой Laravel-клиент Open Banking.

Повторяемый операционный процесс: [Teacher payroll operator playbook](TEACHER_PAYROLL_OPERATOR_PLAYBOOK.md).

Страница `/admin/teacher-payroll-readiness` и команда `payroll:readiness` используют один сервис и один отпечаток. Они только читают данные: не создают `payments`, `teacher_payouts` или строки выплат. Перевод выполняет человек, подтверждение остаётся в существующем процессе кабинета.

## Приватные доказательства

Файл `storage/app/private/payroll/evidence-manifest.json` не коммитится. Минимальная форма:

```json
{
  "generated_at": "2026-10-01T08:30:00+03:00",
  "sources": {
    "payout_sheets": {"as_of": "2026-10-01", "sha256": "..."},
    "bank_credit": {"as_of": "2026-10-01", "sha256": "..."},
    "paypal_xoom": {"as_of": "2026-10-01", "sha256": "..."}
  }
}
```

Хэши относятся к свежим августовско-сентябрьским ведомостям и подтверждениям, которые хранятся вне публичного репозитория. Отсутствующий, просроченный или повреждённый источник имеет статус `incomplete`, а не нулевую сумму, и удерживает только положительные обязательства.

## Операционный порядок

1. Импортировать свежую выписку зачислений и подготовить приватный манифест; обновить ручной снимок PayPal.
2. Включить после приёмки `MONEY_BANK_STATEMENT_CREDITS=true`, `TEACHER_DIRECT_RECEIPT_REVENUE_PARITY=true` и `TEACHER_PAYROLL_READINESS=true`, затем `php artisan config:cache`.
3. Сформировать приватный пакет: `php artisan payroll:readiness --on=2026-10-01T08:30:00+03:00 --export=auto`.
4. Проверить 23 диспозиции. Строка `payable` обязана иметь свежие источники и ноль исключений; `held` не переводится.
5. Непосредственно перед каждым переводом повторить команду с `--expect-fingerprint=<SHA-256>`. Несовпадение означает обязательную регенерацию и новое утверждение.
6. При нехватке средств порядок детерминирован: `due_on`, затем `teacher_id`; непокрытый остаток показывается явно.

Прямой платёж при включённом флаге входит в выручку курса, получает обычные 92% × ставку преподавателя, после чего уже удержанная сумма вычитается один раз. Ставки и 92%-ная база не переписываются.
