# Incident — n8n (.91): CP866-mojibake в шаблонах Telegram-постов трёх воркфлоу

_Created: 26-08-2026 · Last updated: 26-08-2026_

## Резюме

25-08-2026 между 13:40 и 14:33 МСК при правке воркфлоу «ZOOM 1.4 (Final)» через Windows-консоль/вставку текст прошёл преобразование **UTF-8 → прочитано как CP866 → пересохранено как UTF-8**. В результате в JSON воркфлоу буквально сохранились символы-кракозябры. Эмодзи контрольной галочки превратился в видимый пользователям мусор: ☑️ (`E2 98 91 EF B8 8F`) стал строкой `тШСя╕П`. Воркфлоу при этом продолжал исполняться успешно — повреждения были внутренне согласованными (в т.ч. ключи роутинга Switch грызлись одинаково на обеих сторонах).

Обнаружено MG по опубликованному посту «`тШСя╕П Кочергина 1, 2, 3 (проверка) (#7, 25.08.26)`». Диагноз поставлен механическим разбором: все шесть символов точно ложатся на байты `☑️`, видимые как CP866; случайность исключена.

## Починка (26-08-2026)

1. **Снапшот:** контейнер остановлен; `/root/n8n-mojibake-fix-2608/` — копии `database.sqlite` (+wal/shm), консолидированный `apply.sqlite`, экспорт трёх воркфлоу в JSON, dry-run отчёт `report_dryrun.txt`.
2. **Обратное преобразование:** для каждой строки с символами псевдографики U+2500–U+25FF — целостное `encode('cp866').decode('utf-8')`; для смешанных строк — минимально-оконная сегментная реставрация с проверкой валидности UTF-8. Итого 57 строк починено (zoom 54 + lovim 3).
3. **Контроль:** bad_refs NONE (все `$('…')` указывают на существующие ноды), граф соединений провалидирован постранично, `PRAGMA integrity_check ok`, ноль остаточной псевдографики в живых строках, уникальность имён нод.
4. **Заслон:** в оба активных воркфлоу добавлены Code-ноды «Encoding Guard (…)» перед каждой из пяти отправок Telegram — глубокая нормализация исходящих строк тем же обратным правилом плюс жёсткий throw при остаточной псевдографике. Если кодировка слетит снова — исполнение упадёт громко, а не уедет в группы молча.
5. **Старт:** контейнер запущен, healthz 200, обе версии активированы n8n собственным актом (publish_history row 68, версия совпадает с живой исправленной).
