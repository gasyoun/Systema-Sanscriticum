## 1. Что такое сервис «Должники»

Это рабочий список студентов, у которых начался блок курса, но он не оплачен. Сервис нужен для звонков, напоминаний, оформления договоренностей по оплате и контроля рассрочек.

Каждая строка — пара **(студент, курс)**. У одного студента может быть несколько строк, если он должен по разным курсам. Тип долга бывает двух видов:

- **Не продлил** — студент когда-то платил, но не оплатил текущий блок. «Теплый» долг, обычно достаточно напоминания.
- **Без оплат** — студент записан на курс, но никогда не платил. Либо лид, либо забытая запись.

### Кто НЕ попадает в список

Из выборки автоматически исключаются студенты, у которых в карточке «Обучается на курсах» по этому курсу стоит один из *терминальных* статусов: **Покинул**, **Исключен**, **Выпускник** или **Льготник**. У первых трех обучение завершено, у льготника оно бесплатное по договоренности. Долг им начислять некорректно, и в списке должников их быть не должно.

Для всех терминальных статусов в форме статуса есть поле **«Блок выхода»** — номер блока этого курса, на/после которого студент вышел. Это полезная справка для отчетности (например, «выпустился после 8-го блока»). Долги по блокам после «блока выхода» система не начисляет.

## 2. Дашборд: виджеты «Общий итог» и «Скоро срок»

### На странице «Должники»

Над таблицей — четыре карточки сводки:

- **Должников** — сколько пар (студент × курс) в текущей выборке.
- **Общий долг** — сумма всех долгов. Пометка «(часть «≈»)» означает, что для каких-то пар часть блоков посчитана по средней цене (точного тарифа на блок не было).
- **Просроченных обещаний** — активные promises, у которых дата уже прошла. Первоочередные кандидаты на «отозвать или продлить».
- **Неблагонадежных** — сколько студентов помечены флагом 🚩.

### На главном дашборде админки

Виджет **«Скоро срок оплаты (7 дней)»** показывает обещания, у которых `promised_at` попадает в ближайшие 7 дней (включая уже просроченные). Удобно открыть в начале рабочей недели и сразу видеть, у кого подходит срок, не заходя в страницу должников.

## 3. Колонки таблицы

| Колонка | Что в ней |
|---|---|
| **Студент** | Имя, по клику — быстрая карточка. В подписи мелким: красная иконка 🚩 (если флаг неблагонадежности), бейджи каналов связи (`TG`, `VK`, `Max`, `📞`, `IG`, `FB`), внутренний id `#42` и «был N дней назад». При наведении на 🚩 показывается причина флага. |
| **Блок** | Номер текущего блока курса (`№7`). В подписи — даты блока и просрочка: «просрочено 5 дн» или «просрочено 3 нед» (недели после 14 дней). Если блок еще не начался, просрочки нет. |
| **Статус обучения** | Бейдж с pivot-статусом из карточки «Обучается на курсах»: Записался, Вернулся, Рассрочка, Приостановка. Под бейджем мелким — «после блока №5», если задан «блок выхода». Терминальные статусы (см. раздел 1) сюда не попадают по построению. Колонка скрываема тогглом. |
| **Долг** | Главная сумма в рублях. Оранжевый до 10 000 ₽, красный от 10 000 ₽. Подпись: тип долга («Не продлил» / «Без оплат») и какие блоки не оплачены («№5–7»). Знак «≈» — часть блоков посчитана по средней цене (точного тарифа нет). |
| **Обещание** | Активная договоренность по этому курсу: «до 25.05.2026» или «просрочено 18.05.2026». В тултипе — сумма обещания и комментарий. |
| **Последняя оплата** | Скрыта по умолчанию (включается тогглом колонок). Дата, сумма и диапазон блоков последнего реального платежа за курс. |
| **Дисциплина** | Скрыта по умолчанию (включается тогглом колонок). Бейдж-тир (Good/Watch/Poor) + composite-скор 0–100 — см. [раздел 13a](#13a-скор-платежной-дисциплины). Advisory-only: только контекст, ни на что не влияет автоматически. |

> **Группировка по курсу.** Таблица по умолчанию свернута в группы по курсам. Если у студента долги на разных курсах, они попадают в разные группы и не смешиваются. Заголовок группы можно свернуть/развернуть кликом.

## 4. Фильтры и группировка

Над таблицей справа — кнопка фильтров. Доступно:

- **Курс** — мультивыбор. Чтобы работать по одному курсу за раз.
- **Тип долга** — «не продлившие» / «без оплат». Разные сегменты — разные стратегии общения.
- **Каналы связи** — «Есть Telegram», «Есть VK», «Есть Max», «Есть телефон», «Есть email», «Есть Instagram», «Есть Facebook». Чтобы отсечь тех, до кого по этому каналу не достучаться.
- **Статус обучения** — мультивыбор активных статусов (Записался / Рассрочка / Приостановка / Вернулся). Полезно, например, сфокусироваться на «Рассрочке» при сверке графиков.
- **Неблагонадежные** — «Все» / «Только 🚩» / «Скрыть 🚩». Это и есть фильтр «злостных» / рецидивистов (отдельной подписи «злостный неплательщик» в UI нет).
- **Обещание оплатить** — «Все» / «С обещанием» / «Без обещания». Имеет смысл сначала закрыть тех, у кого обещаний еще нет.

По умолчанию строки отсортированы по имени студента. Пагинация — 25/50/100 на странице.

## 5. Меню действий по строке

В правом столбце каждой строки — иконка-меню (три точки). Внутри:

1. **Подтвердить оплату** — видно, когда есть активное обещание. Создает реальный Payment и закрывает обещание (раздел 6).
2. **Напомнить в TG/VK** — видно, когда у студента привязан хотя бы один мессенджер. Индивидуальное сообщение (раздел 7).
3. **Договориться** — создать / обновить одиночное обещание. Можно сразу открыть доступ. *Скрыто для 🚩.*
4. **Рассрочка** — создать план из нескольких обещаний. Можно сразу открывать доступ поблочно. *Скрыто для 🚩.*
5. **Исключить из TG-чата** — hard ban в учебных Telegram-чатах **этого курса** через `@zapisi_ORSbot` (раздел 11). Видно, если у студента есть `telegram_id` и настроен токен zapisi-бота. LMS-доступ и статус курса **не** меняются.
6. **🚩 Отметить как неблагонадежного** — поднять флаг с обязательной причиной (раздел 11). Опциональный тумблер «Также исключить из учебных TG-чатов курса».
7. **Снять флаг неблагонадежности** — видна только когда флаг уже стоит. **Не** разбанивает в Telegram.
8. **Карточка студента** — открывает полную карточку в новой вкладке.

## 6. Подтвердить оплату

Когда деньги пришли, в меню действий → «Подтвердить оплату». В модалке:

- **Сумма** — подставляется из обещания или из расчетного долга.
- **Блок с № / по №** — диапазон неоплаченных блоков по умолчанию.
- **Идентификатор транзакции** — по умолчанию `promise_#<id>`.
- Тогл **«Не уведомлять студента в TG»** (silent) — для фиксации факта прошлой оплаты задним числом, без шумного «оплата получена» прямо сейчас.

После «Подтвердить»: создается Payment в статусе `paid`, обещание становится «Выполнено», студент попадает в группу курса, начисляется прана, идет синк в Google Sheets.

> ⚠️ **silent ≠ conditional access.** silent фиксирует ОПЛАТУ задним числом (фин-отчеты считают ее настоящей), а conditional access (раздел 9) дает ДОСТУП без оплаты (в фин-отчетах не появляется). Не путайте.

## 7. Напоминания в TG / VK

### Индивидуальное

В меню действий → «Напомнить в TG/VK». Поля:

- Текст с предзаполненным шаблоном. Плейсхолдеры: `{name}`, `{course}`, `{block}`.
- Тогглы «Telegram» и «VK». По умолчанию включены те каналы, что у студента привязаны.

### Массовое

Слева у каждой строки чекбокс. Отметили несколько → внизу появляется кнопка «Напомнить в TG/VK». Те же плейсхолдеры. Студенты без TG и без VK попадут в счетчик «без канала».

> 💡 **Перед массовой рассылкой** отфильтруйте по типу долга и/или курсу. Одно сообщение на разные сегменты редко дает хорошую конверсию.

## 8. Договоренности и рассрочка

### Одиночное обещание — «Договориться»

Меню действий → «Договориться». В форме:

- **Дата обещанной оплаты** — по умолчанию +7 дней.
- **Сумма** — можно оставить пустой (= «оплатит весь текущий долг»).
- **Комментарий** — например «получит зарплату 25-го».
- Тогл **«Открыть доступ под обещание»** — см. раздел 9.

Обещание сохраняется в статусе «Активно». Студенту автоматических сообщений не уходит (если не включен тогл «Открыть доступ» — тогда уходит уведомление об открытии).

### Рассрочка

Меню действий → «Рассрочка». График платежей:

- Минимум 2 строки, по умолчанию 3. Первая дата = сегодня + 7, далее с шагом +1 месяц.
- Если сумма долга посчитана — суммы автоподставятся поровну, остаток в последний платеж.
- **Факт. дата** — DatePicker для случая, когда деньги по этой строке уже фактически поступили (например, при импорте старого графика задним числом). Пусто = не оплачено. Поле *не создает* Payment — это просто отметка на обещании.
- **Откр. с блока № / по №** — заполняйте, если этот платеж сразу открывает диапазон блоков (см. раздел 9).
- «Комментарий ко всему плану» — общий для всех строк.

После сохранения создается N обещаний, объединенных общим id плана. В карточке студента они помечены бейджем `#xxxxxxxx` — короткий id рассрочки.

> ⚠️ **Факт. дата без реального Payment долг не закрывает.** Если вы поставили только «Факт. оплата», но не вызвали «Подтвердить оплату», студент остается в списке должников. Это поле для исторической сверки графиков, а не для закрытия задолженности. Если оплата действительно была — проводите ее через «Подтвердить оплату».

> 💡 **Когда рассрочка, а не одно обещание?** Когда студент явно говорит «по столько-то в месяц», или когда долг большой (3+ блока). Одно обещание — для разовых «оплачу 25-го».

### Отмена

- **Одно обещание** — в карточке студента → вкладка «Обещания оплатить» → «Отменить» на строке. Статус: «Отменено».
- **Вся рассрочка целиком** — там же на любой строке плана → «Отменить всю рассрочку». Активные обещания плана отменяются разом, выполненные не трогаются.

## 9. Conditional access — доступ под обещание

По умолчанию обещание / рассрочка **сами по себе не открывают доступ** — это просто заметка о договоренности. Но если студенту нужно начать учиться до фактической оплаты, можно **открыть доступ в кредит**. Деньги при этом не считаются полученными, должник остается должником в списке, но материалы открываются.

### Два режима

- **Весь курс** — открывается весь курс целиком, включая будущие блоки. Хорошо для одиночного обещания.
- **Конкретные блоки** — указанные номера. Через запятую (`5, 6, 7`) или диапазоном (`1-3, 5`). Хорошо для рассрочки.

### При создании одиночного обещания

1. «Договориться» → заполните дату, сумму, комментарий.
2. Включите тогл «Открыть доступ под обещание».
3. Выберите режим (Весь курс / Конкретные блоки), для второго введите номера.
4. «Сохранить» → студенту в TG: «Доступ к {курс/блокам} открыт по договоренности до DD.MM».

### При создании рассрочки — поблочно по графику

В строках графика заполните «Откр. с блока №» и «по №»:

| Дата | Сумма | с № | по № | Что будет |
|---|---|---|---|---|
| 25.05 | 10 000 ₽ | 5 | 7 | Откроется доступ к блокам 5–7 при сохранении плана |
| 25.06 | 10 000 ₽ | 8 | 10 | Одновременно откроется доступ к блокам 8–10 (аванс) |
| 25.07 | 10 000 ₽ | — | — | Только обещание, без открытия доступа |

> 💡 На практике чаще открывают весь предполагаемый объем рассрочки сразу при создании. Студент начинает учиться, а помесячные обещания служат напоминанием. Если по строке оплата не приходит — отзываете доступ к ее блокам вручную.

### Открыть/отозвать доступ позже

В карточке студента → вкладка «Обещания оплатить»:

- **Открыть доступ** — видно, пока доступ не открыт. *Скрыто для 🚩.*
- **Отозвать доступ** — видно, когда открыт. Удаляет conditional-платежи **и одновременно дублирует уведомление студенту во все каналы**: Telegram, email, VK, Max. Это страховка на случай блокировок (например, недоступен Telegram).

В action отзыва можно вписать комментарий для студента — он попадет во все 4 канала. После выполнения Filament покажет менеджеру отчет по каналам: `telegram: sent`, `email: sent`, `vk: skipped:no_vk_id`, `max: failed:auth`. Отчет также сохраняется на самом обещании в полях `revocation_notified_at` и `revocation_channels_sent` (JSON) — чтобы потом можно было посмотреть, дошло ли уведомление, без перепрогона.

### Что происходит под капотом

- Создается «conditional» Payment со статусом `paid` и флагом `is_conditional=true`, привязанный к обещанию через `linked_promise_id`.
- «Весь курс» — один Payment с тарифом `full`. «Конкретные блоки» — по одному Payment на каждый блок с тарифом `block_X`.
- Студент попадает в группы курса, уроки открыты согласно тарифам.
- Conditional Payments **не считаются оплатой**: должник остается в списке, прана не начисляется, welcome-email не уходит, в Google Sheets такие платежи не синкаются.
- В TG студенту уходит спец-уведомление «доступ открыт по договоренности до DD.MM», а не стандартное «оплата получена».

### Шпаргалка по сценариям

| Ситуация | Что делать |
|---|---|
| Фиксируем договоренность, доступ не нужен | «Договориться» / «Рассрочка», тогл «Открыть доступ» выключен. |
| Оплата пришла — зачесть и открыть доступ | «Подтвердить оплату» (раздел 6). Создается реальный Payment, доступ открывается, начисляется прана. |
| Проверенный студент — открыть до факта оплаты | «Договориться» / «Рассрочка» с включенным тоглом «Открыть доступ». В фин-отчетах нет, в списке должников остается. |
| Студент не оплатил — отозвать доступ | На обещании → «Отозвать доступ». Conditional-платежи удалятся, студент получит уведомление в TG + email + VK + Max. |
| Деньги пришли давно через банк | «Подтвердить оплату» с тоглом silent — фиксируем факт без шума. |

> ⚠️ **Отзыв — только вручную.** Система не отзывает conditional-доступ автоматически при просрочке. Если студент не оплатил к обещанной дате — менеджер сам решает «отозвать или продлить». За день до даты обещания студенту автоматически уходит TG-напоминание «завтра срок оплаты».

### Студент может заплатить сам (self-service)

В личном кабинете студента во вкладке **«Мои долги»** у каждого долга теперь есть кнопка **«Оплатить»**:

- долг «не продлил» ведет на штатный чекаут по тарифу неоплаченного блока (или всего курса);
- по рассрочке/обещанию студент может **внести следующий платеж** по графику, **погасить всё сразу**, либо **частичную сумму** (в диапазоне от ближайшего взноса до остатка) — под «Другая сумма». Если включена прана, студент может списать **свою прану** против суммы (лояльность/промокод не применяются — сумма зафиксирована вами);
- под «Перенести дату» студент может **один раз** сдвинуть дату ближайшего обещания вперед не более чем на 2 недели — вам придет уведомление «Студент перенес дату оплаты»; дальнейшие переносы только через вас;
- многоблочный долг открывает **все оплаченные блоки** сразу (не только первый), и «не продлил»-долг из нескольких блоков можно закрыть одной кнопкой «Оплатить всё».

Когда реальная оплата приходит, покрытые ею обещания **закрываются автоматически** (становятся «Выполнено», в них записывается платеж; частичная оплата закрывает самые ранние взносы, что покрыла), и куратор получает уведомление «Обещание закрыто оплатой» — подтверждать вручную не нужно. Это студенческая половина того же сервиса; ваши инструменты (§6–§9) продолжают работать как раньше.

## 10. Разовый доступ к одному уроку

Иногда нужно открыть студенту **один конкретный урок**, без покупки целого блока. Типичный сценарий: первое занятие 1-го блока было бесплатным в рекламных целях, студент пропустил его и хочет вместо этого попасть, например, на 2-е занятие 3-го блока.

Это **общая** возможность — она не привязана ни к долгу, ни к обещанию, и доступна для *любого* студента, в том числе без активных промисов и без долгов.

**Где:** карточка студента (`/admin/users/{id}/edit`) → вкладка **«Разовые доступы к урокам»**. В правом верхнем углу таблицы — кнопка «Выдать доступ к уроку». В модалке:

- **Курс** — список всех активных курсов. После выбора курса второй селект становится активным.
- **Урок** — все уроки выбранного курса, отсортированы по блокам, подпись «Блок №X · название». Работает поиск по названию.
- **Действует до** (опционально) — дата окончания. Пусто = бессрочно.
- **Причина** — короткий комментарий для аудита.

После «Сохранить» создается запись в `lesson_access_grants`. Студент сразу видит этот урок открытым, остальной блок остается закрытым. Это не пересекается с conditional access и не влияет на «Долг».

**Отзыв:** на строке гранта — кнопка «Отозвать». Доступ закрывается, статус — «отозван», студенту в TG уходит «доступ к уроку закрыт». Если у гранта было «действует до» и дата прошла — статус автоматически «истек» (без явного отзыва).

Для студентов с флагом 🚩 кнопка «Выдать доступ к уроку» скрыта (и сервис кидает ошибку — двойная защита).

## 11. Неблагонадежные студенты (рецидивисты)

Если студент **регулярно** срывает обещания оплаты без предупреждения, его «прана сгорает». Это рабочий термин: студент теряет привилегии — скидку лояльности, возможность взять рассрочку и conditional-доступ под честное слово.

### Что меняется при флаге 🚩

- **Скидка лояльности отключается.** `Tariff::getDiscountPercentForUser()` возвращает 0 независимо от количества купленных курсов.
- **«Договориться» и «Рассрочка» скрыты** в меню должника и в карточке студента.
- **Conditional access не открывается.** Сервис кидает ошибку «Студент в черном списке».
- **Разовый доступ к уроку** — кнопка скрыта, сервис тоже отказывает.
- В строке должника — красная иконка 🚩 рядом с именем, при наведении показывается причина.
- **Флаг сам по себе не кикает из Telegram-чата** — только привилегии LMS. Кик — отдельное действие (ниже).

### Фильтр «злостный / неблагонадёжный»

На странице «Должники» фильтр **«Неблагонадёжные»**: «Только 🚩» / «Скрыть 🚩» / «Все». Отдельной подписи «злостный неплательщик» нет — это и есть 🚩.

### Исключение из учебного Telegram-чата

Рабочий сценарий для злостных неплательщиков, которых нужно убрать из «Чата учеников» (и других учебных групп курса), **не** путая это с отчислением в LMS.

**Предусловия (без любого из них действие не сработает):**

1. Бот **`@zapisi_ORSbot`** добавлен в группу как **админ** с правом **ограничивать / исключать участников** (`can_restrict_members`).
2. У учебной **группы** в админке заполнен **`telegram_chat_id`** (карточка группы / дашборд «Записи (бот)»).
3. У студента привязан Telegram: **`telegram_id`** (бейдж `TG` в строке должника; привязка через студенческий бот кабинета).
4. В Marketing settings задан **токен** zapisi-бота.

| Откуда | Действие |
|---|---|
| «Должники» → меню строки | **«Исключить из TG-чата»** — выбираете группы курса с chat_id → hard ban (`banChatMember`) |
| «Должники» → bulk (чекбоксы) | то же для выделенных строк: все активные группы **курса строки** с chat_id |
| «🚩 Отметить…» | тумблер **«Также исключить из учебных TG-чатов курса»** (по умолчанию **выкл**) |
| «Записи (бот)» | кик **и разбан** по снимку ростера (не по карточке должника) |

**Hard ban:** вернуться **по инвайт-ссылке нельзя**, пока оператор не **разбанит** (дашборд **«Записи (бот)»** → unban). Это намеренно: soft-kick с мгновенным unban позволял вернуться.

**Что НЕ меняется киком:**

- членство в LMS-группе / pivot `group_user` (доступ к курсу по оплате);
- `course_user.status` (статус «Исключен» на курсе — **отдельный** ручной шаг в карточке, раздел 12);
- оплаченные материалы и conditional-доступ (их отзывают своими кнопками).

**Типичный порядок для злостного:**

1. Фильтр **Неблагонадёжные → Только 🚩** (или отметить 🚩 с причиной).
2. **Исключить из TG-чата** (или тумблер при 🚩).
3. При необходимости — статус **Исключен** + «Блок выхода» (тогда строка пропадёт из «Должников»).
4. Если помирились и оплатил — **разбан** в «Записи (бот)», при необходимости снять 🚩.

Код: [`ZapisiChatMemberService`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Telegram/ZapisiChatMemberService.php) (`kick` / `kickFromStudyChats` / `unban`).

### Как ставится флаг

- **Вручную:** меню действий → «🚩 Отметить как неблагонадежного». Причина обязательна. Сохраняется кто пометил и когда. Опционально — сразу hard ban в TG-чатах курса.
- **Автоматически:** команда `php artisan unreliable:recount` (ежедневно в 03:45 после `promises:expire`) считает количество просроченных обещаний студента за последние 12 месяцев. Если 3+ — выставляется флаг с пометкой «авто» и причиной «Автофлаг: N просроченных обещаний за последние 12 месяцев». **Авто-кик из TG при авто-флаге не делается** — только ручной/опциональный шаг менеджера.

### Как снимается флаг

**Только вручную** — меню действий → «Снять флаг неблагонадежности». Автоматически не снимается, даже если поведение улучшилось.

Но при улучшении дисциплины автоматически появляется подсветка: если за 6 месяцев у студента не было ни одной просрочки, выставляется поле `discipline_improved_since = today`. В диалоге «Снять флаг» менеджеру показывается подсказка «Поведение улучшилось с MM.YYYY». Если потом снова появляются просрочки, подсветка сбрасывается.

> ⚠️ **Флаг не блокирует существующие доступы.** Если у студента уже открыт conditional-доступ или активная рассрочка, флаг сам по себе их не отменяет. Хотите отозвать конкретное — действуйте через «Отозвать доступ» или «Отменить всю рассрочку».

## 12. Статусы обучения и «блок выхода»

Статус обучения по курсу — поле в pivot-таблице `course_user.status`, выставляется в карточке студента → вкладка «Обучается на курсах».

### Полный набор статусов

| Статус | Смысл | Попадает в «Должники»? |
|---|---|---|
| Записался | Обычный активный студент. | Да, если есть долг. |
| Вернулся | Возобновил обучение после паузы. | Да. |
| Рассрочка | Платит по графику. | Да, если по графику не вовремя. |
| Приостановка | Временно не учится. | Да. |
| Льготник | Учится бесплатно по договоренности. | **Нет** — исключен. |
| Выпускник | Курс завершен. | **Нет** — исключен. |
| Покинул | Студент вышел из курса. | **Нет** — исключен. |
| Исключен | Отчислен администрацией. | **Нет** — исключен. |

### Поле «Блок выхода»

Для статусов **Покинул / Исключен / Выпускник** в форме статуса появляется обязательно-полезное поле **«Блок выхода»** — номер блока курса, после которого студент вышел/был отчислен/выпустился. Затем номер показывается:

- В карточке студента → «Обучается на курсах», колонка «Блок выхода»: `№5`.
- На странице «Должники» — в подписи к колонке «Статус обучения» мелким: «после блока №5» (только для пар, которые еще не исключены полностью — например, если статус ставится прямо сейчас и менеджер хочет видеть контекст).

## 13. Карточка студента: вкладки

Карточка пользователя (`/admin/users/{id}/edit`) содержит несколько релевантных вкладок:

### «Обучается на курсах»

Все курсы, на которые студент записан, со статусом обучения, «блоком выхода» и примечанием по этому курсу. Здесь же — кнопка «Записать на курс» (AttachAction).

### «Обещания оплатить»

Все обещания студента по всем курсам — активные, выполненные, просроченные, отмененные. Колонки:

- **Курс**, **Дата**, **Факт. оплата**, **Сумма**, **Статус**, **Комментарий**.
- **План** — короткий id рассрочки (`#xxxxxxxx`). Пустое = одиночное обещание.
- **Платеж** — номер реального платежа, которым закрыто обещание (для выполненных).
- **Доступ** — «открыт», если есть активный conditional-доступ.

На каждой активной строке доступны: *Подтвердить оплату, Отменить, Открыть доступ, Отозвать доступ, Отменить всю рассрочку, Редактировать, Удалить*. Создать новое обещание / рассрочку можно из правого верхнего угла таблицы.

### «Разовые доступы к урокам»

Все ранее выданные lesson grants. Колонки: курс, урок (с подписью «Блок №X»), статус (активен / отозван / истек), даты, кто открыл, причина. Header-action «Выдать доступ к уроку» (раздел 10) и row-action «Отозвать».

## 13a. Скор платежной дисциплины

Рядом с вкладкой «Обещания оплатить» на карточке студента — блок «Дисциплина»: composite-скор 0–100 и тир (Good / Watch / Poor), плюс разбивка по 4 сигналам (оплата вовремя, обещания выполнены, доля доступа «в кредит», случаи молчания). Полная формула, веса и обоснование решений — в [`docs/discipline-score-spec.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/discipline-score-spec.md).

Ключевое, что нужно помнить:

- **Lifetime-метрика** — считается с момента зачисления на каждый курс, отдельно от 12-мес. окна авто-флага 🚩 (`unreliable:recount`). Обе цифры сосуществуют, одна не заменяет другую.
- **Advisory-only** — скор нигде не меняет скидки, не блокирует рассрочку/conditional-доступ и не влияет на порог авто-🚩. Это только контекст для менеджера/преподавателя, решение по-прежнему принимает человек.
- **Не персистится** — считается on-demand при каждом открытии карточки/виджета (`App\Services\DisciplineScoreService`), кешируется только в рамках одного запроса.
- **Групповой скор** — на странице «Аналитика студентов» виджет «Дисциплина по группам» показывает простое среднее скора активных участников группы; преподаватель видит только свои группы (read-only).
- Веса и пороги 3-уровневой шкалы — в [`config/discipline.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/config/discipline.php), помечены как требующие калибровки после первого прогона на реальных данных.

## 14. Массовые действия

Чекбоксы слева у каждой строки. Отметили — внизу появляется меню:

- **Напомнить в TG/VK** — массовая рассылка. Плейсхолдеры: `{name}`, `{course}`, `{block}`. Идет в Telegram и/или VK — куда у студента привязан аккаунт. Без TG и VK → в счетчик «без канала».
- **Исключить из TG-чата** — hard ban через `@zapisi_ORSbot` по активным группам **курса каждой строки** (нужны `telegram_id` + `telegram_chat_id` группы). Без них строка уходит в «пропуски». LMS не меняется. Подтверждение обязательно.
- **Экспорт** — выгрузка выбранных строк в CSV/Excel.

## 15. Автоматика и регламент

| Что и когда | Подробности |
|---|---|
| `promises:expire` · ежедневно 03:30 | Просроченные обещания переводятся в статус «Просрочено». До этого они остаются «Активно» и в списке должников отображаются красным «просрочено DD.MM». |
| `unreliable:recount` · ежедневно 03:45 | Пересчет авто-флага 🚩 (3+ expired-обещаний за 12 мес.) и подсветки «поведение улучшилось» (6 мес. без просрочек). **Не** кикает из Telegram — только флаг привилегий. |
| `promises:remind-tomorrow` · ежедневно 09:00 | За день до даты обещания студенту автоматически уходит TG-напоминание «завтра срок оплаты». |
| Conditional-доступ | **Не отзывается автоматически** при просрочке — только менеджер вручную через «Отозвать доступ». |
| Google Sheets синк | Реальные платежи через «Подтвердить оплату» уходят в синк. Conditional-платежи — НЕ уходят (это часть их смысла). |
| Терминальные статусы | Студенты со статусом Покинул / Исключен / Льготник / Выпускник исключаются из выборки должников на уровне SQL. |

## 16. FAQ

### Студент оплатил, но колонка «Долг» всё еще показывает блок

Проверьте Payment в карточке студента: должны быть заполнены `start_block` и `end_block`, статус `paid` или `success`, и `is_conditional=false`. Conditional-платежи (доступ в кредит) намеренно не считаются оплатой долга.

### Сумма долга показывает «≈»

У курса нет точного тарифа на один из блоков — посчитано по средней цене. Решение — завести точный тариф (`type=block`, `block_number=N`) в админке курса.

### Нужно перенести дату обещания

«Договориться» (на этом же студенте/курсе) откроется модалкой с уже заполненной датой — меняйте и сохраняйте. В карточке студента → «Обещания оплатить» — «Редактировать» на строке.

### Студент договорился на рассрочку, но потом захотел оплатить всё разом

На первой строке плана → «Подтвердить оплату» с полной суммой долга, остальные строки отмените через «Отменить всю рассрочку». Conditional-доступы по этим строкам сначала отзовите — иначе они «зависнут» без обещания (хотя и не сломают ничего: их можно потом просто удалить).

### Можно ли удалять обещания?

Технически да, кнопка «Удалить» в RM есть. Но лучше переводить в «Отменено» — тогда останется история и видно, что договоренность была.

### Куда уходит уведомление о платеже?

- Реальная оплата (не conditional, без silent): студенту в Telegram «оплата получена».
- Реальная оплата с silent: ничего студенту, синк в Google Sheets.
- Conditional access (открытие в кредит): студенту «доступ открыт по договоренности до DD.MM», в Google Sheets НЕ уходит.
- Отзыв conditional access: студенту дублированно в TG + email + VK + Max «доступ временно закрыт».
- Разовый доступ к уроку: студенту TG «открыт доступ к уроку …» при выдаче, «доступ к уроку закрыт» при отзыве.

### Можно ли дать доступ только под обещание?

Да — раздел 9. Тогл «Открыть доступ» при создании обещания или поля «Откр. с блока №» в строках рассрочки. Это и есть conditional access.

### Студент пишет «я был в курсе, теперь не могу зайти»

Скорее всего был conditional-доступ, который отозвали (или его никогда не было — студент видел только бесплатные/открытые уроки). Проверьте в карточке студента: вкладка «Обещания оплатить», столбец «Доступ»; в Payments — есть ли paid-платежи с покрывающим тарифом.

### Студент попал в выборку, хотя уже не учится

В карточке студента → вкладка «Обучается на курсах» поставьте статус **Покинул** / **Исключен** / **Выпускник** (плюс «Блок выхода»). Со следующего открытия страницы должников он исчезнет — фильтрация делается на уровне SQL.

### Льготник не должен платить — он попал в список

Поставьте ему по этому курсу статус **Льготник** в «Обучается на курсах». Этот статус полностью исключает пару из выборки должников.

### Не приходит TG-уведомление при отзыве доступа

После «Отозвать доступ» Filament показывает отчет по каналам: `telegram: sent / skipped:no_telegram_id / failed:…`. Тот же отчет хранится на обещании в `revocation_channels_sent`. Если по TG — *skipped*, значит у студента в карточке не привязан `telegram_id`; если *failed* — смотрите детали в логе. Поскольку дублируем сразу во все 4 канала (TG + email + VK + Max), как минимум один обычно доходит.

### Где посмотреть, кто и когда выставил флаг 🚩

В таблице `users`: `unreliable_marked_at` (когда), `unreliable_marked_by` (кто, FK на users.id), `unreliable_auto` (true = авто-флаг, false = ручной), `unreliable_reason` (причина).

### Есть ли фильтр «злостный неплательщик»?

Отдельной подписи нет. Используйте фильтр **«Неблагонадёжные» → Только 🚩**. Флаг 🚩 — рабочий термин для рецидивистов / «злостных» (раздел 11).

### Можно ли исключить должника из Telegram-чата из админки?

Да. «Должники» → меню строки → **«Исключить из TG-чата»** (или bulk / тумблер при 🚩). Работает через `@zapisi_ORSbot` (hard ban). Нужны: бот-админ с правом исключать, `telegram_chat_id` у группы, `telegram_id` у студента. Подробности — раздел 11.

### Студент снова зашёл в чат по инвайту после кика

Значит был soft-kick или разбан. Текущий режим — **hard ban**: без **разбана** в дашборде «Записи (бот)» вернуться по инвайту нельзя. Если всё же зашёл — проверьте, что кик шёл через актуальный код (ban без auto-unban) и что разбан не делали.

### Кик из чата = отчисление с курса?

**Нет.** Кик трогает только Telegram. Чтобы убрать из выборки должников и зафиксировать отчисление, отдельно поставьте статус **Исключен** (или Покинул / Выпускник) + «Блок выхода» (раздел 12).


### Сообщение студента в Telegram автоматически создаёт обещание / отсрочку?

**Да, как черновик — после approve.** При включённом флаге `promise_suggestion_detection_enabled` (default **OFF**) `promises:detect-deferrals` может создать pending **`PaymentPromiseSuggestion`** из ЛС `@rusamskrtam` / веб-чата; куратор в **«Предложения отсрочек»** правит дату/курс и **Approve** → активный `PaymentPromise` (дата в «Мои долги»). Без approve и при флаге OFF — как раньше: только **«Договориться» / «Рассрочка»** (или self-service перенос уже существующей даты). Playbook §4: [PLAYBOOK_PAYMENT_DISCIPLINE_CURATOR_STUDENT_2026.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/PLAYBOOK_PAYMENT_DISCIPLINE_CURATOR_STUDENT_2026.md).

### Кнопка «Исключить из TG-чата» не видна

Обычно: нет `telegram_id` у студента (нет бейджа TG) **или** не задан токен `@zapisi_ORSbot` в Marketing settings. Если кнопка есть, но ошибка — чаще всего у группы пустой `telegram_chat_id` или бот не админ / без `can_restrict_members`.
