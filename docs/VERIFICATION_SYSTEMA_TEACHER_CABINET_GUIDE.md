# Приемка и риски: руководство преподавателя по личному кабинету

_Created: 09-08-2026 · Last updated: 09-08-2026_

Что считается доказательством готовности для
[PLAN_SYSTEMA_TEACHER_CABINET_GUIDE_2026H2.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/PLAN_SYSTEMA_TEACHER_CABINET_GUIDE_2026H2.md),
и что может пойти не так. Шаги сборки — в
[IMPLEMENTATION_SYSTEMA_TEACHER_CABINET_GUIDE_W1.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/IMPLEMENTATION_SYSTEMA_TEACHER_CABINET_GUIDE_W1.md).

Приемка двухступенчатая (R9): сначала машинная самопроверка агентом, и только пройдя ее,
текст попадает к живому преподавателю. Порядок именно такой, потому что тратить внимание
преподавателя на ловлю пропущенного раздела — расточительство: это умеет скрипт.

## 1. Ступень первая — машинная самопроверка

| Что доказываем | Чем доказываем | Порог |
|---|---|---|
| Гид не пропустил раздел, видимый преподавателю | `php artisan teacher:nav-census` плюс `tests/Feature/TeacherGuideCoverageTest.php` | Ни одного элемента переписи без заголовка в гиде |
| Страница в панели открывается преподавателю | Тот же тест: 200 для пользователя с `teacher_id` | Зеленый |
| Страница закрыта посторонним | Тот же тест: 403 для пользователя без роли | Зеленый |
| PDF собирается из нового источника | `php docs/build-teacher-guide.php` | Файл создан, размер отличен от нуля |
| Бейджи обратимости уцелели в PDF | Глазами по собранному PDF | Ни одного пустого прямоугольника вместо знака |
| Каждый шаг сценария имеет бейдж | Сверка по тексту части I | Ни одного шага без одного из трех бейджей |
| Ни одной инструкции по денежным операциям | Чтение раздела про деньги | Только «где посмотреть» (R7) |
| Внутренние имена не утекли в текст | Поиск по гиду имен классов и ролевых гейтов | Ни одного вхождения |
| Стиль репозитория не сломан | Штатный форматтер и статические проверки проекта | Чисто |

Провал любой строки — работа не закончена. Не «в целом нормально»: пропущенный раздел
означает, что преподаватель наткнется именно на него.

## 2. Ступень вторая — живой прогон преподавателем

Проводится после выкладки, на настоящем аккаунте, без подсказок рядом. Преподаватель проходит
три сценария из части I, по одному из каждой группы риска:

1. **Проверить домашнюю работу** — самое частое действие, много состояний.
2. **Перенести занятие** — то, где легче всего задеть студента.
3. **Выдать сертификат** — необратимое действие, главный источник страха.

Что фиксируем: где преподаватель остановился и перечитал; где сделал не то, что имел в виду;
где полез спрашивать человека. Каждая такая точка — дефект гида, а не преподавателя.

**Порог выпуска:** три сценария пройдены до конца без обращения к человеку. Одно обращение —
правим формулировку и переспрашиваем этот сценарий. Два и больше — часть I переписывается, а
не подшлифовывается.

Отдельно спрашиваем ровно один вопрос по исходной жалобе: стало ли меньше опасения сделать не
то. Ответ «нет» при пройденных сценариях означает, что дело не в тексте, а в интерфейсе, и
вес переносится на волну 3.

## 3. Приемка по каждому результату волны 1

| Результат | Готово, когда |
|---|---|
| `docs/TEACHER_CABINET_GUIDE_RU.md` | Четыре части на месте, семь сценариев, покрытие по переписи полное, бейджи у всех шагов |
| PDF | Собирается из `.md`, таблицы и цитаты читаемы, колонтитул на месте |
| Страница в `/admin` | Открывается преподавателем на проде, текст совпадает с файлом в репозитории |
| `teacher:nav-census` | Отдает JSON, сводка по группам совпадает с наблюдаемым в панели |
| Тест покрытия | В общем прогоне, зеленый |
| Предупреждение в CI | Срабатывает на подложенном изменении наблюдаемого файла, при этом не роняет сборку |
| SRS влит | Раздел в гиде, в исходном файле — ссылка, метадок к нему создан |
| Issue по навигации | Открыт, с данными переписи, дубликатов нет |

## 4. Реестр рисков

| Риск | Насколько вероятен | Чем плох | Что делаем |
|---|---|---|---|
| Dompdf не покажет эмодзи в бейджах | Высоко — известное ограничение сборщика с этим шрифтом | Легенда обратимости превратится в прямоугольники, то есть ровно та часть, ради которой все делается | Бейджи задуманы текстовыми (R8, [архитектура §4](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/ARCHITECTURE_SYSTEMA_TEACHER_CABINET_GUIDE.md)) — риск снят замыслом, проверить на шаге 4 |
| Перепись не воспроизведет живую навигацию | Средне | Гид будет полон по бумаге и дыряв на деле | Сверить сводку переписи с панелью глазами один раз, на настоящем аккаунте преподавателя |
| Названия разделов в интерфейсе разойдутся с гидом | Средне, панель меняется часто | Преподаватель не найдет раздел глазами | Предупреждение в CI (шаг 7) плюс сверка по названиям в тесте покрытия |
| Гид вырастет в стену текста и повторит исходную беду | Средне | Жалоба воспроизведется, только в документе | Часть I — не длиннее семи шагов на сценарий; подробности уходят в часть II |
| «Только чтение» по деньгам прочтут как разрешение | Низко | Преподаватель полезет в чужие начисления | Формулировки только наблюдательные, без единого глагола действия |
| Неэкранированный вывод на странице панели | Низко | Внедрение разметки | Источник — закоммиченный файл по константному пути, параметра выбора файла нет (шаг 5) |
| Живой прогон покажет, что дело в интерфейсе | Средне, и это скорее полезный исход | Волна 1 не снимет жалобу до конца | Так и задумано: волна 1 честно ограничена текстом, продуктовая половина живет в issue и волне 3 |
| Разъезд с параллельной сессией по репозиторию | Средне, репозиторий многосессионный | Потеря работы | Отдельный worktree с уникальным именем, проверка перед первой записью |

## 5. Что требует разведки до сборки

| Неизвестное | Как выясняем | Когда |
|---|---|---|
| Дает ли Filament перечислить навигацию от имени произвольного пользователя вне запроса | Прототип команды переписи на десяток минут | Шаг 1, до написания текста |
| Есть ли в проекте готовые `prose`-стили для длинного текста в панели | Поиск по шаблонам панели | Шаг 5 |
| Куда встроить проверку свежести — в имеющийся рабочий процесс или отдельный | Чтение файлов в `.github/workflows/` | Шаг 7 |
| Есть ли фикстура пользователя-преподавателя или нужна фабрика | Чтение тестов проекта | Шаг 1 |

Ни одно из этих неизвестных не блокирует старт: каждое выясняется внутри своего шага и имеет
очевидный запасной путь.

## 6. Что не проверяем в волне 1

Скриншоты, воспроизводимость их сборки и правило про денежные экраны — все это приемка волны
2 (H2502). Упрощение навигации — волна 3, и до решения человека по issue у нее нет критериев
приемки, потому что нет согласованного объема.
