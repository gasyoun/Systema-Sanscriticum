## Known limitations / caveats

- **Scope:** strategy/sequencing only — no implementation detail, no code, no budget figures. Companion docs (asset→pedagogy index, learner progression, architecture SVG) carry the detail.
- **Staleness risk:** high. It is a dated two-year plan pinned to specific quarters and asset IDs; each closed quarter and each renamed asset erodes accuracy. The five `@DECIDE` items are the first thing that will date it.
- Priority ordering (B→A→C→D→E) is asserted per the org Tier-0 rule, not re-derived here; if the org rule changes the roadmap does not auto-follow.

## Intended use / known misuse

- **For:** orienting a session on where the Sanskrit-HUB build is heading, which workstream a task belongs to, and what the critical path is. Reading the `@DECIDE` list before making a strategic call.
- **Misuse:** treating quarter blocks as committed deadlines or contracts (they are directional), executing an ambient roadmap line as a task without a user trigger, or trusting an asset ID here over FEATURES_INDEX (the index is the source of truth for asset state).

## Maintenance & sunset plan

- **Kept alive by:** the project owner and Systema-Sanscriticum sessions — revised when a quarter closes, a KPI gate is hit/missed, or an `@DECIDE` resolves. Substantive edits bump "Last updated" and add a revision-history row here.
