# Архитектура: руководство преподавателя по личному кабинету

_Created: 09-08-2026 · Last updated: 09-08-2026_

Слой «как устроено» для [PLAN_SYSTEMA_TEACHER_CABINET_GUIDE_2026H2.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/PLAN_SYSTEMA_TEACHER_CABINET_GUIDE_2026H2.md).
Здесь зафиксированы границы компонентов, форматы разметки и вердикт «брать готовое или писать»
по каждому куску. Порядок шагов — в
[IMPLEMENTATION_SYSTEMA_TEACHER_CABINET_GUIDE_W1.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/IMPLEMENTATION_SYSTEMA_TEACHER_CABINET_GUIDE_W1.md).

## 1. Один источник, три канала доставки

Источник правды — единственный файл `docs/TEACHER_CABINET_GUIDE_RU.md`. Из него, без ручного
копирования текста, получаются три поверхности:

| Канал | Как получается | Кто читатель |
|---|---|---|
| Репозиторий | сам `.md` | агент, разработчик, ревьюер |
| PDF | [docs/build-teacher-guide.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/build-teacher-guide.php), переключенный с HTML на Markdown | преподаватель, которому удобнее файл на почте |
| Страница в `/admin` | Filament-страница читает тот же `.md` | преподаватель в момент работы |

Единственный источник — это и есть ответ на то, почему гид отстал на два месяца незамеченным:
раньше правку надо было вносить в HTML руками, и никакая проверка на это не смотрела.

**Что уходит.** [docs/teacher-guide.html](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/teacher-guide.html)
(36 КБ) перестает быть источником и удаляется в том же коммите, который вводит `.md` —
иначе в репозитории останутся две версии одного текста, и через месяц никто не скажет, какая
живая. Текст из него переносится целиком, ни один существующий раздел не теряется.

## 2. Разметка: три соглашения, которые обязаны выжить во всех трех каналах

Разметка выбрана под ограничение самого слабого канала — Dompdf.

### 2.1. Маркеры обратимости

У каждого шага сценария стоит один из трех текстовых бейджей:

| Бейдж | Смысл | Что пишем рядом |
|---|---|---|
| `**[Безопасно]**` | результат виден только внутри панели, отменяется тем же экраном | ничего |
| `**[Видно студенту]**` | сразу отражается в кабинете студента | что именно студент увидит |
| `**[Необратимо]**` | своими силами не откатывается | к кому идти за откатом |

**Бейджи текстовые, не эмодзи — и это не вкусовое решение.** Dompdf собирает PDF шрифтом
DejaVu Sans (задан в [build-teacher-guide.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/build-teacher-guide.php)),
у которого нет глифов для эмодзи: цветной кружок ушел бы в PDF пустым прямоугольником или
вопросительным знаком. Геометрические символы (`●`, `■`, `▲`) DejaVu покрывает, но текст
читается однозначно и без легенды, поэтому берем текст. Проверка этого места — обязательный
пункт приемки в
[VERIFICATION_SYSTEMA_TEACHER_CABINET_GUIDE.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/VERIFICATION_SYSTEMA_TEACHER_CABINET_GUIDE.md).

### 2.2. Ролевые блоки

Материал не для всех оформляется цитатой, а не HTML-врезкой:

```
> **Только куратор.** Этот раздел виден, если у вас роль куратора.
```

Причина прямая: HTML в `.md` запрещен и блокируется линтом на запись файла, а цитата — та самая
замена, которую правило и предлагает. Дополнительно цитата корректно доезжает и до PDF, и до
Markdown-рендера в панели.

### 2.3. Уровни заголовков

`##` — раздел оглавления, `###` — сценарий или подраздел. Глубже третьего уровня не идем:
оглавление в PDF и боковая навигация страницы в `/admin` строятся из `##`/`###`, и четвертый
уровень сделает их нечитаемыми.

## 3. Структура документа

Гибрид из решения R3: сценарии впереди, справочник за ними.

```
Часть I. Сценарии (что нужно сделать прямо сейчас)
  Провести занятие: до, во время, после
  Проверить домашнюю работу
  Создать или перенести урок
  Изменить расписание и календарь
  Выдать сертификат
  Добавить карточки в колоду (SRS)          <- вливается из MANUAL_TEACHER_SRS_KOLODA_RU
  Посмотреть свою нагрузку и расчеты        <- только чтение, R7

Часть II. Справочник по разделам панели
  (12 глав старого гида, сокращенные до «что это, где, что можно менять»)

Часть III. Безопасность и границы
  Что нельзя сломать и как откатывать
  Что преподаватель делать не может
  Если сайт недоступен -> ссылка на TEACHER_SITE_DOWN_CHEATSHEET_RU

Часть IV. Частые вопросы и чек-листы
```

Каждый сценарий держит один и тот же скелет: **зачем** (одна строка) → **шаги** с бейджами
обратимости → **что увидит студент** → **если пошло не так**. Скелет одинаковый специально:
преподаватель, прошедший один сценарий, узнает форму остальных и перестает читать их целиком.

## 4. Страница в `/admin`

### 4.1. Компоненты

| Что | Файл | Роль |
|---|---|---|
| Filament-страница | `app/Filament/Pages/TeacherGuide.php` | точка входа, навигация, доступ |
| Blade-шаблон | `resources/views/filament/pages/teacher-guide.blade.php` | рендер Markdown в HTML |
| Источник | `docs/TEACHER_CABINET_GUIDE_RU.md` | текст |

Страница садится в группу навигации **«Обучение»** — там уже 7 ресурсов, и это единственная
группа, целиком относящаяся к работе преподавателя.

### 4.2. Доступ — почему это не нарушает запретную зону

Запретная зона (R14) закрывает **правку существующих** ролевых гейтов и навигации. Новая
страница объявляет свой доступ сама, в собственном методе `canAccess()`, и не трогает ни один
существующий `canViewAny()` из 190 ресурсов. Условие доступа копирует уже действующую в проекте
формулу из [routes/web.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/routes/web.php)
(строка 578) — админ, редактор лекций или пользователь с `teacher_id` — чтобы не изобретать
второе определение того, кто такой преподаватель. Ссылка на `User::isTeacher()`
([app/Models/User.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Models/User.php), строка 309)
предпочтительнее ручной проверки поля.

### 4.3. Рендер и его границы безопасности

Markdown разбирается штатным `Str::markdown()` (CommonMark, входит в Laravel) — отдельная
библиотека не нужна, вердикт «брать готовое». Вывод вставляется в Blade неэкранированно, и это
безопасно ровно при одном условии, которое надо назвать вслух: **рендерится только файл,
закоммиченный в репозиторий, и никогда — ввод пользователя**. Путь читается из `base_path()`
константой в коде, а не из запроса; параметра «какой файл показать» у страницы нет и появиться
не должно. Если когда-нибудь понадобится показывать пользовательский текст, экранирование
придется вернуть.

Файл читается на каждый показ страницы (объем 40–60 КБ — кеш не нужен и только создал бы
расхождение между `.md` и тем, что видно в панели). Если файла нет — страница показывает одну
строку «руководство не найдено», а не падает с ошибкой: на стенде без выкачанных `docs/` это
штатная ситуация.

## 5. Перепись навигации

Задача переписи — механически ответить, не пропустил ли гид раздел, который преподаватель
видит. Реализация — artisan-команда, а не внешний скрипт: только внутри приложения можно
честно спросить у Filament, что видно конкретному пользователю.

```
php artisan teacher:nav-census
```

Команда собирает пользователя с ролью преподавателя (из фикстуры, не из прода — R14),
проходит зарегистрированные ресурсы, страницы и виджеты панели, отбирает те, что проходят
`canViewAny()`/`canAccess()`/`shouldRegisterNavigation()`, и пишет
`docs/generated/teacher_nav_census.json`: группа, заголовок, класс, URL.

Дальше этот JSON работает в двух местах: тест покрытия сверяет его с оглавлением гида, а
человек читает его как ответ на вопрос «что вообще видит преподаватель» — тот самый вопрос,
из которого выросла жалоба на перенасыщенность.

**Побочный результат, который важнее самой переписи.** Первый прогон даст точный список
чужих разделов, видимых преподавателю. Он идет в GitHub-issue как доказательная часть
находки (R1) — сейчас у нас есть только косвенная оценка: гейт с упоминанием преподавателя
стоит у 9 ресурсов из 190, а групп навигации семь, включая «Маркетинг» (14 ресурсов),
«Продажи» (9) и «Финансы».

## 6. Проверка свежести в CI

Предупреждение, не блокировка (R11): если в коммите менялись файлы, влияющие на то, что видит
преподаватель, а `docs/TEACHER_CABINET_GUIDE_RU.md` не тронут — CI пишет предупреждение и
проходит. Наблюдаемые пути:

```
app/Filament/Pages/Teacher*.php
app/Filament/Pages/{MutualSettlements,AttendanceDashboard,CalendarPage,LessonMaterials}.php
app/Filament/Resources/{Lesson,Course,HomeworkSubmission,Schedule,Certificate,StudentGroup}Resource*
app/Filament/Widgets/{DisciplineByGroup,ScheduleCalendar}Widget.php
```

Почему предупреждение, а не блок: изменение может быть чисто внутренним (рефакторинг,
переименование метода) и не требовать правки текста. Блок в таком случае заставлял бы
приписывать в гид пустую строку ради зеленого CI — то есть портил бы документ ради проверки.
Предупреждение оставляет решение человеку и при этом не дает промолчать.

## 7. Вердикты «брать готовое или писать»

| Кусок | Вердикт | Основание |
|---|---|---|
| Разбор Markdown | **брать** — `Str::markdown()` | входит в Laravel, отдельная зависимость не нужна |
| Сборка PDF | **брать** — Dompdf, уже стоит | [build-teacher-guide.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/build-teacher-guide.php) работает, меняется только вход |
| Правила текста | **брать** — §4 [MANUALS_TO_UI_CONTENT_AUDIT_2026.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/MANUALS_TO_UI_CONTENT_AUDIT_2026.md) | правила уже выведены и приняты, переписывать нечего |
| Текст про SRS | **брать** — [MANUAL_TEACHER_SRS_KOLODA_RU.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/MANUAL_TEACHER_SRS_KOLODA_RU.md) | готовый проверенный раздел, вливается почти без правок |
| Действия при недоступности сайта | **брать** — [TEACHER_SITE_DOWN_CHEATSHEET_RU.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/TEACHER_SITE_DOWN_CHEATSHEET_RU.md) | остается отдельным файлом (R6), из гида только ссылка |
| Страница в панели | **писать** | своего рендера документации в проекте нет |
| Перепись навигации | **писать** | требует знания именно этой панели, готового аналога нет |
| Проверка свежести | **писать** | тривиальный шаг CI, зависимость не оправдана |
| Скриншоты | **брать основу** — Laravel Dusk | в экосистеме проекта, отдельный Playwright не нужен; волна 2 |

## 8. Что архитектура сознательно не решает

- **Упрощение навигации.** Находка фиксируется, код не меняется (R1, R14). Решение по ней — за человеком, по issue.
- **Кеширование и версионирование гида.** Пока файл читается напрямую; понадобится — добавим тогда, когда появится вторая версия текста для разных ролей.
- **Отдельный гид куратора.** Материал куратора живет пометками внутри одного документа (R4). Если пометок станет больше трети текста — это сигнал разделять, но не сейчас.
