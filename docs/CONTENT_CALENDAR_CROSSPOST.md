# Календарь контента: кросспостинг в Telegram и VK

_Создан 22-10-2026._

Пост планируется в админке (**Маркетинг → Календарь контента → Edit**) и в
назначенное время уходит во все отмеченные площадки:

| Ключ | Площадка | env |
|---|---|---|
| `tg_opoveshchenie` | TG «Оповещение санскритян» (-1001762848803) | `CONTENT_CAL_TG_OPOVESHCHENIE` (chat_id или @username) |
| `tg_ors` | TG «Общество ревнителей санскрита» (-1001417740969) | `CONTENT_CAL_TG_ORS` |
| `tg_institut` | TG «Институт исследования санскрита» (-1001730104817) | `CONTENT_CAL_TG_INSTITUT` |
| `vk_opoveshchenie` | VK samskrte (236973776) | `CONTENT_CAL_VK_OPOVESHCHENIE` |
| `vk_ors` | VK samskrtamru (88831040) | `CONTENT_CAL_VK_ORS` |
| `vk_institut` | VK «Институт исследования санскрита» (89658969) | `CONTENT_CAL_VK_INSTITUT` |

Площадка с пустым значением выключена: в форме она серая, «не настроено».
Ключи стабильны: на них завязаны строки `content_calendar_publications`.

**Бот — @zapisi_ORSbot** (`MarketingSetting.zapisi_bot_token`; переменная
`CONTENT_CAL_TG_BOT_TOKEN` только подменяет его). Он админ всех трёх каналов
с правом публикации. Своего вебхука у календаря нет: `channel_post` приходит в
общий поток апдейтов бота записей (`ProcessTelegramZapisiUpdate`; вебхук через
входной узел или аварийный `zapisi:poll`), остальные сценарии бота — разнос
записей по чатам групп, n8n-форварды — не затронуты.

## Откуда берутся слоты

- **Админка** — кнопка «Новый пост» в «Календаре контента»: заголовок (для себя),
  время публикации (MSK, в будущем), текст, вложение, галочки площадок.
  Слот сразу `scheduled`, тип `manual`.
- **Telegram** — любой админ публикует пост в канале «Оповещение санскритян»
  (сразу или отложкой Telegram). Бот записей получает его в момент выхода
  (`channel_post`; отложенные посты бот до выхода не видит — ограничение
  Telegram), создаёт слот типа `tg_channel` с уже опубликованной площадкой
  «TG · Оповещение» и сразу разносит пост в остальные площадки:
  - в TG-каналы — `copyMessage` / `copyMessages` оригинала (разметка, медиа,
    альбом — как есть);
  - в VK — плоский текст и первое вложение, скачанное через `getFile`
    (Bot API отдаёт файлы до 20 МБ; крупнее — пост уйдёт без вложения,
    причина в `meta.tg_media_note`).
  Альбом (несколько медиа) собирается в один слот, разнос — через 20 с после
  первой части. Чек-лист §2.8 удерживает пост от разноса (`draft`).
  Правки поста в канале после выхода не переносятся.

Включение приёма из Telegram: `CONTENT_CAL_TG_INGEST=true` и
`CONTENT_CAL_TG_OPOVESHCHENIE` в `.env`, `config:cache`. Ничего
перерегистрировать не нужно — `channel_post` уже в `allowed_updates` бота
записей (`zapisi:set-webhook`).

## Как это работает

1. `content:publish-due` (ежечасно, флаг `CONTENT_CALENDAR_AUTOPILOT`) берёт
   `scheduled` слоты с наступившим `publish_at`, прогоняет чек-лист §2.8 по
   плоскому тексту и ставит `PublishCalendarSlotJob`.
2. Джоб публикует в каждую выбранную площадку и пишет строку
   `content_calendar_publications` (status / attempts / permalink / error / warning).
   - Telegram — бот записей @zapisi_ORSbot, `parse_mode=HTML`; с вложением —
     `sendPhoto`/`sendVideo` с подписью.
   - VK — `wall.post` от имени сообщества (`from_group=1`) VK ID токеном админа
     (см. ниже). Группа обязана стоять в `VK_PUBLISH_AUTHORIZED_GROUPS`, иначе
     отказ без повторов.
   Если ни одна площадка `CONTENT_CAL_*` не задана, тик ничего не делает.
   Слот, чей `publish_at` прошёл больше 24 ч назад (`max_lateness_hours`) и
   который ещё никуда не публиковался, **не публикуется**, а уходит в `draft`
   с `meta.stale_hold` — чтобы старые посты не вышли пачкой. Новая дата + Keep.
3. Неудачная площадка остаётся `pending` и повторяется на следующем тике, уже
   опубликованные не трогаются. После 3 попыток (или сразу при отказе гейта /
   нет настроек) — `failed` и сообщение админам в Telegram. Слот становится
   `published`, когда pending-площадок не осталось.

Статус по площадкам — колонка «Площадки» в таблице и блок «Публикации» на
странице слота.

## Форматирование

Редактор: жирный, курсив, подчёркнутый, зачёркнутый, ссылка, цитата,
моноширинный (строка и блок), **маркер = спойлер** в Telegram.

- Telegram получает это как HTML (`App\Services\Content\PostFormatter::toTelegramHtml`).
- **Стена VK форматирование не поддерживает** — уходит простой текст, ссылка
  как «текст (url)». Предпросмотр «Как увидит VK» есть в форме.
- С вложением Telegram допускает подпись до 1024 символов, без — 4096; форма
  не сохранит пост длиннее.

## Вложения

Одна картинка или одно видео, до 50 МБ (предел Bot API), диск `public`,
`storage/app/public/content-calendar/`.

**VK.** Загрузить файл в VK можно только с правами `photos` / `video`, а у
токена приложения 54821902 сейчас (23-10-2026) только `wall offline`. Прикрепить
уже существующее медиа хватает `wall`, поэтому `CalendarVkPublisher` выбирает
по порядку:

1. **«Готовое медиа VK»** — поле слота: ссылки на фото/видео/клипы, уже
   загруженные в VK (`vk.com/photo-…`, `vk.com/video-…`, `vkvideo.ru/…`,
   `?z=photo-…`), до 10. Хранятся как `photo-1_2,video-1_3` в
   `vk_attachments`, прикрепляются ко всем VK-площадкам; в Telegram не идут.
2. **Загрузка файла слота** — если у токена есть нужное право.
3. **Картинка без права `photos`** — уходит карточкой-ссылкой на
   `/cc/{slot}/{sig}` (`ContentCalendarShareController`): страница с
   `og:image` = картинка, VK рисует по ней превью. Подпись — HMAC от
   `APP_KEY`, id слота не перебрать. VK делает крупное превью, если
   картинка не меньше 537×240.
4. **Видео без права `video`** — пост уходит текстом, warning в строке
   публикации и сообщение админам.

Когда поддержка VK даст `photos,video`: переавторизоваться, `vk:token-import` —
код сам перейдёт на п. 2.

## VK-токен

VK ID user-токен живёт **час**; refresh ротирует и `refresh_token` — у пары
может быть только один владелец. Владелец — прод:

- хранится в `vk_user_tokens` (Eloquent `encrypted`);
- `vk:token-refresh` — каждые 15 минут, реально обновляет, когда до
  истечения < 35 мин; первая неудача — сообщение админам;
- `vk:token-import` — принять новый токен из stdin (строки `KEY=VALUE` в
  формате `vk_poll.env`: `VK_APP_ID`, `VK_ACCESS_TOKEN`, `VK_REFRESH_TOKEN`,
  необязательно `VK_DEVICE_ID`). Сразу делает refresh и печатает только
  user_id / scope / срок.

Перенос с Mac (значения нигде не печатаются):

```bash
# 1. выключить Mac-агент, иначе он и прод будут ротировать пару наперегонки
ssh mac 'launchctl bootout gui/$(id -u)/ru.samskrte.vk-token-refresh'
# 2. передать ключи по пайпу
ssh mac 'grep -E "^VK_(APP_ID|ACCESS_TOKEN|REFRESH_TOKEN|DEVICE_ID)=" ~/.claude/secrets/vk_poll.env' \
  | ssh vps-samskrte92 'cd <app> && php artisan vk:token-import'
```

После переноса Mac-скрипты (`vk_poll_crosspost.py`) свежего токена больше не
получают.

Если токен умер (Mac/прод молчали дольше часа, refresh отозван) — заново
авторизоваться (`vk_token_setup.py --flow vkid`) и повторить `vk:token-import`.

## Включение

1. `.env` на проде: `CONTENT_CAL_*`, `CONTENT_CAL_TG_BOT_TOKEN`,
   `VK_PUBLISH_AUTHORIZED_GROUPS` (**прод-сообщества — только после «да» MG на
   каждое**), `config:cache`.
2. `vk:token-import` (см. выше).
3. Смоук: слот с одной площадкой → `php artisan content:publish-due` при
   включённом флаге → проверить пост и строку публикации.
4. `CONTENT_CALENDAR_AUTOPILOT=true`.
