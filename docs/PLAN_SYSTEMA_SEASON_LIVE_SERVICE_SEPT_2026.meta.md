## Назначение

Зафиксировать 16 архитектурных решений по игровому сезону, принятых в 4 раунда
интервью 10-08-2026, так чтобы реализующая сессия не пере-решала их заново.
План кодом ничего не меняет — он входной контракт для H2549.

## Ограничения

- **Не реализация.** Ни одной миграции, команды или теста в этом PR. Всё в H2549.
- **Три открытых вопроса** оставлены в §9 намеренно: механизм включения decay из
  `season:open`, семантика `prana_earned`, уведомления. Ни один не блокирует схему.
- **Сезон 2+ не спроектирован.** Ротация паков описана механикой, но набор паков
  для Сезона 2 не выбран — это решение декабря 2026.
- **Публичная поверхность вне плана.** Решено R1-4: только кабинет. Публичная
  страница сезона и анонимный лидерборд — отдельная задача.
- **Прод-параметры decay не проверены на реальной когорте.** `inactive_days=14`
  выбрано из соображения «4-месячный сезон требует ритма», не из данных о
  фактических интервалах между входами. Первый сезон — сам себе замер.

## Ранжированный backlog улучшений

1. **Заполнить `rewards_config` конкретными наградами** — сейчас в §4 описана
   только схема, состав наград Сезона 1 не решён.
2. **Проверить `inactive_days=14` на исторических данных** — распределение
   интервалов между `last_activity_at` по активным студентам; 14 может оказаться
   слишком агрессивным или слишком мягким.
3. **Описать поведение при смене ранга во время сезона** — floor привязан к
   текущему рангу, ранг может вырасти в середине сезона; пересчитывать floor
   при каждом прогоне или фиксировать на старте сезона?
4. **Anti-abuse для сезонного лидерборда** — P2P-перевод праны не растит
   `lifetime`, но растит `balance`; проверить, что сезонный `prana_earned`
   не накачивается переводами между аккаунтами.
5. **Механика «сезон закончился, а награда не забрана»** — `season_rewards`
   имеет `claimed_at`, но TTL на непринятую награду не описан.
