## Предмет

- **Документ:** [`docs/access-self-service-spec.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/access-self-service-spec.md)
- **Назначение:** спецификация Phase 1 «самообслуживания по доступу» — студент из личного кабинета сам диагностирует, почему у него нет доступа, и запускает узкий набор безопасных идемпотентных «самолечащих» действий, разгружая кураторов.
- **Аудитория:** разработчик-исполнитель (Laravel-бэкенд + Blade-фронт Systema-Sanscriticum), а также человек, принимающий три открытых `@DECIDE`-решения в спеке.
- **Формат/контракт:** проектная спека-задание (проблема → что уже есть → гап → архитектура → граница → Done when). Access-контрагент платёжной спеки [`docs/debtor-self-service-spec.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/debtor-self-service-spec.md).

## Известные ограничения / оговорки

- Спека остаётся **проектом с тремя нерешёнными развилками** (`@DECIDE`) — это не финальный контракт, а предложение с рекомендациями.
- Приоритет «access — тема №2» опирается на `php artisan support:topic-ranking`, но конкретная выгрузка в документе не приложена — число не воспроизводится из спеки.
- Архитектура сознательно «тонкая»: диагност только читает, действия — обёртки над существующими эндпоинтами; корректность зависит от того, что перечисленные механизмы (`BlockAccessMaterializer`, `telegram.connect`, `password.request`) не изменятся под ней.
- Граница Phase 1 исключает деньги/долг, записи, авто-повтор вебхука и смену email — эти классы обращений спека не закрывает.

## Предполагаемое использование / возможное злоупотребление

- **Использовать** как задание на реализацию Phase 1 и как чек-лист «Done when» при ревью PR; читать вместе с долговой спекой-контрагентом.
- **Не** трактовать как описание уже существующего кода — это план, а не отчёт; на 13-07-2026 `AccessDiagnosticsService` и панель «Мой доступ» ещё не реализованы.
- **Не** использовать для действий, меняющих деньги/долг, — спека явно выносит их в долговое самообслуживание.

## План сопровождения и вывода из эксплуатации

- **Владелец:** ведущий разработчик Systema-Sanscriticum.
- **Триггеры ревизии:** разрешение любого `@DECIDE`; старт/завершение реализации Phase 1; появление данных `support:topic-ranking`, сдвигающих приоритет; изменение любого из переиспользуемых механизмов.
- **Sunset:** когда Phase 1 реализована и смёржена, спека переходит в статус исторической записи (реализованного дизайна); при появлении Phase 2 — минтить отдельную спеку, не расширять эту.
