# Разблокировка студента + лента «Проблемы со входом» (H849)

_Created: 13-07-2026 · Last updated: 13-07-2026_

Инструмент поддержки: увидеть, кто не может войти, и разблокировать его одним
кликом — из админки или прямо из Telegram, минуя сломанную доставку почты.

## Зачем

Триггер — реальная студентка: письмо со ссылкой не пришло, а на повторную
попытку система писала «Слишком много попыток». Разбор показал две вещи:

- **«Блокировки» как флага у приложения нет.** Войти мешает только IP-троттл
  `throttle:5,1`, который сам спадает за 60 секунд. Настоящая проблема
  застрявшего — не троттл, а **доступ** (не дошло письмо со ссылкой).
- **Неудачные попытки нигде не логировались** — единственным следом были строки
  Laravel в `password_reset_tokens`.

Поэтому «разблокировка» здесь = **снять троттл + выдать рабочую ссылку для
входа**, которую можно передать студенту напрямую (в т.ч. в Telegram).

## Что делает

1. **Лента `access_attempts`** — единый поток проблем со входом:
   - `failed_login` — неверный пароль на `/login` или `/shop/login`
     (слушатель `Auth\Events\Failed`);
   - `reset_sent` / `reset_not_found` / `reset_throttled` — исход запроса ссылки
     восстановления (пишется в `PasswordResetController::sendResetLink`).
2. **Админка (Filament):**
   - Ресурс **«Проблемы со входом»** (`AccessAttemptResource`, группа
     «Пользователи») — свежие попытки, бейдж числа неразобранных, фильтр
     «только неразобранные», разблокировка из строки.
   - Кнопка **«Разблокировать»** на карточке студента (`UserResource`).
3. **Разблокировка** (`StudentUnblockService::unblock`): снимает IP-троттл для
   всех недавних IP студента + выпускает **одноразовую magic-ссылку** для входа
   (назначение `admin_unblock`, TTL 24 ч, hashed-at-rest, маршрут
   `GET /login-link/{token}`) + опционально сбрасывает пароль. Ссылку админ
   показывает в уведомлении и передаёт студенту.
4. **Telegram:**
   - **Проактивный алерт** админам (`ADMIN_TELEGRAM_ID`) с inline-кнопкой
     «🔓 Выслать ссылку», когда человек застрял (троттл восстановления либо серия
     неудачных логинов известного студента). Алерты дедуплицируются по email/IP.
   - Команда **`/unblock <email>`**.

## Безопасность / права

- Выдача ссылки = потенциальный вход в чужой кабинет, поэтому и кнопки в админке,
  и Telegram-путь ограничены **`super_admin`/`admin`** (менеджер-куратор — нет).
  В админке — через `AdminOnly`/`RoleGate::adminOnly()`; в Telegram — по
  `telegram_id → роль`, неавторизованным тишина.
- Ссылка одноразовая, короткоживущая, в БД лежит только SHA-256-hash. Маршрут
  `/login-link/{token}` принимает **только** токены назначения `admin_unblock`
  (newsletter-ссылки сюда не подходят и наоборот).

## Настройка

- `ADMIN_TELEGRAM_ID` (`config/services.php` → `telegram.admin_id`) — куда идут
  проактивные алерты (несколько ID через запятую). Алерты и `/unblock` работают
  основным ботом (`TELEGRAM_BOT_TOKEN`).
- Миграция `access_attempts`: `php artisan migrate`.

## Что это НЕ чинит

Корневую причину недоставки писем (боевой SMTP / верифицированный домен
отправителя) — это отдельная серверная задача. Инструмент даёт админу способ
**обойти** сломанную почту вручную, пока доставка не починена.
