## Предмет

- **Документ:** [group-recruitment-module-spec.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/group-recruitment-module-spec.md)
- **Назначение:** архитектурная спецификация (design-only, без кода) минимального модуля «Набор курсов» — статус формирования группы, плановая/фактическая дата старта и авто-уведомление уже оплативших студентов о недоборе, спроектированные поверх уже существующих сущностей.
- **Аудитория:** MG (владелец продукта, принимает открытые развилки), разработчик, который будет реализовывать модуль в кодовой базе Laravel/Filament, куратор как конечный пользователь curator-facing раздела.
- **Формат/контракт:** спека фиксирует reuse-first-инвентаризацию существующего кода, перечень недостающего (поля, таблица, scheduled-команда, Filament-раздел) и явный список вынесенного за объем. Design-only: никакие миграции/классы в этой сессии не создаются; несколько развилок оставлены открытыми для решения на реализации.

## Известные ограничения / оговорки

- Спека — **проектная, а не реализация**: ни одна из описанных сущностей (поля `Group`, `enrollment_preferences`, команда `groups:notify-forming-shortfall`) на момент 04-07-2026 в коде не создана.
- Несколько центральных решений сознательно оставлены открытыми (получатель уведомления, формат сбора предпочтений, авто-переход статуса) — спека не является полной до их закрытия.
- Раздел «Reuse-first» опирается на состояние кодовой базы на 04-07-2026; при рефакторинге перечисленных классов (`Group`, `MarketingSetting`, `CuratorNotifier`, `SendMessengerAlerts`) ссылки-обоснования могут устареть.
- Каденс уведомлений намеренно сужен до «за 2 дня» — расширение до «в день Х»/«через неделю» вынесено за объем и потребует отдельной настройки.

## Назначение / возможное неверное использование

- **Использовать** как отправную точку реализации: сначала свериться с reuse-инвентаризацией, чтобы не строить с нуля, затем закрыть открытые развилки, затем писать миграции/команды.
- **Не использовать** как готовое ТЗ «под ключ»: пока открытые развилки не решены MG, прямая имплементация рискует зашить неверного получателя уведомления или лишнюю таблицу предпочтений.
- **Не путать** design-only статус с наличием функциональности — на момент написания модуль в продукте отсутствует.

## План сопровождения и вывода из эксплуатации

- **Сопровождение:** обновлять при закрытии каждой открытой развилки (перевести соответствующую строку бэклога в done со ссылкой на решение/PR) и при старте реализации — добавить статус готовности.
- **Вывод из эксплуатации:** спека устареет, когда модуль «Набор курсов» будет реализован и покрыт кодом/тестами — тогда роль источника истины переходит к коду, а спеку следует пометить как исторический design-record (не удалять — фиксирует исходное обоснование reuse-first).
