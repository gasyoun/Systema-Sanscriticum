## Известные ограничения / оговорки

- Спека описывает **состояние одного PR** (дельта H476), а не полную схему атрибуции — половина контракта живёт в prior art H267 и без него не читается.
- Номер PR самой дельты в тексте отсутствует; проверяемость сведена к именам классов/файлов.
- Раздел «Как читать через месяц» — план, а не результат: пока не появится committed-выгрузка, замыкающих цифр нет.
- Границы «чего в PR нет» отражают продуктовое решение на 10-07-2026 и могут разойтись с текущим кодом при следующей итерации воронки.

## Предполагаемое использование / известное злоупотребление

- **Использовать** как обоснование, почему `signup_source` — nullable-словарь без свободного текста, и почему год рождения не пошёл в trial; как отправную точку для месячного среза каналов.
- **Не использовать** как актуальный реестр всех полей атрибуции (это срез одного PR), как ПДн-регистр (канон — [B16](https://github.com/gasyoun/Uprava/blob/main/dpo/ip-gasuns/B_lna/B16_pdn.md)), и как основание менять валидацию без сверки с текущим кодом контроллеров.

## План поддержки и вывода из эксплуатации

- **Ревизия:** при любом изменении набора `SIGNUP_SOURCES`, при подключении partial в новую форму, либо когда появится первый месячный срез — бампнуть «Last updated» и добавить строку в историю ревизий.
- **Sunset:** после появления сводного реестра полей атрибуции (бэклог #3) эта спека переводится в статус исторического артефакта H476; отдельного удаления не требует.
