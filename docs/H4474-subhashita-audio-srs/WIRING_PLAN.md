## Steps (once rights confirmed)

1. **Fill the 46 medium-confidence + 121 unmatched rows.** The medium tier needs a human or a second matching pass (e.g. matching on the *second* word, or on the Devanagari string directly instead of the transliteration) — do not auto-promote medium → high without a spot-check, the way this session hand-verified 5 of the 40 high rows.
2. **Resolve the `Subhashitas-Systematic` vs `Subhashitas-Systematic (1)` duplicate set.** Both folders hold recordings of the *same* 96 sayings under two numbering schemes (confirmed this session: `Su94-Yatha.mp3` ↔ `94 (95) ... Yatha...mp3`, `Su95-Vishasya.mp3` ↔ `95 (94) ... Vishasya...mp3` — the parenthesized number in folder 2 is a renumbering correction, not a different saying). Pick ONE as canonical (recommend `Subhashitas-Systematic/` — its `SuN-Name.mp3` naming is unambiguous and it carries the reference docx lists) and drop the other from the deck to avoid duplicate audio.
3. **Move the actual mp3 bytes.** WebDAV → download → re-encode/normalize loudness if needed → host wherever Systema-Sanscriticum serves media today (check `app/Http/Controllers` for the existing lecture-audio pattern before inventing a new storage path — reuse-check first, per org policy).
4. **New deck JSON** at `kosha/data/srs/srs-deck-subhashita-audio-v1.json` following the shape above, built by a script mirroring [`scripts/build_subhashita_pack.py`](https://github.com/gasyoun/kosha/blob/main/scripts/build_subhashita_pack.py)'s I/O contract.
5. **Register the new dataset row** in [kosha `data/manifest/datasets.json`](https://github.com/gasyoun/kosha/blob/main/data/manifest/datasets.json) per [SHARED_CODE.md](https://github.com/gasyoun/github-spine/blob/main/SHARED_CODE.md) §8/§10 — do not skip, this is exactly the kind of derived asset that hub expects a row for.
6. **Systema-side SRS UI**: locate the existing flashcard/SRS review component (grep `srs` in `resources/js` or `app/Livewire`) and add an audio-play affordance per card when `audio_file` is present — feature-flagged OFF by default per [money-pr-land](https://github.com/gasyoun/claude-config/blob/main/commands/money-pr-land.md) since this touches the paid product surface.
7. **Acceptance for the wiring PR itself**: ≥1 rendered screenshot of the audio-enabled card in a browser (per this org's UI-change rule — start the dev server, don't just ship untested), a manual play-through of 3 sample cards, and the feature flag confirmed OFF in the default config.
