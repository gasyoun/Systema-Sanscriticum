# ADR 0015: студент в учебном чате не мутирует и не молчит — canned-подсказки + стопочка

Рулинг MG 21-11-2026 («молчание бота в учебном чате НЕ допускается никогда», инциденты
гр.57 и Кашмирский шиваизм 20–21.11): reply-вопрос участника на пост zapisi-бота получает
детерминированную одну строку по типу поста (ДЗ-пост → что такое ДЗ и где список/сдача;
напоминание → ссылка в посте, записи в кабинете; расписание → ближайшее занятие), а
нераспознанный вопрос — «вопрос зафиксировал» + запись в `telegram_student_questions`
(стопочка) с CuratorAi-черновиком куратору (SupportAnswerSuggester-паттерн P1: черновик
только хранится, никогда не отправляется). Студенческие предложения переносов — ТОЛЬКО
в стопочку (kind=proposal): студенческий текст НИКОГДА не применяет перенос/отмену/архив
(мутационный pin-тест `StudentMutationPinTest`).

Решения по контуру:

- Поверхность ack = опознанный по панели участник (студент, не staff). Неопознанные
  отправители молчат, как и сегодня (спам-безопасность; группа закрыта paid-входом,
  участники — оплатившие студенты с кабинет-аккаунтом).
- Флаг `student_question_ack_detect` default **true** (нарушение рулинга и есть
  инцидент, поэтому не fail-closed, вопреки соседним флагам); OFF — только аварийный
  стоп. `student_question_group_ids` пустой = все zapisi-группы.
- LLM не ходит в учебный чат: в чате только canned-строки, CuratorAi пишет черновик
  куратору отдельным джобом (OpenRouter + PII-маскировка, fail-closed).
- Мульти-перенос и сдвиг дня недели (`AnnounceRescheduleService`) — teacher/staff
  ACL как раньше; все пары применяются ОДНОЙ транзакцией (несовпадение числа дат,
  прошедший источник, занятый целевой слот → уточнение и ноль мутаций). Прошедшие
  даты не двигаются (старый pin), явная будущая дата источника теперь применяется.
- Каждый перенос из мульти-сообщения — своя строка `TelegramScheduleReschedule`
  (уникальность ослаблена до chat+message+schedule) со своей кнопкой «Отменить
  перенос (1 ч)».

Status: accepted 21-11-2026 (H8527, рулинг MG 21-11).

Consequences: студенческий чат получает одну строку на вопрос вместо тишины; стопочка
становится источником проактивной обработки для агентов MG (`zapisi:student-questions
--json`); расширение парсера переносов ограничено явными паттернами, всё остальное —
уточнение.
