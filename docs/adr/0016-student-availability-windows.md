# ADR-0016 — Окна доступности ученика (RRULE + TZID) и OfferGate

_Created: 26-11-2026 · Status: accepted · Game rules: grilling + domain-modeling, 3 раунда_

## Context

Новый ученик (`korolevan889@gmail.com`) сообщил, когда он вообще может заниматься:
пн–ср — никак; чт после 20:00; пт после 18:00; сб 09:00–11:00 и после 14:30;
вс после 17:00 (МСК). В системе не было никакой per-student модели времени:
существовали только `WaitlistVote::SLOT_PREFERENCES` (утро/день/вечер) и
`BillingProfile::preferred_mode` (поток A/B) — границы 14:30 и 20:00 ими не
выражаются. Требовалось (а) дать ему самому быстро создать кабинет через бота,
(б) навсегда зафиксировать окна и (в) не предлагать новый курс/факультатив вне окон.

## Decision

1. **Хранить RRULE + TZID в своей таблице** `student_availability_windows`
   (`user_id, source, kind, rrule, start_time, end_time, tzid, valid_from, valid_until`).
   Одна строка = одно окно; два интервала в субботу = две строки. Поддерживаемый
   подвид RRULE — `FREQ=WEEKLY;BYDAY=…`; всё остальное отторгается исключением,
   а не молча разрешается. Основа — паттерн Cal.diy / Calnode (недельные окна +
   IANA-таймзона), но без отдельного self-hosted шедулера: у нас офферы курсов,
   а не запись на приём.
2. **Вводят оба**: студент сеткой на новой вкладке `/dvaram/availability`
   (за флагом `availability_windows`, default OFF), куратор — в Filament. Уточнение
   27-11-2026: у студента есть оба режима — «Удобное время» (`allow`) и «Неудобное время»
   (`deny`); последний перекрывает его же `allow`.
3. **Приоритет куратора — любой**: `deny` куратора запрещает, `allow` куратора разрешает,
   оба перекрывают студенческие строки. Студент не может редактировать строки куратора.
4. **OfferGate применяется только к новым офферам**: фильтрует строки списка
   ожидания в кабинете (`buildDashboardWaitlistData`) по известному недельному
   слоту. Купленное и текущее обучение, расписание, ДЗ не трогаются.
5. **Границы**: у студента без строк фильтр не применяется (поведение как сейчас);
   «после 20:00» = до 23:59 того же дня; TZ по умолчанию `Europe/Moscow`
   (переиспользуем уже существующее `User::timezone()` из H4434).
6. **Запись ученика**: `TH 20:00–23:59`, `FR 18:00–23:59`, `SA 09:00–11:00`,
   `SA 14:30–23:59`, `SU 17:00–23:59`; пн–ср строк нет.

## Alternatives considered

- **Готовый шедулер** (Cal.diy MIT / Calnode Apache-2.0 / The Booking Kit RRULE):
  избыточен — решает задачу записи на приём, а не фильтрации офферов; Cal.diy к тому
  же рекомендован только для личного пользования.
- **Грубые слоты** `WaitlistVote::SLOT_PREFERENCES`: не выражают 14:30/20:00.
- **Blackout-only**: не выражает «только после 20:00».
- **Фильтр везде** (витрина, ждун-бот, генератор расписания): отклонено — в этом
  проходе гейтится только кабинет.

## Consequences

- Миграция + флаг должны быть выкачены до включения `AVAILABILITY_WINDOWS_ENABLED`;
  при OFF всё байт-стабильно.
- RRULE хранится как строка, но интерпретатор поддерживает только недельный `FREQ=WEEKLY`
  с `BYDAY`; при расширении формата нужно обновить парсер и тесты.
- Кураторские строки видны в Filament; их изменение немедленно меняет офферы.
