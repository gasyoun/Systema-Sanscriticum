## Предмет

- **Документ:** [`docs/student-manual.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/student-manual.md)
- **Назначение:** единая карта личного кабинета студента (`/dvaram`) — все вкладки, кнопки и механики так, как их видит студент сегодня; связывает воедино отдельные спеки (долги, доступ, бот), не дублируя их.
- **Аудитория:** разработчики и кураторы Академии, которым нужна полная (не только «первые 5 минут») техническая карта кабинета.
- **Формат/контракт:** обзорный справочник-«хаб» на Markdown, разбитый по разделам-вкладкам (§1–§11 + FAQ); осознанно делегирует детали профильным спекам вместо их копирования.

## Известные ограничения / оговорки

- Описывает состояние кабинета **на момент правки** («как видно студенту сегодня») — снимок UI без привязки к номеру релиза, поэтому дрейфует по мере изменений продукта.
- Сознательно **не самодостаточен**: механика долгов, доступа и бота живёт в отдельных спеках; при их изменении этот файл может рассинхронизироваться, не «зная» об этом.
- Часть разделов условна и зависит от настроек школы (Прана, decay, соц-вход) — описанное может быть выключено в конкретной инсталляции.
- Ссылается на finance-manual/admin-manual, которые на момент правки ещё в PR #328, а не в `main`.

## Предполагаемое использование / вероятные злоупотребления

- **Использовать** как отправную карту при онбординге куратора/разработчика и как индекс к профильным спекам кабинета.
- **Не использовать** как дружелюбный чек-лист для самого студента — для этого есть [`docs/onboarding-student.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/onboarding-student.md).
- **Не трактовать** как источник истины по механике долгов/доступа/бота — там первичны профильные спеки; этот файл лишь связывает их.

## План сопровождения и вывода из эксплуатации

- **Триггеры ревизии:** мерж PR #328; любое изменение вкладок кабинета, механики праны, способов входа или адресов (`/dvaram`).
- **Владелец:** разработчики/кураторы Систему-Санскритикум.
- **Сунсет:** остаётся живым, пока кабинет студента активен; при крупном редизайне UI — переписать раздел за разделом, а не латать.
