## 1. Резюме — EduTech-позиционирование и цели года

Продукт зрелый: денежный контур, доступы, helpdesk с AI-черновиками, геймификация, CRM-кокпит,
модуль набора и вебинарный цикл уже построены. Год 2026–2027 — не строительство платформы, а
**превращение построенного в измеримый EduTech-бизнес**: включить в проде то, что лежит за
флагами, замкнуть воронку «канал → лид → оплата → активация → удержание» данными и добавить
два продуктовых дифференциатора (native SRS и словарь ↔ CDSL), которых нет ни у одной
Sanskrit-LMS.

| Поток | Метрика | Цель года (к 30-06-2027) |
|---|---|---|
| **A. Acquisition / воронка** | CAC, конверсия лид→оплата | атрибуция «канал→оплата» замкнута; CAC посчитан по ≥2 платным кампаниям; поисковый трафик — управляемый канал (SEO P2) |
| **M. Monetization** | ARPU, LTV, средний чек | записи завершённых курсов продаются (evergreen); юнит-экономика замкнута на всех трёх уровнях (урок H226 ✅ · ученик-LTV/CAC H256 ✅ · маржа группы — M3); PayPal в финконтуре |
| **O. Onboarding / activation** | % активированных, time-to-first-lesson | никто из оплативших не «висит» без входа; TTFL меряется по когортам |
| **R. Engagement / retention** | DAU/WAU, retention, churn | SRS-пилот живёт на ≥1 курсе; прана публикована и наблюдается; win-back меряется |
| **SUP. Support / забота** | часы кураторов, время ответа | ≥60 % автоматизируемого потока закрыто ([H243](https://github.com/gasyoun/Uprava/blob/main/handoffs/H243-Fable_Systema-Sanscriticum_support_automation_year_roadmap_06.07.26.md)) |
| **T. Teachers / operations** | маржа, нагрузка на команду | зарплатный контур без известных багов; набор ведётся в LMS, не в Google-таблице; темп групп сравним данными |
| **C. Content / product** | завершаемость курса, NPS | завершаемость меряется; словарь кабинета подключён к CDSL; лекторий v2 без хвостов |
| **X. Tech / надёжность** | инциденты, скорость доставки | прод на PHP 8.3 + Laravel 11; деплой одной командой; error-tracking + проверенный restore; 0 открытых money-находок |

## 2. Зафиксированные решения (не переоткрывать)

Перенесены из редакции 02–04-07-2026 без изменений — это входные условия всех тикетов ниже.

**Roadmap-интервью 02-07-2026 (MG):**

- **Порядок приоритетов года:** (1) production operability → (2) money/finance hardening →
  (3) support/AI automation → (4) student-facing growth. Позже (05-07-2026) native SRS помечен
  MG как **top priority, start now** — итоговое примирение сигналов в §3.
- **AI-приватность (`@DECIDE` снят):** разрешено отправлять support-контент в OpenRouter
  **включая импортированные приватные Telegram-ЛС** — в проде можно включать оба флага
  `features.support_ai_assist` **и** `features.support_ai_include_telegram`. В коде дефолты
  остаются ВЫКЛ (env-gated); включение — шаг активации прода.
- **Активация прода:** человеческие шаги (миграции, интерактивный TG-логин, Zoom-креды) — за MG.
- **Деплой — скриптованный, на сервере:** один идемпотентный `deploy.sh` (pull → composer →
  vite build → сброс кэшей → migrate → рестарт Horizon → smoke-check), запускается вручную по
  SSH; полноценный CD через GitHub Actions не строим. Закрывает
  [#193](https://github.com/gasyoun/Systema-Sanscriticum/issues/193). См.
  [`docs/deploy.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/deploy.md).
- **Laravel 10 → 11 — не откладывать** (PHP 8.1 без security-патчей с декабря 2025, Laravel 10 —
  с февраля 2025; год на EOL-стеке для платёжного приложения неприемлем). Сразу после PHP 8.3.
- **Словарь кабинета ↔ Кёльнская линейка:** одобрено — MW/PWG/Apte через Kosh/Salt API в
  [`csl-apidev`](https://github.com/sanskrit-lexicon/csl-apidev) или bulk-импорт, поверх —
  кураторский слой курсовой лексики. Уникальное преимущество: ни одна Sanskrit-LMS такого не имеет.
- **Продажа записей завершённых курсов**
  ([#190](https://github.com/gasyoun/Systema-Sanscriticum/issues/190)): одобрено — ложится на
  существующую тарифную модель (`full`/`block_N`).
- **Jivo:** решение об отказе — по данным в Q1 2027 (native inbox vs Jivo после Q4).
- **Прана:** ship & observe — опубликовать построенное, наблюдать, без новых механик в этом
  году; decay остаётся ВЫКЛ.
- **Наблюдаемость:** error-tracking (Sentry или self-hosted аналог) + регулярная проверка
  восстановимости Spatie-бэкапов — дефолт (переспросить, если Sentry-подписка нежелательна).

**CUSTDEV-дельты 03-07-2026** (полный отчёт приватен:
[`Uprava/custdev/CUSTDEV_2026.md`](https://github.com/gasyoun/Uprava/blob/main/custdev/CUSTDEV_2026.md),
резолвится только у MG):

- **Покупатель = женщина 35–55, Москва/СПб, мобильная** (>90 % покупателей 35+, ~60 % женщин,
  ~90 % мобильного соц-охвата) → маркетинг-тон и UX под зрелую аудиторию; мобильный аудит +
  PWA-проверка обязательны (тикет C3).
- **Самая вовлечённая когорта (25–34) почти не покупает живые потоки** → главный аргумент за
  записи/evergreen (тикет M1).
- **Поиск — крупнейший внешний канал (~39 % визитов) без всякого SEO-продукта** → SEO P2 /
  словарь-магнит (тикеты A2, C2).
- **Платного привлечения фактически нет** → сперва атрибуция «лид → пользователь → оплата»
  (тикет A1), затем малый платный эксперимент на VK (тикет A3).
- **Атрибуция обрывается в CRM** (возраст известен у ~7 %, e-mail у ~20 %) → при
  регистрации/онбординге забирать источник прихода и год рождения (тикет A1).
- **Международный сегмент существует при нулевых усилиях** (~10–15 % выручки через PayPal,
  диаспора, чек выше среднего) → дешёвые шаги (тикеты M2, M4); полноценный EN-продукт НЕ строим
  (остаётся `@DECIDE`).
- **YouTube-масштаб иллюзорен** (вирусный не-санскритский контент на ТВ) → канал — витрина, не
  воронка; рост канала как KPI не использовать.

Открытые `@DECIDE` (зеркалятся в
[`Uprava/GTD_NEXT_ACTIONS.md`](https://github.com/gasyoun/Uprava/blob/main/GTD_NEXT_ACTIONS.md)):

## 3. Приоритизация — 4 метрики сразу и итоговый порядок

Каждый тикет оценён по четырём метрикам (1–5): **(1) часы кураторов/команды**,
**(2) выручка/LTV**, **(3) удовлетворённость студентов**, **(4) простота внедрения** — сводный
приоритет с перевесом дешёвых быстрых побед (принцип MG 06-07-2026: минимум внешних расходов,
LLM только с префильтром; переиспользование кода — для каждого тикета указано, что именно
переиспользуется).

Примирение зафиксированных сигналов приоритета (интервью 02-07: operability → money → support →
growth; `.ai_state.md`/[`AGENTS.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/AGENTS.md):
support-аналитика → salary/finance → hardening → UX; native SRS = top priority 05-07) — **итоговый
порядок года**:

1. **X0 — деплой-разблокировка и активация прода** (gate: почти всё построенное выключено, пока
   нет миграций/флагов; человеческий шаг, не agent).
2. **SUP Q3 (S1–S4)** — support-автоматизация до сезонного пика 01-09-2026 (S3 уже ✅).
3. **R1 — native SRS Волна 1** — top priority MG; agent-доставимо параллельно, прод не нужен.
4. **M1 записи + A1 атрибуция** — деньги из уже произведённого; agent-доставимо, прод не нужен.
5. **X2 — money-core hardening** (остаток H071 + разбор PR-очереди на ревью MG).
6. Остальное — по кварталам ниже.

Противоречия между сигналами нет: пункты 1–2 — «operability + support», 3–4 — точечные growth-
исключения, явно поднятые MG позже интервью; money/hardening остаётся стоячим приоритетом на
каждый денежный diff.

## 4. Ставки года

Три главные ставки — то, что через год должно отличать продукт, а не просто «сделанные тикеты»:

1. **Native SRS — «Anki для санскрита и хинди»** (R1–R3). Единственный продуктовый
   дифференциатор такого рода среди Sanskrit-LMS; бьёт в retention и завершаемость — самые
   дорогие метрики школы с живыми потоками. Обоснование по метрикам: удовлетворённость 5,
   выручка 4 (удержание = повторные блоки), при умеренной цене (FSRS + существующий
   `DictionaryWord`, ноль внешних сервисов).
2. **Support-автоматизация ≥60 % deflection** ([H243](https://github.com/gasyoun/Uprava/blob/main/handoffs/H243-Fable_Systema-Sanscriticum_support_automation_year_roadmap_06.07.26.md)).
   Часы кураторов — главный операционный ограничитель роста: 38.5 % вопросов автоматизируемы
   (~190/мес), инфраструктура уже построена. Обоснование: часы 5 при простоте 4 (черновики без
   LLM там, где факты в LMS).
3. **Деньги из уже произведённого** (M1 записи + A1 атрибуция + M3 маржа групп). Записи
   монетизируют контент, который уже есть, для когорты, которая уже ходит, но не покупает живые
   потоки; атрибуция и маржа групп достраивают юнит-экономику (урок H226 и ученик H256 уже
   считаются) до расчёта вместо интуиции. Обоснование: выручка 5/4/4 при нулевом новом контенте.
