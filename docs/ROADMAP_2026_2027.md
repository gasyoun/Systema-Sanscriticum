## 1. Резюме — EduTech-позиционирование и цели года

Продукт зрелый: денежный контур, доступы, helpdesk с AI-черновиками, геймификация, CRM-кокпит,
модуль набора и вебинарный цикл уже построены. Год 2026–2027 — не строительство платформы, а
**превращение построенного в измеримый EduTech-бизнес**: включить в проде то, что лежит за
флагами, замкнуть воронку «канал → лид → оплата → активация → удержание» данными и добавить
два продуктовых дифференциатора (native SRS и словарь ↔ CDSL), которых нет ни у одной
Sanskrit-LMS.

| Поток | Метрика | Цель года (к 30-06-2027) |
|---|---|---|
| **A. Acquisition / воронка** | CAC, конверсия лид→оплата | атрибуция «канал→оплата» замкнута; CAC посчитан по ≥2 платным кампаниям; поисковый трафик — управляемый канал (SEO P2) |
| **M. Monetization** | ARPU, LTV, средний чек | записи завершенных курсов продаются (evergreen); юнит-экономика замкнута на всех трех уровнях (урок H226 ✅ · ученик-LTV/CAC H256 ✅ · маржа группы — M3); PayPal в финконтуре |
| **O. Onboarding / activation** | % активированных, time-to-first-lesson | никто из оплативших не «висит» без входа; TTFL меряется по когортам |
| **R. Engagement / retention** | DAU/WAU, retention, churn | SRS-пилот живет на ≥1 курсе; прана публикована и наблюдается; win-back меряется |
| **SUP. Support / забота** | часы кураторов, время ответа | ≥60 % автоматизируемого потока закрыто ([H243](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H243-Fable_Systema-Sanscriticum_support_automation_year_roadmap_06.07.26.md)) |
| **T. Teachers / operations** | маржа, нагрузка на команду | зарплатный контур без известных багов; набор ведется в LMS, не в Google-таблице; темп групп сравним данными |
| **C. Content / product** | завершаемость курса, NPS | завершаемость меряется; словарь кабинета подключен к CDSL; лекторий v2 без хвостов |
| **X. Tech / надежность** | инциденты, скорость доставки | прод на PHP 8.3 + Laravel 11; деплой одной командой; error-tracking + проверенный restore; 0 открытых money-находок |

## 3. Приоритизация — 4 метрики сразу и итоговый порядок

Каждый тикет оценен по четырем метрикам (1–5): **(1) часы кураторов/команды**,
**(2) выручка/LTV**, **(3) удовлетворенность студентов**, **(4) простота внедрения** — сводный

LLM только с префильтром; переиспользование кода — для каждого тикета указано, что именно
переиспользуется).

Примирение зафиксированных сигналов приоритета (интервью 02-07: operability → money → support →
growth; `.ai_state.md`/[`AGENTS.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/AGENTS.md):
support-аналитика → salary/finance → hardening → UX; native SRS = top priority 05-07) — **итоговый
порядок года**:

1. **X0 — деплой-разблокировка и активация прода** (gate: почти всё построенное выключено, пока
   нет миграций/флагов; человеческий шаг, не agent).
2. **SUP Q3 (S1–S4)** — support-автоматизация до сезонного пика 01-09-2026 (S3 уже ✅).
3. **R1 — native SRS Волна 1** — top priority MG; agent-доставимо параллельно, прод не нужен.
4. **M1 записи + A1 атрибуция** — деньги из уже произведенного; agent-доставимо, прод не нужен.
5. **X2 — money-core hardening** (остаток H071 + разбор PR-очереди на ревью MG).
6. Остальное — по кварталам ниже.

Противоречия между сигналами нет: пункты 1–2 — «operability + support», 3–4 — точечные growth-
исключения, явно поднятые MG позже интервью; money/hardening остается стоячим приоритетом на
каждый денежный diff.
