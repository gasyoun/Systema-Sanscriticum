# Инструкция для бухгалтера

_Created: 02-07-2026 · Last updated: 18-08-2026_

Документ описывает **весь функционал**, доступный пользователю с ролью **«Бухгалтер»** в админ-панели Общества ревнителей санскрита (ОРС). Написан для не-технического сотрудника: что видно, что можно делать, как выполнять типовые задачи.

> Роль назначает супер-админ. Если каких-то разделов из этой инструкции вы не видите — значит, у вашей учетной записи другая роль; обратитесь к администратору.

> **Отдельный вход-точка:** [`finance-manual.md`](finance-manual.md) — короткий
> обзорный документ поверх этого файла с полной картой ролей (кто из
> админ/бухгалтер/супер-админ что видит) и содержанием обоих финансовых разделов.
> Если вы не бухгалтер, а администратор/владелец — начните оттуда.

---

## 1. Вход и общая навигация

- **Адрес панели:** `/admin` (например, `https://samskrtam.ru/admin`).
- Входите по своему email и паролю. После входа открывается **Дашборд** с общими показателями (продажи, статистика студентов, должники, ближайшие обещания оплаты, «застрявшие» студенты).
- Все разделы бухгалтера собраны в левом меню, преимущественно в группе **«Продажи»**.

### Что видит бухгалтер (карта меню)

| Раздел | Группа меню | Права бухгалтера |
|---|---|---|
| **Финансы** (транзакции) | Продажи | Полный доступ: смотреть, создавать, редактировать, удалять, импортировать |
| **Зарплаты** (преподавателей) | Продажи | Полный доступ: расчет, выплаты, авансы, закрытие месяца |
| **История выплат** | Продажи | Полный доступ: смотреть, создавать, редактировать, удалять, экспорт |
| **Финансовый штурвал** (§4c) | Финансы | Полный доступ: ОПиУ, ДДС, Баланс, платежный календарь (виден и администратору — `RoleGate::finance()`) |
| **Расходы (opex)** (§4d) | Финансы | Полный доступ: смотреть, создавать, редактировать, удалять |
| **Планирование (шаблоны)** (§4e) | Финансы | Просмотр/скачивание шаблонов |
| **Потоки курса** (§4k) | Финансы | Только чтение: сравнение потоков одной программы + экспорт в Excel + акт сверки PDF |
| **Подтверждение выплат преподавателям** (§4l) | Финансы | Подтвердить/отклонить: какой платёж-«Расход» был выплатой преподавателю |
| **Участники по блокам** (§4i) | Пользователи | Только чтение: кто какой блок оплатил (с 18-08-2026 — у бухгалтера, не у администратора) |
| **Студенты** (список) | — | **Только просмотр** (создавать/править/удалять нельзя) |
| **Дашборд** | — | Просмотр общих виджетов |

### Чего бухгалтер НЕ видит (по задумке)

Эти разделы закрыты — это нормально, не ошибка:

- **Должники** и **Реактивация** — только у администратора;
- **Журнал финансов** (аудит-лог изменений платежей, §4g) — только у супер-админа, даже
  администратор его не видит;
- **Лиды**, **Стоимость лида**, **Курсы / Уроки / Расписание / Сертификаты / Группы / Домашние задания** — у администратора/преподавателя/менеджера.

По вопросам из закрытых разделов обращайтесь к администратору.

## 2. Раздел «Финансы» (транзакции)

Главный рабочий раздел. Здесь хранятся **все денежные движения**: оплаты студентов, брони (предоплаты), расходы/возвраты и выплаты зарплат преподавателям.

### 2.1. Таблица транзакций

Колонки:

- **Дата** — день операции.
- **Студент** — ФИО + email.
- **Курс и Тариф** — за что платеж (весь курс, блок, половина блока, бронь и т. п.).
- **Сумма** — зеленым для оплат, **красным для отрицательных** (расход/возврат), серым — если еще не оплачено.
- **Скидка** — бейдж `-10%` или `-1000 ₽`, если платеж прошел со скидкой.
- **Промокод** — скрытая колонка (включается тумблером колонок).
- **Статус** — Оплачено / Ожидает / Отменено.
- **Примечание (Банк)** — ID транзакции банка или комментарий (скрытая колонка).

### 2.2. Фильтры

- **По курсу** — выбрать конкретный курс.
- **Оплаченный блок №** — найти всех, кто оплатил конкретный блок (учитывает и покупку всего курса, и диапазоны блоков). Комбинируется с фильтром по курсу.
- **По статусу** — Ожидает / Оплачено / Отменено.
- **Только брони (депозиты)** — показать/скрыть предоплаты-брони.
- **Заявки PayPal на проверке** — pending `provider=paypal` (диаспора). Сверить перевод в **личном** PayPal (`gasyoun@gmail.com`) по полям «с какого PayPal / дата / сумма» → кнопка **«Подтвердить PayPal»** (откроет доступ).
- **Счета юрлиц на проверке** — pending `provider=invoice`. Сверить безнал на р/с школы → **«Подтвердить счет»**. Печать: действие **«Счет»**.
- **Период** — диапазон дат «с … по …».

> **H2017 (с 31-07-2026 на проде):** PayPal и счет для компании **включены**. Это не автоэквайринг Точки: доступ открывается только после ручного подтверждения. Подробнее: [money-diaspora-paypal-buyer-path](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/copy/money-diaspora-paypal-buyer-path.md), [money-company-invoice-path](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/copy/money-company-invoice-path.md), [Tochka audit](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/TOCHKA_PAYMENT_METHODS_AUDIT_2026-07-31.md).

### 2.3. Создание транзакции вручную

Кнопка **«Создать»** (вверху справа). Поля:

- **Студент** и **Курс** — обязательны.
- **Тариф (Доступ)** — определяет, какой доступ откроется студенту:
  - **Весь курс целиком** — открывает все уроки курса;
  - **Блок N** — открывает целый блок (4 занятия);
  - **Блок N — 1-я / 2-я половина** — открывает половину блока (если блок продается «по половинам»);
  - **📌 Бронь курса (предоплата)** — депозит, который позже зачитывается в полную оплату;
  - **🎟 Пробное занятие** — доступ к одному уроку;
  - **💸 Системный расход / Возврат** — движение денег без открытия доступа (для отрицательных сумм/возвратов);
  - **👨‍🏫 Выплата преподавателю** — отток по зарплате.
- **Сумма (₽)** — для расхода/возврата вводится со знаком минус.
- **Оплачен с блока № / По блок №** — для поблочных покупок проставляются автоматически при выборе тарифа (можно поправить вручную).
- **Скидка %** / **Скидка ₽** — обычно заполняются автоматически при покупке.
- **Дата платежа** — по умолчанию текущий момент.
- **Статус** — по умолчанию «Оплачено».
- **ID транзакции** — номер из банка/примечание.
- **Месяц начисления ЗП (override)** — необязательное поле: перекрывает авто-раскладку зарплаты преподавателя по месяцам (вся сумма уйдет в выбранный месяц). Пусто = авто-расчет по периодам блоков.

> **Важно про доступ:** при статусе «Оплачено» система сама открывает студенту соответствующие уроки. Тариф «полблока» (`Блок N — 1-я/2-я половина`) открывает только уроки своей половины.

### 2.4. Редактирование и удаление

- **Редактировать** — иконка-карандаш в строке.
- **Удалить** — массовое удаление через выбор строк (галочки) → действие «Удалить».

### 2.5. Импорт оплат из файла

Кнопка **«Импорт оплат»** (вверху). Позволяет загрузить **CSV или XLSX** и массово завести оплаты:

1. **Шаг 1:** выбрать курс и загрузить файл.
2. **Шаг 2:** сопоставить колонки файла с полями: Студент, Сумма, Дата, Блок «с», Блок «по», Тариф, Примечание. Указать, **по какому полю искать студента** (ФИО / email / телефон).
3. Нажать «Импортировать».

После импорта появится сводка: сколько вставлено, сколько дубликатов, по скольким строкам **студент не найден** (со списком), сколько расходов пропущено.

> Дубликаты и отрицательные суммы обрабатываются автоматически; не найденных студентов нужно завести/проверить и импортировать повторно.

## 3. Раздел «Зарплаты» (преподавателей)

Дашборд по зарплатам преподавателей. Сверху — **виджет с итоговой суммой** за выбранный период.

### 3.1. Таблица

По каждому преподавателю:

- **Курсов** — сколько курсов ведет;
- **Начислено за месяц** — заработано за выбранный период;
- **Возвраты за месяц** — красным, с подсказкой «из чего минус» (наведите курсор);
- **Начислено всего / Выплачено всего** — накопительно (скрытые колонки, включаются тумблером);
- **К выплате** — текущий остаток (желтый = есть долг перед преподавателем, зеленый = ноль);
- **Авансы (не зачтены)** — выданные деньги, еще не зачтенные в счет ЗП;
- **Дней без выплаты** — целое число дней с последней выплаты (regular + аванс); «—» если выплат еще не было; желтый = 14+ дней, красный = 30+ дней; наведите курсор — покажет дату и общую сумму выплат;
- **Месяц закрыт** — замок: закрыт ли период у преподавателя.

**Фильтр «Период»** — выбор месяца (по умолчанию текущий). Меняет колонки начислений/выплат.

### 3.2. Расчет выплаты по блоку

Кнопка **«Рассчитать выплату по блоку»** (вверху). Калькулятор:

1. Выбрать **преподавателя → курс → блок** (и при желании **группу**).
2. Система подставит **«Сумму за блок»** из фактической выручки группы за блок (можно поправить вручную). Ниже показывается период блока и какие оплаты в него вошли.
3. Указать **коэффициент** (например, 92% — минус ~8%) и **процент преподавателя** (из ставки курса).
4. При необходимости добавить **допзанятия** (кол-во × цена), **доплату** (фикс. добавка сверх формулы) и **удержание** (фикс. вычет — штраф/аванс/корректировка).
5. Поле **«Итог к выплате»** показывает формулу и результат вживую:
   `(база × коэф%) × процент% + допзанятия × коэф% + доплата − удержание`.
6. Тумблер **«Провести в Финансах»** (по умолчанию вкл.) — создаст в «Финансах» транзакцию-отток типа «Выплата ЗП» на этом курсе и блоке.
7. **«Записать выплату»** — сохранит выплату с подробной разбивкой.

### 3.3. Действия по строке преподавателя

Меню действий (троеточие/группа) у каждого преподавателя:

- **Разбивка** — модальное окно: из чего сложилось начисление за период (по курсам/блокам/оплатам).
- **Записать выплату** — провести обычную выплату. Поля: сумма (по умолчанию = остаток − непогашенный аванс), дата, период, курс (необязательно — зафиксирует снимок ставки), комментарий, тумблер **«Зачесть аванс»** (если есть невыданные авансы), тумблер «Провести в Финансах».
- **Выдать аванс** — выдать деньги авансом. Аванс уходит реальными деньгами (проводится в «Финансы»), но **висит как «не зачтен»**, пока его не зачтут при полной выплате.
- **Закрыть / Открыть месяц** — закрытие периода у преподавателя: после закрытия поздние оплаты/обещания/рассрочки за уже прошедшие блоки этого месяца **переносятся в ближайший открытый месяц** (чтобы не переписывать закрытый отчет).
- **Карточка преподавателя** — открыть профиль в новой вкладке.

### 3.4. Экспорт

Кнопка **«Экспорт»** — выгрузка сводки по зарплатам.

## 4. Раздел «История выплат»

Полный журнал всех выплат и авансов преподавателям (то, что создается из «Зарплат» или вручную).

### 4.1. Таблица

- **Преподаватель**, **Сумма**, **Тип** (Выплата / Аванс — с пометкой «зачтен … / не зачтен»), **Дата выплаты**, **Период**, **Курс**, **Схема (снимок)**, иконка **«Расчет по блоку»** (с подсказкой-разбивкой), **Комментарий**.

### 4.2. Фильтры

По преподавателю, по периоду (месяцу), по курсу.

### 4.3. Создание / редактирование выплаты вручную

Поля: преподаватель, сумма, дата, период, курс (необязательно — зафиксирует **снимок ставки**), схема оплаты (снимок), ставка (снимок), комментарий, тумблер **«Провести в Финансах»** (создаст/обновит отток в «Финансах»; выключение — убирает транзакцию из Финансов).

> **Снимок ставки** фиксируется на момент выплаты, чтобы последующая смена ставки курса не переписывала прошлые периоды.

### 4.4. Экспорт

Экспорт всех выплат (кнопка «Экспорт» вверху) или выбранных строк (массовое действие «Экспорт»).

## 4a. Авансы преподавателям (H222, добавлено в июне-июле 2026)

**Где:** дашборд «Зарплаты» (`/admin/teacher-salaries`) → меню действий по строке
преподавателя → **«Выдать аванс»**. **Доступ:** 🔴 только бухгалтер и супер-админ
(`RoleGate::accounting()`), как и весь раздел «Зарплаты».

- **Выдать аванс** — деньги уходят преподавателю реально (создается проводка в
  «Финансах», тип «Выплата ЗП»), но помечаются как **«не зачтен»**, пока не будут
  учтены в счет обычной выплаты.
- **Зачесть аванс** — при «Записать выплату» (обычную, не по блоку) или при расчете по
  блоку (§4b) появляется тумблер «Зачесть аванс», если у преподавателя есть
  непогашенные авансы. Итоговая сумма выплаты автоматически уменьшается на остаток
  непогашенного аванса.
- В таблице «Зарплаты» — колонка **«Авансы (не зачтены)»**; в «Истории выплат» строка
  аванса помечена типом **«Аванс»** с подсказкой «зачтен … / не зачтен».
- **Брони (депозиты) и пробные занятия теперь входят в базу начисления ЗП** — раньше
  эти тарифы могли выпадать из расчета выручки блока; теперь учитываются наравне с
  обычными оплатами.
- **Удержание (−)** — отдельное фиксированное поле в формуле начисления (штраф/
  корректировка), вычитается из итога как есть, без применения коэффициента/процента.

**Готча:** аванс — это реальный отток денег (проведен в «Финансах» в момент выдачи), а
не резерв. Если аванс выдан, но обычная выплата с зачетом так и не создана, деньги всё
равно списаны с кассы — контролируйте список «не зачтенных» авансов регулярно.

## 4b. Прямые платежи преподавателю — зачет в калькуляторе (H… #270, слои 1–4)

**Где:** тот же калькулятор **«Рассчитать выплату по блоку»**, блок
«Прямые платежи преподавателю (зачет)». **Доступ:** 🔴 только бухгалтер и супер-админ.
**Полная техническая спецификация:** [`direct-teacher-receipts.md`](direct-teacher-receipts.md).

Иногда студент платит **напрямую на личный (зарубежный) счет преподавателя**, минуя
кассу школы — например, через PayPal или банковский перевод постороннему лицу.
Такой платеж заводится в «Финансах» с пометкой «получено преподавателем лично»
(поле `received_account`), а система:

1. **Исключает его из выручки курса** — иначе преподаватель получил бы свой процент
   еще раз сверху той суммы, которую уже держит на руках (двойной счет).
2. **Предлагает его к зачету** в калькуляторе выплаты — построчный список еще не
   зачтенных прямых платежей (дата, плательщик, курс, студент), **по умолчанию все
   выбраны** (снимите галку у ненужных).
3. **Вычитает по номиналу** в валюте выплаты преподавателя (через курс на дату
   выплаты) — не по курсу поступления, а по курсу, введенному в самой выплате.

**Учет зачтенного:** после того как выплата с зачетом сохранена, эти платежи больше
не появляются в списке «доступных к зачету» — снимок хранится в
`TeacherPayout.breakdown.direct_receipts`. Удаление выплаты возвращает эти платежи
обратно в пул («освобождает» их для следующего зачета).

**Готча (по коду `direct-teacher-receipts.md`, «следствие принятой модели»):**
исключение из выручки + зачет по номиналу означает, что **школа не берет свою долю** с
денег, собранных преподавателем напрямую — преподаватель оставляет себе полную сумму.
Это осознанная договоренность, не баг, но сумма в «Финансах» и реальная выручка курса
по таким платежам расходятся — учитывайте это при сверке P&L (§4c).

## 4c. Финансовый штурвал — управленческие отчеты (H207, #311)

**Где:** `/admin/finance-cockpit` — пункт меню **«Финансовый штурвал»** (группа
«Финансы»). **Доступ:** 🟡 админ **или** бухгалтер (`RoleGate::finance()` —
`RoleGate::any(ADMIN, ACCOUNTANT)`, шире, чем «Зарплаты»/«Выплаты»: сюда проходит и
администратор-владелец, не только бухгалтер).

Управленческие отчеты «в стиле Нескучных финансов», считаются автоматически из живых
данных LMS (не требуют ручной выгрузки в Excel):

- **ОПиУ (P&L)** — отчет о прибылях и убытках за выбранный период (селектор месяца,
  последние 12 месяцев). Показывает выручку, расходы (включая раздел «Расходы»,
  §4d), зарплатный фонд, чистую прибыль и маржу.
- **ДДС** — движение денежных средств за период.
- **Баланс** — снимок текущего финансового состояния (не привязан к периоду).
- **Платежный календарь** — горизонт по умолчанию 30 дней (настраивается), какие
  поступления/выплаты ожидаются впереди.

**Готча:** «Финансовый штурвал» раскрывает чистую прибыль и маржу — это
управленческая, а не только кассовая информация; ruling MG (H116) — поэтому доступ
шире, чем к самим выплатам (`accounting()`), но всё равно закрыт от куратора/
преподавателя/менеджера.

## 4d. Расходы (opex) (H207)

**Где:** `/admin` → **Финансы → Расходы (opex)** (`ExpenseResource`).
**Доступ:** 🟡 админ или бухгалтер (`FinanceAccess` = `RoleGate::finance()`).

Ручной ввод операционных расходов, которых раньше не было в LMS: эквайринг, хостинг,
подрядчики, налоги. Это расходная часть ОПиУ (§4c), не пересекается с зарплатами и
маркетинговыми тратами (они учитываются отдельно).

Поля при создании: **Дата траты**, **Статья расхода** (справочник категорий),
**Сумма ₽**, **Контрагент** (необязательно), **Комментарий**. Таблица сортируется по
дате, есть фильтр по статье, итоговая сумма подсчитывается автоматически (Summarizer)
внизу колонки «Сумма».

## 4e. Планирование — шаблоны (H207)

**Где:** `/admin/finance-planning` — пункт меню **«Планирование (шаблоны)»**.
**Доступ:** 🟡 админ или бухгалтер (`RoleGate::finance()`).

То, что нельзя автоматически посчитать из данных LMS (сценарное планирование,
бюджет, план доходов/расходов), остается ручными Excel-книгами «Нескучных финансов» —
этот раздел дает **ссылки на их скачивание**, три шаблона:

| Шаблон | Назначение |
|---|---|
| **Финансовая модель** | сценарное планирование (unit-экономика, драйверы роста) — слишком forward-looking для авто-расчета |
| **Бюджет** | плановый бюджет по периодам — кандидат на план-факт против живого ОПиУ |
| **План доходов и расходов** | ближе к строкам ОПиУ — второй кандидат на план-факт |

**Готча:** это статичные шаблоны для скачивания, не интерактивные формы — раздел не
считает план-факт автоматически (пока не выбран канонический источник плана).

## 4f. Пометка платежей со скидкой + типо-зависимая скидка (H…)

**Где:** таблица «Финансы» — бейдж скидки в колонке «Сумма» (`-10%` или `-1000 ₽`);
также отражается в выгрузке Google Sheet. **Доступ:** обычный доступ к «Финансам»
(бухгалтер/супер-админ).

- Платежи со скидкой помечены визуально в админке и в синхронизируемой Google Sheet —
  раньше скидка была видна только в сумме, без явного маркера «это была скидка».
  Поддерживает и процентную, и рублевую скидку — показывается тот тип, который
  реально применялся к этому платежу (не всегда пересчитывается в «эквивалент
  процента»).
- **Поблочные персональные скидки** — скидка теперь может быть привязана к
  конкретному студенту и конкретному блоку (а не только к тарифу/промокоду целиком).
- **Называть реальный источник снижения цены, а не всегда «скидку»** — если цена ниже
  из-за иной причины (например, зачет блоков в полный курс), в интерфейсе это не
  подписывается словом «скидка», чтобы не путать бухгалтера при сверке причин
  расхождения цены.
- **Промокод, привязанный к курсу + ограничение «один раз на человека»** — колонка
  «Промокод» (скрытая по умолчанию, включается тумблером колонок) показывает, какой
  промокод применен; система не даст одному студенту применить один и тот же промокод
  дважды.

## 4g. Аудит-лог операций с платежами (H…) — «Журнал финансов»

**Где:** `/admin` → **Продажи → Журнал финансов** (`PaymentAuditResource`).
**Доступ:** 🔴 **только супер-админ** (`RoleGate::isSuperAdmin()`) — бухгалтер этот
раздел **не видит**, хотя работает с самими платежами. Это неизменяемый (append-only)
журнал: создавать/редактировать/удалять записи через UI нельзя ни одной роли.

Каждая строка — кто (`admin_name` + email), когда, какое действие (Создание/
Изменение/Удаление, цветной бейдж), с каким платежом (`#id` + имя студента) и на какую
сумму (отрицательная — красным). Колонка «Изменения» — человекочитаемое резюме, что
именно поменялось. Фильтры: по действию, по админу, по периоду дат.

**Синк нулевых оплат:** в рамках того же слоя платежи с нулевой суммой (льготный
доступ без денег) тоже синхронизируются в аудит-лог — раньше могли выпадать из
трейла как «неинтересные».

**Готча — почему это важно для бухгалтера, даже без доступа:** если сумма в
«Финансах» разошлась с ожиданиями и не находится объяснение, попросите **супер-админа**
(не администратора — у него тоже нет доступа к этому журналу) поднять аудит-лог по
конкретному платежу — там будет видно, кто и когда его правил.

## 4h. Справочная сумма в валюте (USD/EUR) для отчета

**Где:** «Финансы» и отчет по выплате — дополнительное справочное поле суммы в
валюте, отдельно от расчетной конвертации PayPal (§3.2 калькулятора).
**Готча:** это справочное значение для отчетности, не пересчитывается автоматически
при смене курса задним числом — если нужна точная конвертация на конкретную дату,
используйте поле «Курс на дату» в калькуляторе выплаты (§3.2), а не это справочное.

## 4i. Дашборд «Участники по блокам» — кто какой блок оплатил

**Где:** `/admin` → отчет **«Участники по блокам»** (`CourseBlockParticipants`).
**Доступ:** 🔴 бухгалтер и супер-админ (`RoleGate::accounting()`). С 18-08-2026 этот
дашборд **видит именно бухгалтер**, а обычный администратор его больше не видит:
экран стоит рядом с «Потоками курса» (§4k), где показано вознаграждение
преподавателя, и оба закрыты одним и тем же гейтом.

Сводная таблица: по каждому студенту курса — какие блоки оплачены, какие нет, единым
взглядом по всей группе/курсу, без необходимости открывать карточку каждого студента.

## 4k. «Потоки курса» — потоки одной программы бок о бок

**Где:** «Финансы» → **«Потоки курса»** (`CourseStreamComparison`).
**Доступ:** 🔴 бухгалтер и супер-админ (`RoleGate::accounting()`).

Экран отвечает на вопрос «стоит ли объявлять следующий поток и остались ли мы что-то
должны преподавателю». Выбираете семью потоков — рядом встают все потоки одной
программы: ученики по блокам и удержание, деньги, начислено/выплачено/остаток,
пересечение потоков и поимённый отток. Кнопка **«Экспорт в Excel»** выгружает то же
самое строкой на студента.

Экран **только читает**: он ничего не начисляет и не выплачивает.

Три вещи, которые важно понимать, глядя на цифры:

1. **«Чел.» у блока** — сколько человек купили именно этот блок; это то же
   определение, что у выручки блока. Приписка «доступ у N» появляется, когда
   у блока есть ещё и купившие курс целиком: отдельно за блок они не платили.
2. **Плашка покрытия** над оттоком говорит, по скольким людям вообще есть данные
   о посещаемости. Пустая клетка означает «не собрано», а не «не ходил».
3. **Слово «предварительно» у остатка** значит, что часть платежей-«Расходов» по
   этим курсам не размечена: из данных они неотличимы от аренды или рекламы.
   Пока человек их не подтвердит, остаток — не готовый ответ. Разметка
   подтверждается в разделе **«Подтверждение выплат преподавателям»** (см. § 4l ниже); ссылка на него
   есть прямо в жёлтой плашке под остатком.

Кнопка **«Акт сверки (PDF)»** печатает одну страницу по преподавателю выбранной
семьи: по каждому потоку выручка → ставка → начислено, отдельной строкой записи
прошлого потока, ниже выплачено и остаток. Внизу — **пустая строка «решение о
доплате сверх остатка»**: если школа доплачивает сверх расчёта, это решение
человека, и оно вписывается от руки, а не подмешивается в арифметику. Пока остаток
предварительный, акт печатает это словом.

Пошаговая памятка на одну страницу: [`MANUAL_ACCOUNTANT_COURSE_STREAMS_RU.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/MANUAL_ACCOUNTANT_COURSE_STREAMS_RU.md).

Семья потоков проставляется в карточке курса, поле **«Семья потоков»**; заполненное
вручную значение автоопределение никогда не перетирает.

## 4l. «Подтверждение выплат преподавателям» — какой «Расход» был выплатой преподавателю (H3084)

**Где:** «Финансы» → **«Подтверждение выплат преподавателям»**
(`TeacherPayoutAttributionSuggestionResource`). В меню рядом с пунктом стоит счётчик
неразобранных строк.
**Доступ:** 🔴 бухгалтер и супер-админ (`RoleGate::accounting()`).

Часть выплат преподавателям исторически проводилась не через «Историю выплат», а
платежом с тарифом **«Расход»** на служебного пользователя. Из данных такой платёж
неотличим от аренды зала или рекламы — поэтому система не решает за вас, а
складывает кандидатов в эту очередь.

По каждой строке видно: номер платежа, дату, сумму, курс, преподавателя,
уверенность и **основание** — почему система вообще сочла платёж выплатой.

Две кнопки:

- **«Это выплата»** — сумма входит в «выплачено» на экране «Потоки курса», и
  остаток по преподавателю становится на неё меньше.
- **«Не выплата»** — платёж остаётся расходом и в сверку выплат не попадает.
  Вопрос закрыт: строка перестаёт держать пометку «предварительно».

Ошиблись — **«Вернуть в очередь»** возвращает строку в исходное состояние.

Три вещи, которые важно понимать:

1. **Подтверждение НЕ создаёт строку в «Истории выплат».** Оно меняет только
   разметку. Если платёж нужно ещё и провести по реестру выплат — это отдельное
   действие, которое вы делаете руками в разделе «История выплат».
2. **Платежи, заведённые прямо на личного пользователя преподавателя, в очередь
   не попадают** — они и так считаются выплатой. Подтверждать их ещё раз не надо
   и не получится: система такие строки не предлагает, чтобы одна и та же сумма
   не была учтена дважды.
3. **Очередь наполняет команда** `salary:detect-payout-attributions` (запускает
   администратор). Сама она ничего не подтверждает — все строки приходят в статусе
   «Ожидает».

## 4j. Ведомость ЗП преподавателей / фикс-vs-процент what-if

**Где:** «Зарплаты» → кнопка **«Экспорт»** (ведомость, `TeacherSalariesExporter`) и
блок **«Что было бы при проценте»** в калькуляторе выплаты по блоку (виден только для
фикс-моделей ЗП: «за студента» / «за блок» / «за курс»).
**Доступ:** 🔴 только бухгалтер и супер-админ.

What-if-сравнение показывает, сколько преподаватель получил бы, если бы его
фиксированная ставка была процентом от выручки блока — помогает решить, не пора ли
пересмотреть схему оплаты конкретного преподавателя. Разница показывается со знаком:
«процент дороже школе на …» или «фикс дешевле школе на …».

**Готча:** сравнение считает только «схемную» часть (без допзанятий/доплат/удержаний —
они одинаковы в обоих сценариях и сокращаются в разнице) — не путать с итоговой суммой
выплаты.

## 4k. Два преподавателя на курсе — у каждого свои условия ЗП

**Где:** карточка курса (`CourseResource`) — со-преподаватель добавляется отдельно от
основного, с собственной схемой/ставкой ЗП (pivot `course_teacher`), не наследует
условия основного преподавателя.
**Доступ к настройке условий на курсе:** обычный доступ к `CourseResource`; расчет
выплаты со-преподавателю в калькуляторе — доступ 🔴 бухгалтер/супер-админ, как обычно.

В калькуляторе выплаты по блоку (§3.2 выше) при выборе со-преподавателя подтягиваются
именно его условия, а не условия основного преподавателя курса — проверяйте, кого
именно выбрали в поле «Преподаватель», если на курсе их двое.

## 6. Частые сценарии (cookbook)

**Завести оплату студента вручную**
Финансы → «Создать» → выбрать студента, курс, тариф (весь курс / блок / полблока), сумму, статус «Оплачено» → Сохранить. Доступ откроется автоматически.

**Массово загрузить оплаты за месяц**
Финансы → «Импорт оплат» → выбрать курс и файл → сопоставить колонки → «Импортировать» → проверить сводку и список «студент не найден».

**Провести возврат**
Финансы → «Создать» → тариф «💸 Системный расход / Возврат», сумма со знаком **минус** → Сохранить.

**Рассчитать и выплатить ЗП преподавателю за блок**
Зарплаты → «Рассчитать выплату по блоку» → преподаватель/курс/блок/группа → проверить базу, коэффициент, процент → «Записать выплату» (галка «Провести в Финансах» вкл.).

**Выдать аванс и потом его зачесть**
Зарплаты → у преподавателя «Выдать аванс» → сумма. Позже при «Записать выплату» включить тумблер **«Зачесть аванс»** — аванс пометится зачтенным, а сумма выплаты будет доплатой (остаток за вычетом аванса).

**Закрыть месяц по преподавателю**
Зарплаты → выбрать период в фильтре → у преподавателя «Закрыть <месяц>». Поздние начисления за прошедшие блоки уйдут в ближайший открытый месяц.

**Выгрузить выплаты для отчета**
История выплат → отфильтровать по периоду/преподавателю → «Экспорт».

## 7. Глоссарий

- **Транзакция** — любая денежная запись в «Финансах» (оплата, бронь, расход, выплата ЗП).
- **Тариф / ключ доступа** — что открывает оплата: `весь курс`, `блок N`, `полблока (block_N — 1-я/2-я половина)`, `бронь`, `пробное`, `расход`, `выплата ЗП`.
- **Бронь (депозит)** — предоплата, которая позже зачитывается в полную стоимость курса.
- **Блок** — раздел курса из 4 занятий; может продаваться целиком или по половинам.
- **Коэффициент** — поправочный множитель к базе при расчете ЗП (например, 92% ≈ минус 8%).
- **Снимок ставки** — зафиксированная на момент выплаты схема/процент преподавателя; защищает прошлые периоды от пересчета при смене ставки курса.
- **Аванс** — деньги, выданные преподавателю заранее; «не зачтен», пока не учтен при полной выплате.
- **Закрытый месяц** — период, в который новые начисления уже не попадают (переносятся в ближайший открытый).
- **«Провести в Финансах»** — создать в разделе «Финансы» транзакцию-отток типа «Выплата ЗП», чтобы выплата отражалась в общем учете.

- **Прямой платеж преподавателю** — оплата, пришедшая на личный счет преподавателя, минуя кассу (§4b); исключается из выручки курса и зачитывается в выплату по номиналу.
- **Финансовый штурвал** — управленческие отчеты ОПиУ/ДДС/Баланс/платежный календарь, считаются из живых данных LMS (§4c).
- **Opex (Расходы)** — операционные расходы бизнеса вне зарплат и маркетинга: эквайринг, хостинг, подрядчики, налоги (§4d).
