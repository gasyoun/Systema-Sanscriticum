## 2. Контрольная команда (воспроизведение ключевых чисел)

Команда на .92 (агрегаты, без PII):

```sql
mysql laravel -e "
-- Q1 выручка/возвраты 12м
SELECT ROUND(SUM(amount),0) revenue_net, SUM(amount<0) refund_cnt, COUNT(*) pay_cnt, COUNT(DISTINCT user_id) payers
FROM payments WHERE status IN ('paid','success') AND is_conditional=0 AND user_id IS NOT NULL
AND tariff NOT IN ('Расход','salary_payout') AND created_at >= DATE_SUB(NOW(), INTERVAL 12 MONTH);
-- Q2 повторные vs первые
SELECT ROUND(SUM(CASE WHEN ord=1 THEN amount ELSE 0 END),0) first_pay_rev,
       ROUND(SUM(CASE WHEN ord>1 THEN amount ELSE 0 END),0) repeat_rev
FROM (SELECT amount, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY id) ord FROM payments
WHERE status IN ('paid','success') AND is_conditional=0 AND user_id IS NOT NULL
AND tariff NOT IN ('Расход','salary_payout') AND created_at >= DATE_SUB(NOW(), INTERVAL 12 MONTH)) t;
-- Q3 выплаты преподавателям 12м по месяцам
SELECT DATE_FORMAT(paid_at,'%Y-%m') m, ROUND(SUM(amount),0) payouts FROM teacher_payouts
WHERE paid_at >= DATE_SUB(CURDATE(), INTERVAL 12 MONTH) GROUP BY m ORDER BY m;
-- Q4 выручка по месяцам
SELECT DATE_FORMAT(created_at,'%Y-%m') m, ROUND(SUM(amount),0) rev FROM payments
WHERE status IN ('paid','success') AND is_conditional=0 AND user_id IS NOT NULL
AND tariff NOT IN ('Расход','salary_payout') AND created_at >= DATE_SUB(NOW(), INTERVAL 12 MONTH) GROUP BY m ORDER BY m;
"
```

## 3. Вердикт

**300–700 тыс. без найма: 300 тыс. — выводится, и только рычагом заполненности: довести новые потоки с 7–11 до ≥30 учеников в уже запланированные 90–130 ч расписания (×1,6–2,0 к выручке июля–сентября: 613 → ~1,0–1,2 млн/мес; нетто ≈ 113 тыс./мес с потока при ставке 30 %), при обязательном удержании повторной базы (83,6 % выручки) и при условии, что прочие расходы + резерв под неоказанные услуги не превысят ~300–380 тыс./мес; 700 тыс. — не выводится: потолок нормативной заполненности ×2,0 и запрет ценового рычага (премортем) не дают требуемых ×2,3 к выручке.**

Формула: `Прибыль_мес ≈ Выручка_мес × (1 − доля_преподавателей) − Прочие_расходы − Резерв_под_неоказанные`.

Рычаги, по данным:

1. **Заполненность** — единственный количественный рычаг: 23–33 % нормы сейчас → ×1,6–2,0 к выручке при нулевом приросте часов (расписания уже существуют). Факт записи рычаг сегодня не подтверждает — сигнал премортема («два потока подряд ниже 60–70 % нормы») уже сработал.
2. **Повторные покупки** — 83,6 % выручки; это условие выживания модели, а не рычаг роста; потеря базы обнуляет арифметику.
3. **Цена** — не рычаг: премортем прямо фиксирует, что рост ценой сжимает средний сегмент, заполняющий группы.
4. **Возвраты** — 0 ₽ за 12 мес, рычага нет.
5. **Часы преподавателя** — растут как % выручки (20–60 % на новых потоках против блендед 13,5 % за 12 мес): маржа масштабируется медленнее выручки, но часы фиксированы расписанием.

Сверка якорей H6215: заполненность 60–70 % нормы — **провалена** (23–33 %, два+ потока подряд); доля топ-5 плательщиков >40 % — **не сработала** (0,2 %, база широкая, 475 плативших).

## 4. Ограничения и источники вне БД

- **Выручка в таблице — кассовая** (по дате платежа), не начисленная по оказанию: мартовские предоплаты длинных пакетов уже сидят в цифрах 12 мес, а обязательства по ним продолжают оказываться. Начисленная (accrual) прибыль из ledger без данных о сроках пакетов не выводится.
- **Служебные списания `Расход`** (все от служебного аккаунта школы, помесячно: 9 340 968 ₽ за 12 мес, крупнейшие −481 000/−432 329/−386 773) исключены из выручки по семантике H256 и в арифметику вердикта не входят; их фактический состав (вывод прибыли vs прочие переводы) из БД не определяется.
- Прочие расходы (маркетинг, хостинг, ops-контракты) и резерв под неоказанные услуги — вне БД, в вердикте отмечены как условие (не более ~300–380 тыс./мес для цели 300 тыс.), не измерены этим документом.
- Ставки преподавателей — из payout-записей (факт: 20/30/60 %), часы — из расписаний (факт: план/факт по `schedules`), не из оценок.
