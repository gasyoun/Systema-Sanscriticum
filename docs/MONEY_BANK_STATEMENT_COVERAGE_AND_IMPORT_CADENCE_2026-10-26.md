## 1. Что считается покрытием

1. Покрытие берётся **только** из `bank_statement_imports.covers_from` / `covers_to` — периода, который **назвал человек** при импорте.
2. Даты строк выписки покрытием не являются. Иначе день без зачислений выглядел бы непокрытым, а одна строка делала бы покрытым весь день.
3. День покрыт, только если **один** импорт покрывает его **целиком** (00:00:00…23:59:59). Частичный период (например, до 11:59:59) — **не** покрытие; сверка в этом случае честно держит источник `missing`.
4. Отчёт покрытия — **только чтение**: не пишет ни в деньги, ни в доступ, ни в таблицы сверки, ни во флаги. Прогон на проде 26-10-2026: `db_writes=0`.

## 3. Как воспроизвести

```bash
php artisan money:statement-coverage --from=2026-08-01 --to=2026-10-25
php artisan money:statement-coverage --from=2026-08-01 --to=2026-10-25 --json=/tmp/coverage.json
php artisan money:statement-coverage            # окно: первый импорт … вчера
```

Команда печатает таблицу импортов, таблицу месяцев (покрытые и непокрытые дни диапазонами), итог и предупреждение, если флаг `MONEY_BANK_STATEMENT_CREDITS` выключен (тогда покрытые дни всё равно останутся `missing` для сверки). `--json` пишет только файл, названный человеком.

Пин: `tests/Feature/Reconciliation/BankStatementCoverageTest.php` — покрытие месяца, частичный день, строка вне периода, закрытие разрыва новым импортом, отсутствие записей в базу (`DB::listen`, `db_writes=0`), окно по умолчанию.

## 4. Ритм выгрузки — закреплено: Мария, бухгалтер

Тот же ответственный, что за ввод расходов (решение MG 31-07-2026, [issue #953](https://github.com/gasyoun/Systema-Sanscriticum/issues/953); см. [FINANCE_REVIEW_RHYTHM.md](FINANCE_REVIEW_RHYTHM.md) § «Ввод расходов (opex)»). Полное имя в публичном репозитории не дублируется — правило приватности из [DECISIONS_MONEY_LEDGER_AND_RECONCILIATION_2026.md](DECISIONS_MONEY_LEDGER_AND_RECONCILIATION_2026.md).

| Когда | Что выгружается | Кто |
|---|---|---|
| Не позднее **3-го рабочего дня** месяца, следующего за отчётным | Выписка Точки за **весь прошлый календарный месяц** (01…последнее число) | Мария, бухгалтер |
| Если срок пропущен — до **10-го рабочего дня** | То же, догоняющим импортом | Мария, бухгалтер |
| По запросу | После смены тарифа Точки/эквайринга, после расхождения дневного контроля, при разборе крупного поступления | Мария, бухгалтер → собственник |
| Если Мария недоступна > 2 рабочих дней | Выгрузку делает владелец счёта, период подтверждает Мария | собственник |

**Правило периода.** Период называет человек, который делал выгрузку: «за август» = `--from=2026-08-01 --to=2026-08-31`. Выводить период из строк файла запрещено — это ломает и покрытие, и дневной контроль.

**Правило исполнения.** Импорт запускает человек с доступом на хост (ops/собственник), не агент и не расписание. Планового автоматического подтягивания выписки нет и в этом юните не заводится.

## 5. Процедура: выгрузка → сухой прогон → импорт → проверка

1. **Выгрузка.** Мария выгружает CSV за названный период и кладёт на хост:
   `/var/www/html/storage/app/statements/Tochka_YYYY-MM.csv` (каталог задаётся `MONEY_RECON_BANK_STATEMENT_DIR`). В сообщении ops — имя файла и период словами: «за август 2026, 01–31».
2. **Сухой прогон** (ничего не пишет):
   ```bash
   php artisan money:import-statement-credits /var/www/html/storage/app/statements/Tochka_2026-10.csv \
       --from=2026-10-01 --to=2026-10-31 --dry-run
   ```
   Проверить: `период покрытия` совпадает с выгрузкой в кабинете Точки; `не разобрано: 0`; число строк и сумма выглядят правдоподобно. Ненулевое `не разобрано` — файл не тот (другой банк/формат), импорт не запускать.
3. **Импорт** — та же команда без `--dry-run`. Идемпотентность двойная: тот же файл (sha256) вернёт `already_imported` и ничего не запишет; те же строки в другом файле пропустятся как дубли. Пишутся только `bank_statement_imports` / `bank_statement_credits` (append-only); платежи, доступ и флаги не трогаются.
4. **Проверка покрытия** — покрытые дни должны перейти из «нет» в «покрыто», разрыв сократиться:
   ```bash
   php artisan money:statement-coverage --from=2026-09-01 --to=2026-10-31
   ```
5. **Проверка сверки** — прогон за покрытый день без записи:
   ```bash
   php artisan money:reconcile-daily --date=2026-10-15 --json=/tmp/recon.json
   ```
   В `sources.bank_statement.status` — `present`; `missing_sources` больше не называет `bank_statement`; `db_writes` остаётся 0. Расхождения дня, если они есть, появятся как типизированные исключения — их разбирает человек, сверка ничего не чинит.
6. **Ничего не откатывать.** Таблицы append-only: ошибочный период нельзя исправить UPDATE/DELETE. Единственное лечение — импортировать правильный файл; ошибочный импорт остаётся в истории, и покрытие станет объединением периодов. Поэтому шаг 2 обязателен, а период сверяется с кабинетом Точки до импорта.
