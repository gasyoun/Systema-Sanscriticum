# UX-аудит публичной витрины и продающих страниц курсов — Systema Sanscriticum

_Created: 07-07-2026 · Last updated: 07-07-2026_

Документ фиксирует UX-аудит публичного каталога (`/online`, `resources/views/shop/index.blade.php`
+ `Livewire\Shop\CourseCatalog`) и продающей страницы курса (`shop.course.show`,
`resources/views/shop/show.blade.php`) — точку входа холодного трафика, в отличие от
[`docs/STUDENT_CABINET_UX_AUDIT_2026.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/STUDENT_CABINET_UX_AUDIT_2026.md),
который разбирает уже вошедшего студента. Желаемое продуктовое ощущение — редакционный каталог в
духе Arzamas / Synchronization, а не типовая ecommerce-сетка, при сохранении понятного пути к оплате.

Аудит опирается на факт: [`docs/course-landing-spec.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/course-landing-spec.md)
(04-07-2026) в основном уже реализована — `shop.show.blade.php` содержит все спроектированные блоки
(`audience`, `outcomes`, `sample`, `teachers`, `testimonials`, `faq`, `tech-payment`, `final-cta`,
trust-strip, JSON-LD `Course`/`Offer` схема). Этот аудит не повторяет уже закрытые пункты спеки, а
разбирает то, что спека не покрывала: витрину, каталог, editorial-ощущение и несколько сквозных
несостыковок, найденных при чтении фактического кода.

## 1. North star для публичной витрины

Холодный посетитель за первые 10–15 секунд на `/online` должен понять:

1. это редакционная школа санскрита с преподавателями и традицией, а не безликий маркетплейс курсов;
2. живое сейчас vs доступное в записи — очевидно на уровне секции, а не бейджа, который нужно
   рассмотреть;
2. какой курс подходит новичку, практику йоги, филологу — без чтения всех карточек подряд;
4. что будет после оплаты — простой шаг за шагом, без страха «а вдруг сломается доступ»;
5. записи прошлых курсов — это открытая библиотека, а не «то, что осталось» после эфира.

## 2. Текущий путь холодного посетителя

Фактический путь по коду (`routes` → `ShopController::index` → `shop.index` →
`Livewire\Shop\CourseCatalog` → `course-card.blade.php` → `ShopController::show` → `shop.show`):

```text
/online
  -> поиск + чипы формата/категории/преподавателя (Livewire, живой)
  -> сетка карточек (сгруппировано: Идут сейчас / В записи / Другие курсы)
  -> карточка курса -> страница курса (shop.course.show)
  -> hero -> микродоверие -> для кого -> чему научитесь -> о курсе -> программа
  -> пример урока -> преподаватель(и) -> расписание -> тарифы -> отзывы -> FAQ
  -> техтребования/оплата -> финальный CTA -> checkout.show
```

### Что уже сильное

- **Каталог — не голая сетка.** Секционная группировка `Идут сейчас / В записи / Другие курсы`
  ([course-catalog.blade.php:165-195](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/livewire/shop/course-catalog.blade.php#L165-L195))
  уже даёт первый уровень редакционной структуры, а не плоский grid.
- **Типографская обложка-фолбэк** для курсов без фото
  ([course-card.blade.php:26-45](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/components/shop/course-card.blade.php#L26-L45))
  — цвет категории + имя преподавателя + название, а не generic placeholder-картинка. Это уже
  ближе к editorial, чем к обычному ecommerce.
- **Страница курса — почти полностью соответствует `course-landing-spec.md`**: hero с двойным CTA
  (тариф / пробный урок), микродоверие, «для кого», «чему научитесь», программа-аккордеон, пример
  урока (гейт-плеер `is_preview`), преподаватель(и), расписание живых занятий, тарифы с вкладками
  «весь курс / по модулям», отзывы, FAQ, техтребования+оплата, финальный CTA. JSON-LD `Course` +
  `Offer` схема для Яндекса/Google уже на месте
  ([show.blade.php:7-77](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/show.blade.php#L7-L77)).
- **Graceful degradation работает** — каждый новый блок (`audience`, `outcomes`, `testimonials`,
  `course_faqs`) скрывается при пустых данных, как и требовала спека
  ([audience.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/partials/audience.blade.php),
  [testimonials.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/partials/testimonials.blade.php)).

### Главная слабость

Спека закрыла *структуру* страницы курса, но не решила два продуктовых вопроса, которые
`vitrina.md` прямо назвал критическими: **доверие/непротиворечивость сигналов** и **автоматизация
пути после оплаты**. Ниже — конкретные находки по экрану.

## 3. Экранный аудит

### 3.1. Каталог (`/online`)

Проблема: карточка курса (`course-card.blade.php`) показывает цену, формат, бейдж «Новинка» и
кнопку «Выбрать тариф» — уже структурно близко к ecommerce-карточке. Для editorial-ощущения не
хватает **редакционного слоя над сеткой**: у Arzamas/Synchronization первый экран — не список
товаров, а несколько кураторских «полок» (по интересу, по уровню, по формату), и только затем
сетка. Сейчас единственная кураторская метка — чип категории; нет вводного текста/подборки
«с чего начать», «для практиков йоги», «для филологов» над самим списком.

Рекомендация:
- добавить редакционный вводный блок над сеткой (1-2 короткие подборки/траектории — «С нуля»,
  «Для йоги и мантр», «Академическая грамматика» — echo идеи из [`vitrina.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/vitrina.md)
  §«Предлагаемая карта сайта»), не меняя сам движок Livewire-фильтра;
- используя уже существующие `categories`/`icon`/`color`, отрендерить 3-5 кураторских «входов»
  как крупные плитки поверх обычной сетки, кликающих `toggleCategory()` — почти без нового кода.

Acceptance:
- новый посетитель видит хотя бы одну кураторскую точку входа до того, как долистает до карточек;
- существующий фильтр (`search`, `format`, `teacherId`, `categoryIds`) не меняется, только новый
  визуальный слой сверху.

### 3.2. Course page — «Пример урока» и «Преподаватель(и)»

Прочитаны [`sample.blade.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/partials/sample.blade.php)
и [`teachers.blade.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/partials/teachers.blade.php)
по факту скрываются, если у курса нет `previewLesson` или заполненного `teacher.bio`/`photo_path`
— то есть **эти блоки будут пустыми/отсутствующими у большинства текущих курсов**, пока редактор
не заполнит данные вручную через Filament. Спека это предвидела («Раскатка и данные»: «новые
поля/таблицы пустые → блоки скрыты, пока редактор не заполнит»), но сама раскатка контента —
отдельная работа, которую эта спека не делает и которую этот UX-аудит не может подтвердить или
опровергнуть без доступа к продакшен-БД (локально `database.sqlite` не сидирована этим репозиторием).

Рекомендация — не код, а human-процесс: до масштабирования на все курсы заполнить `audience`,
`outcomes`, `is_preview` и `teachers.photo_path` хотя бы для 3-5 флагманских курсов (эталон,
уже предложенный `course-landing-spec.md` §«Раскатка и данные»), иначе новые продающие блоки не
видны нигде на сайте несмотря на готовый код.

### 3.3. Доверие: противоречащие сигналы про доступ после оплаты (найдено при чтении кода)

Обнаружено прямое противоречие между двумя партиалами страницы курса:

- [`tech-payment.blade.php:25-33`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/partials/tech-payment.blade.php#L25-L33)
  — «Как проходит оплата» перечисляет шаг 3 буквально: **«Доступ к материалам открывается
  автоматически сразу после оплаты»**.
- [`resources/views/partials/guest-purchase-warning.blade.php:66-75`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/partials/guest-purchase-warning.blade.php#L66-L75)
  — прямо над блоком тарифов той же страницы, показан **каждому** незалогиненному посетителю
  (директива `@guest`, без проверки, покупал ли он раньше) яркий amber/red блок «Важно»: **«Если
  Вы раньше покупали наши курсы — не регистрируйтесь самостоятельно, напишите куратору»**.

Для нового, никогда не покупавшего посетителя (то есть для большей части холодного трафика) это
предупреждение нерелевантно, но визуально доминирует (`ring`, `shadow`, пульсирующая иконка,
`animate-pulse`) прямо перед кнопкой оплаты — создаёт необоснованную тревогу «что-то может
сломаться» ровно в точке принятия решения о покупке. Это именно тот конверсионный риск про
«несостыковку сигналов доверия», который `vitrina.md` §«Диагностика» описал как общую проблему
сайта (разные юрлица/цены на разных страницах) — здесь та же болезнь на уровне одного экрана.

Рекомендация:
- показывать warning-блок **только** гостю, у которого уже есть исторический платёж на этот email
  при попытке логина/чекаута (существующий поток восстановления доступа для legacy-базы), а не
  всем гостям без разбора — например, перенести формулировку с «страшного» amber-блока на шаг
  формы логина/чекаута («не находите свой email в системе — писать куратору»), а не на публичную
  страницу курса;
- либо, если решение — оставить предупреждение видимым всем (мера предосторожности для legacy),
  смягчить тон и визуальный вес до уровня обычной info-подсказки, а не alert с `animate-pulse`,
  чтобы не соперничать с основным CTA «Выбрать тариф».

Acceptance:
- новый посетитель не видит alert-уровня предупреждения о ручной регистрации, если он не
  идентифицирован как повторный покупатель;
- шаг «оплата → автоматический доступ» в `tech-payment.blade.php` перестаёт формально
  противоречить соседнему блоку на той же странице.

### 3.4. Ценовые якоря (сверка с `vitrina.md`)

`vitrina.md` §«Диагностика…» (04-07-2026) зафиксировал конкретный разрыв: на `samskrtam.ru/faq/`
цена «от 400 ₽ за блок», тогда как в каталоге `samskrte.ru` блоки стоят 3 000–6 000 ₽, а курсы
целиком — от 12 000 ₽. Это внешний (другой домен, `samskrtam.ru`) контент, не код этого
репозитория — данный аудит не может ни подтвердить, ни исправить его в рамках `shop/*.blade.php`.
Флагую как открытый межстраничный конфликт, не закрываемый локальными изменениями каталога/курса.

### 3.5. Мобильная читаемость каталога и курса (статический разбор, без реального рендера)

Прочитанный Blade использует адаптивные классы Tailwind последовательно
(`grid-cols-1 md:grid-cols-2 xl:grid-cols-3 2xl:grid-cols-4` в каталоге; `flex-col lg:flex-row` в
hero страницы курса; горизонтальный `snap-x` скролл для расписания), что на уровне разметки
корректно для мобильного. Однако:

- расписание ([show.blade.php:347](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/show.blade.php#L347))
  — карточка сессии `w-[340px] max-w-[85vw]` при горизонтальном свайпе не имеет видимого
  индикатора «есть ещё карточки» (скроллбар скрыт `[scrollbar-width:none]` в каталоге,
  здесь `[scrollbar-width:thin]`, но нет точек/стрелок) — на мобильном пользователь может не
  понять, что список прокручивается;
- фильтр-чипы каталога ([course-catalog.blade.php:115-148](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/livewire/shop/course-catalog.blade.php#L115-L148))
  прокручиваются горизонтально при переполнении — тот же паттерн, тот же риск потери discoverability
  на маленьком экране.

Это наблюдение по статическому коду, не по реальному скриншоту/Playwright-проходу (эта задача —
document-only, без запуска dev-сервера) — при следующей визуальной проверке (`blade-styling`
скилл с Playwright, уже упомянутый в `course-landing-spec.md`) стоит явно проверить, виден ли
пользователю сигнал «прокрутите вбок» на этих двух горизонтальных лентах.

## 4. Рекомендуемая IA (уточнение к уже реализованной структуре)

Спека `course-landing-spec.md` уже зафиксировала порядок секций страницы курса (§«Порядок
секций»). Для каталога дополнительно:

1. **Редакционный вход** (новый, §3.1) — 3-5 кураторских плиток/траекторий над сеткой.
2. **Живые курсы / Записи / Другое** — уже есть (секционная группировка).
3. **Библиотека записей** как отдельный явный режим — сейчас `format=recorded` это просто фильтр
   внутри одной той же сетки, а не отдельный визуальный «режим витрины». Разделение на два явных
   режима — рекомендация backlog, не срочный тикет (см. §5, Ticket 3).

## 5. Prioritized tickets

### Ticket 1 — Fix contradictory guest warning (`guest-purchase-warning.blade.php`)

Цель: убрать alert-уровня предупреждение о ручной регистрации с глаз нового, никогда не
покупавшего посетителя.

Acceptance:
- warning не показывается гостю без признака «уже покупал» (email lookup на форме логина/чекаута,
  а не на публичной странице курса) **или** визуально понижен до info-уровня без `animate-pulse`;
- `tech-payment.blade.php` шаг «доступ автоматически после оплаты» больше не выглядит
  противоречащим соседнему блоку.

### Ticket 2 — Editorial entry layer above the catalog grid

Цель: добавить кураторский слой (3-5 траекторий) над `Livewire\Shop\CourseCatalog`, не меняя
фильтр-движок.

Acceptance:
- посетитель видит хотя бы одну кураторскую подборку до сетки карточек;
- клик по плитке вызывает существующий `toggleCategory()`/`$set('format', …)`, без нового
  сервера/эндпоинта.

### Ticket 3 — Recorded library as an explicit browsing mode

Цель: сделать `format=recorded` не просто фильтром внутри общей сетки, а отдельно называемым
режимом витрины («Библиотека записей»), созвучно [`STUDENT_CABINET_UX_AUDIT_2026.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/STUDENT_CABINET_UX_AUDIT_2026.md)
Ticket 7 (готовность кабинета к продаже записей). Публичная и кабинетная стороны должны говорить
об этом режиме одним и тем же языком.

Acceptance:
- в каталоге есть явный вход «Библиотека записей», а не только чип формата;
- терминология («запись», «библиотека») совпадает между витриной и кабинетом.

### Ticket 4 — Mobile scroll-affordance on horizontal lists

Цель: дать визуальный намёк на горизонтальную прокрутку — расписание (§3.5) и фильтр-чипы.

Acceptance:
- на мобильном виден признак «есть что пролистать» (частично обрезанная следующая карточка,
  точки-индикатор или лёгкий градиент-fade по краю) на обоих горизонтальных списках;
- проверено реальным просмотром (Playwright/`blade-styling`), не только по коду.

### Ticket 5 — Content rollout for flagship courses (human/editorial task, not code)

Цель: заполнить `audience`, `outcomes`, `is_preview`, `teachers.photo_path`, `course_faqs`,
`testimonials` хотя бы для 3-5 флагманских курсов, чтобы уже написанные Blade-блоки (§3.2) стали
видимы. Это редакторская, не инженерная задача — Filament-интерфейс для этого уже существует
(`course-landing-spec.md` §«Filament»).

Acceptance:
- минимум 3 курса показывают все продающие блоки страницы одновременно (не только пустые
  fallback-состояния);
- визуально проверено на реальных данных (не по коду).

### Ticket 6 — Cross-domain price-anchor conflict (flag only, not this repo's fix)

Не тикет для `Systema-Sanscriticum` — это редакционный конфликт между `samskrtam.ru/faq/` (внешний
контент-сайт) и `samskrte.ru` (этот каталог). Флагуется здесь как известный, неразрешённый в
рамках этого репозитория пункт из `vitrina.md`; решение требует правки контента на `samskrtam.ru`,
вне этого кодового аудита.

## 6. Acceptance metrics (порядок — как в существующих аудитах кабинета)

| Метрика | Что измеряет | Цель |
|---|---|---|
| `course_page_ctr` (клик карточка → страница курса) | понятность/привлекательность карточки | растёт после Ticket 2 |
| `sample_lesson_play` | вовлечённость до оплаты | измеримо только после Ticket 5 (нужен `is_preview` контент) |
| `tariff_click` | понятность блока тарифов | базовая метрика для A/B по §«Что именно измерять» из `vitrina.md` |

| `recorded_library_entered` | использование записей как отдельного режима | появляется после Ticket 3 |

Эти события — target-список для последующей инструментации (по аналогии с

телеметрии в других репозиториях), не обязательная часть этого document-only PR.

## 7. Вне объёма этого аудита

- Правки к `samskrtam.ru` (другой домен/репозиторий) — включая ценовой якорь «от 400 ₽» (§3.4).
- Реальный screenshot/Playwright-проход (эта задача — document-only, без запуска dev-сервера или
  БД; наблюдения §3.5 и §3.2 основаны на статическом чтении Blade/спеки, а не на живом рендере).
- Изменение денежно-доступного ядра (`PaymentObserver::grantAccess()`, тарифная логика) —
  предупреждение в Ticket 1 меняет только видимость/текст, не логику доступа.

- Английская версия витрины.
