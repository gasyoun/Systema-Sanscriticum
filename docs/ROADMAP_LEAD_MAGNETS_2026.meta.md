## Known limitations / caveats

- **Scope is deliberately narrow:** acquisition lead magnets only. Content-ops inbox is owned by `ROADMAP_CONTENT_AI_2026_2027.md`; the general roadmap owns everything else. Do not treat this as the funnel-of-record below the capture step.
- **Staleness risk is high at §4:** the funnel bridge already moved once (Zoom webinar → 3-day marathon). The ladder diagram lags its own supersession note; any later ladder change will re-open the same drift.
- **The doc is a pointer, not a build spec** — every executable detail lives in H312–H315, which are archived. If those move or are rewritten, this roadmap's links rot silently.

## Intended use / known misuse

- **For:** orienting a new build session on why the four LMs exist, which data asset each consumes, and where the funnel ends; capturing MG's four rulings as the frozen decision record.
- **Misuse:** reading §4's ASCII ladder as the current funnel without the top supersession note (the Zoom step is dead); treating the LM table's handoff links as live task queue (they are archived build records, not open work); using it as the storefront/product-ladder config source (that lives Systema-side).

## Maintenance & sunset plan

- **Kept alive by:** whoever ships or re-scopes an LM build handoff bumps the matching §3 row and "Last updated" in the same pass. The marketing/custdev thread owns funnel-shape edits.
- **Archived/ended looks like:** all four LMs live in the RU storefront and the funnel is measured — at that point this roadmap becomes a historical record and should be marked superseded by the running funnel dashboard / custdev doc, not silently left as if still forward-looking.
