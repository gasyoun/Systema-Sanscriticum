**2. `knowledge_chunks` migration (dep: 1).** New migration under `database/migrations/` in the house naming style. Bind the driver in a service provider off the config value. Keep all three inside the existing FAQ namespace. **4. ## Cross-wave conventions

Every new environment key introduced in any `config/*.php` requires `php scripts/generate_env_inventory.php` in the **same** pass — a CI gate reddens `main` otherwise. Every feature flag added in `config/features.php` defaults off and is flipped only by a human after reading the relevant shadow report. Every new resolver, lane or report gets a feature test under `tests/Feature/Support/` running on SQLite in memory with `Carbon::setTestNow` pinning any time-dependent assertion; the existing doubles directory holds the fakes and should be extended rather than duplicated.

Run `./vendor/bin/pint` before each pull request and get one full green suite before each pull request. Money-touching work — wave 1 steps 3, 4 and 5 — follows `/money-pr-land`: a separate worktree, the flag off at land time, money tests run explicitly, and the no-auto-merge marker in the body. Every new Telegram send point claims through `App\Support\TelegramSendGuard` before writing anything outbound, per the 24-08-2026 incident fence. Only additive nullable columns may be added to `telegram_support_messages`. Changelog entries go through `changelog_queue/`, never by editing the assembled file directly. Scheduler registration for every new command is `app/Console/Kernel.php` — `routes/console.php` contains only the inspire closure on this app and is not a scheduling surface.
