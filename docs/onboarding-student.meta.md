## Предмет (Subject)

- **Документ:** [onboarding-student.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/onboarding-student.md)
- **Назначение:** источник правды для онбординга нового студента — как войти в кабинет, сдавать домашние задания и получать помощь; тот же текст показывается студенту в кабинете как приветственный чеклист.
- **Аудитория:** новый студент школы санскрита (нетехнический читатель), а не разработчик; вторично — куратор и поддержка, сверяющиеся с формулировками.
- **Формат / контракт:** простой Markdown без терминов разработки, дружелюбный тон; статусные таблицы (ДЗ, поиск в словаре) и чеклист первых шагов; один экран прочтения за раз.

## Известные ограничения / оговорки (Known limitations / caveats)

- Гайд описывает поведение кабинета словами; при расхождении с реальным UI источником правды становится кабинет, а гайд устаревает молча.
- Названия кнопок и статусов зафиксированы как строки — любой ребрендинг интерфейса требует ручной правки текста.
- Обещания по срокам («за минуты», «автоматически») не подкреплены измеренным SLA.
- Нет версии на других языках — только русский.

## Назначение / возможное неправильное использование (Intended use / known misuse)

- **Использовать для:** первого знакомства студента с кабинетом; как канонический текст приветственного чеклиста.
- **Не использовать для:** технической документации по кабинету, инструкций для кураторов/поддержки, описания внутренней логики начисления праны или правил доступа к блокам — для этого нужны отдельные документы.

## План сопровождения и вывода из эксплуатации (Maintenance & sunset plan)

- **Владелец:** команда школы санскрита (онбординг / поддержка).
- **Пересмотр:** при каждом изменении процесса входа, схемы статусов ДЗ, правил праны или сертификатов; иначе — плановая сверка с UI раз в семестр.
- **Вывод из эксплуатации:** если приветственный онбординг переедет целиком в интерактивный интерфейс кабинета, этот файл становится справочным/архивным.
