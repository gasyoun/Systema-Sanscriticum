## 0. Три вопроса-дискриминатора (первая минута любой аварии)

| Вопрос | Как проверить | Что различает |
|---|---|---|
| 1. Жива ли VM в LAN? | `ssh root@193.232.229.91 "curl -m6 -skI https://192.168.200.92 -H 'Host: samskrte.ru' \| head -1"` | ответ 200 = сервер жив, беда в пути/IP; тишина = сервер или узел |
| 2. Отвечает ли публичный IP с `.91`? | там же: `curl -m6 -skI https://193.232.229.92 -H 'Host: samskrte.ru'` | LAN да + публичный нет = **null-route провайдера** |
| 3. Жив ли пир `.91` из моей сети? | `ssh root@193.232.229.91 echo ok` | нет = проблема у меня/канала, не на серверах |

Эти три ответа кладут случай в одну из секций ниже. Не действовать до дискриминации.

## 1. Сайт недоступен извне

### 1.1 VM жива в LAN, публичный IP чёрен (текущий кейс 23-08)

Диагноз: **null-route / анти-DDoS блочок провайдера** (исходящий LAN работает — бэкапы идут).

Развилки поступков:

1. **Ждать автоснятия** — типично 24–72 ч после затухания атаки. Проверять в начале каждой сессии (три вопроса §0).
2. **Тикет/звонок Пудлинку** — тел. +7 812 6708800 (раб. время), письмо abuse@pudlink.ru с любого ящика, или Артём как владелец договора. Текст готов в чате 23-08 и в `~/.secrets/env.hosting-panel`.
3. **План Б — переезд**: если за несколько дней не отпустили — новый VPS у другого хостера по комплекту [ops/migrate/RUNBOOK.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/ops/migrate/RUNBOOK.md) (Debian 13, скрипты 00–06), затем A-запись в reg.ru. Деньги и слово — MG.
4. **Нельзя**: «чинить сервер» — он исправен; рестартить через Proxmox бессмысленно (VM жива).\n\n> **Статус 23-08, поздний вечер:** Пудлинк на связи; traceroute направлен им по их запросу (путь проходит, 8 хопов), трафик восстановлен ~23:05 МСК. Ждём от них причину блока и рекомендации по предотвращению — дописать сюда при ответе.

### 1.2 VM мертва и в LAN (пинг `.168.200.92` молчит)

Диагноз: VM зависла/упала или узел провайдера лежит.

Развилки:

1. **Узел лежит** (и `.91` тоже лег или лагает) → только Пудлинк: звонок +7 812 6708800, статус дата-центра. Ждать.
2. **Только `.92` висла, `.91` жив** → нужен **Proxmox-restart**: это Артём (или панель, доступа у MG нет). Одно сообщение Артёму: «restart VM .92 в Proxmox, please». Пока он в отпуске — совмещать с пунктом 1 (один звонок решает оба случая).
3. **VM потеряна безвозвратно** → переезд по [ops/migrate/RUNBOOK.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/ops/migrate/RUNBOOK.md) из restic-репозитория на `.91` (он жив отдельно от `.92`). Время: ~3 часа механики после VPS+ключа. **Прецедент отработан 23-08**: Aeza SWEs-1 (1c/2GB, Debian 13) доведён до прода за один вечер — кейс в [RUNBOOK](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/ops/migrate/RUNBOOK.md); погашение панели: my.aeza.ru → service 624477.

### 1.3 nginx отвечает, приложение нет (502/504)

Диагноз: php-fpm упал / MariaDB упала / OOM.

Развилки:

1. `systemctl status php8.3-fpm mariadb` → упавший юнит рестартуем сами: `systemctl restart php8.3-fpm` / `systemctl restart mariadb`.
2. OOM (dmesg kills) → смотрим кто съел: обычно воркеры/бэкап наехали; `memwatch.sh` уже пишет лог; при повторе — поднять swap/память тарифа (money row).
3. Не поднимается — журнал `journalctl -u php8.3-fpm -n 100`; дальше Артём/Агент с ключом.

### 1.4 500 от приложения (nginx и fpm живы)

1. Свежий деплой? → `deploy.sh --rollback` ([H1933](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/deploy.sh) механизм отката).
2. `storage/logs/laravel-*.log` хвост — исключение в коде/конфиге.
3. `php artisan config:clear` при подозрении на битый кэш конфига.
4. Если причина в коммите — фикс-PR обычным порядком; авто-деплой подхватит за ≤30 мин.

### 1.5 Всё работает, но медленно

1. Swap-storm прецедент 19-08: смотреть `free -m`, своп-остатки; перезапуск самого тяжёлого процесса.
2. Диск: `df -h` (алерт при >85%); чистить `storage/logs`, старые снапшоты не трогать.
3. `/tmp` tmpfs-cap — стоящая P5 проблема, правится только Артёмом на хосте (in-container потолок не ставится, [H3181](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/) ).

### 1.6 TLS-сертификат истёк

`certbot renew` (или `certbot --nginx -d samskrte.ru` заново); проверить таймер `certbot.timer`;
Better Stack обычно кричит раньше пользователей.

## 2. Деньги: платежи

### 2.1 Ученик оплатил — доступ не открылся

1. Леджер: `payment_webhook_events` — вебхук вообще пришёл? `decision` строки скажет причину
   (UNMATCHED = purpose без «Заказ №N»; HOLD_NOT_CAPTURED = авторизация без capture; RESURRECTION/AMOUNT_MISMATCH = защиты сработали).
2. Повторная доставка: Точка ретраит не-2xx; если леджер показал apply-fail — чинить причину и ждать ретрай, руками доступ НЕ выдавать до разбора.
3. Webhook URL привязан к домену — при переезде по Фазе 7 ничего менять не нужно.

### 2.2 Задвоение списания/доступа

Защиты стоят (resurrection guard, amount guard, идемпотентность по event_hash). Сработали —
это нормальный лог-warning, не инцидент. Реальное задвоение денег — возврат вручную через
Точку + строка в плейбук.

### 2.3 Донаты `/mecenaty`

Флаг `INSTITUTE_DONATIONS_LIVE` (включён 23-08, переживает ли — см. §5 чеклист восстановления).
Вебхук донатов ветвится по маркеру `№D{id}` в purpose и не касается путей доступа.

### 3.3 Оба сервера разом (провайдер целиком)

**Офсайт-копия создана и верифицирована 23-08 поздним вечером** (ox-alpha, по слову MG «есть свежий бэкап локально — изучай сам»): дамп БД laravel + .env из снапшота 7252145c (17:01 UTC) лежат на D:\Backups\systema\2026-08-23\, SHA-256 сверены байт-в-байт (8883c65d… dump · 23242e3… env). storage/app в копию НЕ включён (решение MG: видео записей — не для временной меры): он весит **2,13 ГиБ / 6285 файлов**, из них видео всего **162 МиБ** — основное хранилище записей YouTube + Rutube; состав: homework 1,05 ГиБ (сдачи учеников) · public 488 МиБ · telegram-harvest 388 МиБ · materials_sync 136 МиБ. storage/app остаётся покрытым restic на .91; дотянуть в офсайт можно одной командой (~2,1 ГиБ) по слову MG. Обновление БД-копии — повторить экспорт тем же способом или дождаться S3-лега. Автоматизация офсайта (S3-лега ждёт бакет Яндекса — остаток Волны 1,
[инструкция](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/ops/backup/RUN_LOG_H3175_WAVE1_23-08-2026.md)).

Митигация сейчас: MG создаёт бакет (20 мин), после возвращения публичного пути `.92` пуш-лега
заработает сам. Худший случай сегодня: последний код — GitHub, последний контент — недавние
локальные зеркала (D:\), БД учеников — под риском окна с последнего снапшота.

## 4. Безопасность

| Случай | Первое действие | Развилка |
|---|---|---|
| Утечка секрета в git | ротация/отзыв секрета ДО чистки истории | навык secret-purge (filter-repo + force-push) — только после ротации |
| Подозрение на взлом VM | не тушить следы: сохранить сессии/логи; сменить пароли панелей | если root под вопросом → переезд на новый бокс из бэкапа (migrate kit) вместо лечения |

| Провайдер запросил реакцию на абузу | отвечать с почты договора (Артём) или MG письменно | игнор = риск блокировки всего сервиса |
