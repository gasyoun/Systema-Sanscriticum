## 0. Ответ на главный вопрос: «TG сам запишет отсрочку в кабинет?»

| | Сейчас (02-08-2026) | Как «починить» |
|---|---|---|
| ЛС ученика → `@rusamskrtam` | **Синхронизируются** в helpdesk Systema (`TelegramSupportMessage`), если `TELEGRAM_SUPPORT_ENABLED` + `telegram-support:sync` | Уже работает |
| Фраза «оплачу 20 августа» | При флаге OFF — **не** создаёт; при ON → pending suggestion → approve → `PaymentPromise` (см. §4) | Флаг `promise_suggestion_detection_enabled` |
| Дата в кабинете и «завтра срок оплаты» | Только после **«Договориться» / «Рассрочка»** в админке (или self-service переноса даты) | Куратор фиксирует руками |
| Доступ к блокам | Оплата **или** conditional access под обещание | Не из текста TG |
| Учебный TG-чат | Кик **вручную** из «Должники» (`@zapisi_ORSbot`) | Авто-кика при долге **нет** |

**Итог:** Telegram **может** «починить» только если куратор (или будущий детектор+approve) создаёт **обещание** в Systema. Одно сообщение в чат = след в support, **не** запись в личном кабинете.

## 1. Для куратора

### 1.1. Что изменилось vs «висит полгода в чате»

- Долг виден в **Должники** (студент × курс).
- Можно: напомнить TG/VK, **Договориться** (дата), рассрочка, открыть/отозвать доступ, 🚩, **исключить из TG-чата**.
- Авто: `promises:remind-tomorrow` (за день до даты обещания); `promises:expire` ночью; при 3+ просроченных обещаниях за 12 мес. — авто-🚩 (без авто-кика).
- **Не** авто: отзыв conditional, кик из чата, отчисление, создание promise из текста TG.

### 1.2. Отсрочка до 20.08 (пример: курс 1 — был срок 2.08, ещё два — 10.08)

1. **Должники** → найти студента (часто **3 строки** = 3 курса).
2. На **каждом** курсе: **⋯ → Договориться**.
3. **Дата** = 20.08.2026; сумма; комментарий:  
   `Отсрочка до 20.08. Было: курс1 02.08; курсы 2–3 10.08. Согласовано в TG.`
4. Тогл **«Открыть доступ под обещание»**:
   - **вкл** — можно учиться до 20.08 (conditional; в фин-отчётах не деньги);
   - **выкл** — только заметка о дате, материалы сами не откроются.
5. Ответить ученику текстом из [1:1 scripts](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/copy/tg-payment-discipline-1to1-scripts.md) §A — **и** явно: «дата уже в кабинете».
6. 19.08 — система напомнит сама (если обещание active).
7. После 20.08 без оплаты: **Отозвать доступ** / **кик TG** / 🚩 / статус **Исключен** + блок выхода — по ситуации (см. debtors-manual §9–12).

### 1.3. Предупредить / «отменим курс / пропустите блок»

| Цель | Действие |
|------|----------|
| Напомнить сейчас | **Напомнить в TG/VK** (один или bulk) |
| Зафиксировать слово | **Договориться** / **Рассрочка** |
| Закрыть материалы | **Отозвать доступ** (TG+email+VK+Max) |
| Убрать из чата | **Исключить из TG-чата** (hard ban; LMS не трогает) |
| Отчислить | Карточка → **Обучается на курсах** → **Исключен** / **Покинул** + блок выхода |

Кик из чата **≠** отчисление. Отчисление **≠** авто-кик.

### 1.4. Деньги пришли

- **Подтвердить оплату** в меню должника / на обещании;  
  или ученик сам в **«Мои долги»** — обещания часто закроются сами.
- Silent = задним числом без «оплата получена» в TG.

### 1.5. 🚩 и чат

- 🚩 режет скидку, «Договориться», conditional, разовый урок — **не** кикает TG сам.
- Кик: отдельная кнопка или тумблер при 🚩.
- Разбан: дашборд **«Записи (бот)»**.

## 2. Для ученика

### 2.1. Где что лежит

| Нужно | Куда |
|-------|------|
| Оплатить / график / перенос даты | Кабинет → **«Мои долги»** |
| История платежей | **«Мои оплаты»** |
| Написать про отсрочку | Куратору или https://t.me/rusamskrtam |
| Урок «под замком» | «Почему закрыто?» на уроке + долги |

### 2.2. Отсрочка правильно

1. Написать **заранее** (шаблон §B в 1:1 scripts): дата, какие курсы, что с доступом/чатом.
2. Дождаться ответа: **«дата в кабинете»** + правила доступа.
3. Проверить **«Мои долги»**: должна быть дата/сумма обещания (если куратор зафиксировал).
4. Оплатить до даты; **один раз** можно **«Перенести дату»** ≤ 14 дней — дальше только куратор.
5. За день до даты может прийти TG-напоминание — штатно.

### 2.3. Чего ждать не стоит

- Что «написал в TG — значит, 20.08 уже в системе» — **нет**, пока куратор не нажал **Договориться**.
- Что можно месяцами сидеть в учебном чате без оплаты — кик **ручной**, но список должников и напоминания **есть**.
- Что «доступ в кредит» вечный — при срыве куратор отзовёт (сообщение в TG/email/…).

### 2.4. Закрыли доступ / выгнали из чата

1. **«Мои долги» → Оплатить** (или написать, если сумма неясна).
2. После оплаты — кабинет; чат может потребовать **разбан** куратором.
3. Hard ban: старая инвайт-ссылка **не** вернёт в чат без разбана.

## 3. Одна таблица на двоих (пример 2.08 / 10.08 → 20.08)

| Когда | Куратор | Ученик |
|-------|---------|--------|
| 2.08 | Видит долг по курсу 1 | Пишет про отсрочку |
| Сразу | 3× **Договориться** → 20.08 + комментарий; тогл доступа; ответ в TG | Ждёт «дата в кабинете» |
| до 20.08 | Виджет «Скоро срок»; 19.08 авто-TG | **Мои долги** → оплата; при нужде 1 перенос ≤ 14 дн |
| после 20.08 без оплаты | Отозвать / кик / 🚩 / Исключен | Оплатить → вернуть доступ/чат |

## 4. Telegram → кабинет: детектор отсрочек (live, H2156)

Реализовано как twin **`reminders:detect-requests`** → `ReminderSuggestion`:

| Шаг | Путь |
|-----|------|
| 1 | `php artisan promises:detect-deferrals` (каждые 15 мин, Kernel) — regex + LLM (`CuratorAi`) по `ChatMessage` + `TelegramSupportMessage` |
| 2 | Pending **`PaymentPromiseSuggestion`** (Filament → **Пользователи → «Предложения отсрочек»**) |
| 3 | Куратор **Approve** (дата, курс, сумма, note) → `PaymentPromise` `status=active` |
| 4 | Ученик видит дату в **«Мои долги»**; `promises:remind-tomorrow` как у любого обещания |
| 5 | **grant_access** в modal **default OFF** — conditional access только если куратор включил тогл; 🚩 + grant → refuse grant (обещание без доступа OK) |

**Флаг:** `MarketingSetting.promise_suggestion_detection_enabled` / дефолт **OFF**. Без включения детектор no-op.  
**Unlinked TG:** `linked_user_id` null → skip (нет orphan promise).  
**Multi-course:** один open debt → prefill `course_id`; несколько → null, курс обязателен на approve.  
**Не делает:** auto-approve, auto-kick, auto-open access, installments из одного сообщения.

Ручной fallback без флага: ЛС → куратор → **Договориться** → кабинет.
