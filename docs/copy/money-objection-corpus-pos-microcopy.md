# H1291 — корпус возражений в микрокопии точки продажи (ВРЕМЯ + ЦЕНА)

_Created: 20-07-2026 · Last updated: 20-07-2026_

Лейн волны revenue-copy
([план](https://github.com/gasyoun/Uprava/blob/main/docs/PLAN_SYSTEMA_REVENUE_COPY_FABLE_WAVE_2026H2.md),
handoff [H1291](https://github.com/gasyoun/Uprava/blob/main/handoffs/H1291-Fable_Systema-Sanscriticum_money-objection-corpus-pos-microcopy_19.07.26.md)).
Исполнитель: Fable 5 (`claude-fable-5`), 20-07-2026.

## Первоисточник

[Плейбук возражений](https://github.com/gasyoun/Uprava/blob/main/custdev/OBJECTION_PLAYBOOK_2026.md)
(H474/H482, ~2 605 размеченных диалогов): **ВРЕМЯ (285) и ЦЕНА (252) дают 537 из 679
зафиксированных возражений корпуса**. Таксономия не перевыводилась — этот лейн
переносит готовые формулировки «Для лендинга» из плейбука на поверхности, где
покупатель возражение чувствует. Ни одна цифра не пересчитана.

**Стоп-гейт плейбука не про этот лейн.** Открытый `@DECIDE` о раскатке плейбука
касается **кураторских скриптов** (реплики живого куратора, §5–§8 плейбука) — не
микрокопии страниц. Кураторские скрипты этим лейном не тронуты; на страницы легли
только формулировки уровня «Для лендинга», уже прошедшие состязательную панель H482.

Чекаут по итогам ревизии **не тронут вовсе**: оба денежных возражения там уже
отвечены, а критерий приемки лейна прямо запрещает превращать чекаут в стену FAQ.

## Дыры, которые лейн закрывает

1. **Норма нагрузки нигде не названа.** «1 блок = 4 занятия» жило только в
   боте-FAQ и внутренних руководствах; ни одна витринная страница не объясняла
   единицу «/ блок», которой назначена цена.
2. **У расписания не снят страх пропуска.** Секция «Расписание» показывает даты и
   время — ровно то место, где покупатель понимает «я не попадаю по вторникам», —
   и не говорила, что занятие остается в записи.
3. **У тарифной сетки нет «выхода из суммы».** Принцип поблочной оплаты, запрос
   «по частям» и льготная цена были доступны только на следующем шаге (чекаут) или
   вообще только в диалоге с куратором; строка возврата — только на чекауте.

## Строки в финальном виде

### 1. Карточка курса в каталоге `/online` — глосса единицы «/ блок»

Файл: [course-card.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/components/shop/course-card.blade.php),
под строками цен, только при наличии блочного тарифа:

> Блок — обычно 4 занятия.

Одна строка, `text-[10px]`: карточка объясняет единицу там же, где показывает
цену «/ блок». «Обычно», не «=»: размер блока в модели данных не фиксирован
(`CourseBlock` без счетчика занятий), внутренние руководства говорят «≈ 4».

### 2. Страница курса, секция «Расписание» — ВРЕМЯ и РАСПИСАНИЕ

Файл: [shop/show.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/show.blade.php),
конец секции `#schedule` (рендерится только при предстоящих занятиях),
`data-analytics="objection-time-microcopy"`:

> Не попадаете по времени? Занятие останется в записи — вернетесь к нему, когда
> будет тишина. Пропуск не выбивает из курса.

Формулировка — «Для лендинга» из §3.1/§3.3 плейбука, дословно по смыслу
(«Пропущенный урок не выбивает из курса: вы вернётесь к нему, когда будет
тишина» → без ё, вопрос расписания «Не попадаете — смотрите в записи» слит в ту
же строку). Отвечает сразу двум возражениям в их точке: ВРЕМЯ (№1 корпуса) и
РАСПИСАНИЕ (лёгкое, конверсия выше базовой).

### 3. Страница курса, секция `#tariffs` — ЦЕНА

Файл: [shop/show.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/shop/show.blade.php),
сразу под тарифными вкладками, `data-analytics="objection-price-microcopy"`.
Три строки и мини-строка доверия, каждая со своей калиткой честности:

Строка принципа (только при блочных тарифах курса):

> Платить за весь курс сразу не нужно: оплачиваете ближайший блок — обычно это
> 4 занятия — и решаете о продолжении после него.

Указатель на запрос «по частям» (только при настроенном кураторском чате —
та же калитка `services.telegram.curators_chat_id`, что у самого запроса H1290
на чекауте; без чата запрос не существует, и обещать его нельзя):

> Нужно разбить оплату на части? Спросите на шаге оплаты — запрос куратору ни к
> чему не обязывает.

Льготная строка (всегда; ссылка ведет в единственный канал поддержки):

> Пенсионерам, студентам и многодетным — льготная цена: напишите куратору в
> Telegram.

Мини-строка доверия — shared string 4 дословно, всегда ссылкой на `/vozvrat`
(контракт [`_shared_strings.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/copy/_shared_strings.md),
строка 4: «H1288 определяет, H1291 цитирует»):

> Возврат: до начала — 100%

## Честность каждой строки — сверка с продуктом

| Утверждение | Основание в кодовой базе | Вердикт |
|---|---|---|
| «Блок — обычно 4 занятия» | бот-FAQ «1 блок = 4 занятия», `TemplateRenderer::$blockSize = 4`, руководства «≈ 4»; в модели размер не фиксирован | честно с «обычно», нечестно с «=» |
| «Платить за весь курс сразу не нужно» | блочные тарифы первоклассны (`Tariff::type = block`), карточки «Оплатить блок целиком» | показывается только курсам с блочными тарифами |
| «оплата по частям» через куратора | H1290: `installments-cta` на чекауте, `CheckoutController::requestInstallments` | показывается только при настроенном чате кураторов |
| льготная цена трем категориям | закрытый список фактов плейбука H474; бот-FAQ; механика — персональная скидка вручную | без сумм и без самообслуживания: «напишите куратору» |
| «Возврат: до начала — 100%» | оферта, прил. №1 п. 3.1(а); страница `/vozvrat` (H1288) | цитата shared string 4, только ссылкой |
| «Занятие останется в записи» | trust-strip «Записи всех занятий» на той же странице | без повторного «навсегда» (см. решения, п. 4) |

**Что сознательно НЕ попало в строки.** «Вводный разбор Гиты за 2 000 ₽» из
закрытого списка фактов плейбука: в кодовой базе нет такого продукта, цены и
маршрута (проверено сплошным поиском; пробное занятие — механизм поштучный,
цена задается в БД курса). Пока человек не подтвердит, что продукт заведен в
проде, строка была бы обещанием несуществующей поверхности — ровно то, что
запрещает критерий приемки. Также не попали: конкретные суммы льготы (400 ₽ и
т. п. — цены не хардкодятся, fence 2), «бесплатное вводное занятие» на этих
поверхностях (страница курса уже несет пробное/пример урока; дубль был бы
стеной FAQ) и часовые пояса у расписания (изменение фичи, не копирайта).

## Регистр

По контракту голоса
([ARCHITECTURE](https://github.com/gasyoun/Uprava/blob/main/docs/ARCHITECTURE_SYSTEMA_REVENUE_COPY_VOICE_CONTRACT.md)):
«вы» строчными, без восклицаний, без эмодзи, без срочности (D4), без «всего»/
«даже» перед суммами, достоинство вместо уступки. Слово «рассрочка» на
студенческих поверхностях запрещено (правило H1290) — везде «оплата по частям» /
«разбить оплату на части»; тест закрепляет запрет. Орфография без ё (D13):
«останется», «вернетесь», «решаете». Ни одного нового утверждения о сроках
доступа: строка расписания говорит «останется в записи», не «навсегда».

## Decisions taken unattended

1. **Отбор возражений: три, не шесть.** Дефолт имплементационного плана — «до
   шести, чтобы чекаут не стал стеной FAQ». По карте дублей выше СОМНЕНИЕ,
   СЛОЖНОСТЬ и ТЕХНИКА в точке продажи уже отвечены существующими поверхностями
   (пробное, пример урока, tech-payment), МОЛЧАНИЕ — не страничное возражение.
   Лег только непокрытый остаток: ВРЕМЯ, ЦЕНА, РАСПИСАНИЕ (слито с ВРЕМЯ).
   Альтернатива — добить до шести дублями — отклонена критерием приемки.
2. **Чекаут не тронут.** Оба денежных возражения там уже отвечены (H1290 +
   H1288). Альтернатива — добавить туда глоссу блока — отклонена: сумма на
   чекауте уже названа, объяснять единицу поздно, место объяснения — витрина.
3. **Указатель «по частям» под той же калиткой, что сам запрос.** Строка о
   запросе куратору рендерится только при `services.telegram.curators_chat_id`.
   Альтернатива — безусловная строка с прямой ссылкой на Telegram — отклонена:
   она обещала бы механизм «на шаге оплаты», которого без чата нет.
4. **Не повторять «навсегда» у расписания.** Trust-strip на той же странице уже
   несет «Доступ к видеозаписям остается с вами навсегда»; бот-FAQ школы
   осторожнее («как правило бессрочно»). Новая строка говорит «останется в
   записи» без срока — не эскалирует расхождение, которое человеку ещё
   предстоит снять. Расхождение «навсегда ↔ как правило бессрочно» существовало
   до лейна и им не создано; снятие — человеческое решение.
5. **Глосса карточки — минимум.** «Блок — обычно 4 занятия.» без «платить можно
   по блокам»: выбор «Весь курс / По модулям» на карточке уже виден, уникальная
   недостающая информация — только размер единицы.
6. **Якорь льготной строки — «напишите куратору в Telegram»,** а не канонический
   «Написать в Telegram» (это форма кнопки из shared string 3): внутри
   повествовательного предложения кнопка-именование читалась бы канцеляритом.
   Канал и адрес — те же, `https://t.me/rusamskrtam`.
7. **Строка принципа эхом H1293, не дублем.** «Платить за весь курс сразу не
   нужно: … решаете о продолжении после него» повторяет мысль лесенки `/online#ceny`
   дословно по конструкции — сознательно: один голос в двух местах воронки.
   Поверхность H1293 не редактировалась.
8. **`data-analytics`-атрибуты добавлены** (`objection-time-microcopy`,
   `objection-price-microcopy`) — по дому (`trust-strip`,
   `price-ladder-narrative`): плейбук честно фиксирует, что его формулировки не
   измерены; атрибуты дают будущему замеру зацепку.
9. **MarketingSetting не задействован.** Строки структурны для страниц (прецедент
   H1290/H1293 — «copy-in-blade»); менеджерской ретюнинг-потребности здесь нет,
   плейсхолдеров нет, ловушка DEPLOY_QUEUE №11 не создается.

## Migration notes

Деплоя данных не требуется: ни миграций, ни сидов, ни ключей MarketingSetting.
Обе новые калитки читают уже существующий конфиг. На инсталляции без
`services.telegram.curators_chat_id` строка «по частям» просто не рендерится —
как и сам запрос H1290.
