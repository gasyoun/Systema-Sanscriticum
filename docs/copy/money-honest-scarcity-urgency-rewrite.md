## Зачем

Блок тарифов
([price_block.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/promo/blocks/price_block.blade.php))
без настройки рендерил обратный отсчет «Повышение цены через:», который
**сбрасывался на +24 часа при каждой загрузке страницы**, жестко зашитые «16/20
мест», мигающий бейдж «Акция» и пульсирующий ярлык «Осталось мало!». Тот же
скопированный код жил в блоке потоков
([course_streams_block.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/promo/blocks/course_streams_block.blade.php)).
Это противоречило анти-urgency голосу марафонского комм-пакета
([marketing/marathon-2026-08/](https://github.com/gasyoun/Systema-Sanscriticum/tree/main/marketing/marathon-2026-08):
«ни одного элемента срочности в продающем контуре») — два маркетинговых голоса
в одном продукте, один из них лгал. Постановление D4: убить фальшивые дефолты,
дефицит показывать только с реальными данными.

## Что изменилось

- **Пустая конфигурация — честный прайс.** Нет настроенной даты — блок дедлайна
  не рендерится вовсе; нет обоих чисел мест — счетчик мест не рендерится. Секция
  дефицита без данных исчезает целиком.
- **Реальный дедлайн — дата словами, не тикающие цифры.** Вместо отсчета:
  «Текущая цена действует до» + «26 июля, 19:00» + «После этой даты стоимость
  будет выше.» (шаг 2 лейна: назвать дату и что изменится, без театра срочности).
- **Истекший дедлайн скрывается.** Раньше прошедшая дата рендерила вечные
  «00:00:00» — просроченный дедлайн такая же фальшивка, как выдуманный.
- **Фолбэк на дату вебинара удален.** Старт вебинара — не дата изменения цены;
  подпись «Повышение цены через:» над датой вебинара была выдумкой.
- **Места — только реальные числа.** Рендер только при заполненных «Занято» и
  «Всего» (0 ≤ занято ≤ всего, всего > 0). Спокойная подпись «Свободных мест: N
  из M» и статичная полоса. Убраны «Осталось мало!», бегущие полоски анимации,
  «Забронировано N мест», мигающий бейдж «Акция».
- **Дефолты 16/20 удалены и из Filament-схемы** — раньше админка предзаполняла
  выдуманные числа, так что даже «настроенный» блок нес фальшивку, если менеджер
  их не менял. Подсказки полей теперь требуют реальные данные и объясняют, что
  незаполненное не показывается.
- Мертвый код снят: Alpine-скрипт `timer()` и keyframes `progress` больше нигде
  не используются и удалены из обоих блейдов.

## Радиус поражения (шаг 4)

Оба блока рендерятся только через конструктор лендингов
(`LandingPage.content` → [promo/show.blade.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/promo/show.blade.php));
статических включений в кодовой базе нет (проверено grep'ом 19-07-2026).
Структурно фальшивую срочность показывал **каждый активный лендинг с блоком
`price_block` или `course_streams_block`, у которого не заполнен `timer_end`**
(отсчет +24 часа с вечным сбросом — или отсчет до даты вебинара с ложной
подписью про цену), **и каждый — с незаполненными местами** (фальшивые «16/20»).
Из-за предзаполненных дефолтов Filament под подозрением и «настроенные» блоки с
ровно 16/20.

Пер-страничный список — это строки прод-БД, доступа к которой у волны нет
(осознанное ограничение плана). Готовая read-only команда для MG (`php artisan
tinker`, одна строка):

```php
App\Models\LandingPage::where('is_active', true)->get()->filter(fn ($p) => collect($p->content)->contains(fn ($b) => in_array($b['type'], ['price_block', 'course_streams_block'], true)))->map(fn ($p) => [$p->slug, collect($p->content)->map(fn ($b) => $b['type'])->join(',')])->values()
```

Каждый слаг из вывода до этого PR показывал фальшивый дефицит, если его блок не
переопределял дефолты.

## Заметки о регистре

- **Дата как факт, не как угроза.** «Текущая цена действует до 26 июля, 19:00» —
  утверждение о том, что есть сейчас; «После этой даты стоимость будет выше» —
  что изменится. Ни «спешите», ни «успейте», ни тикающих цифр: читатель взрослый,
  дата у него есть, решение за ним.
- **«Свободных мест: 4 из 20» вместо «Доступно мест + Осталось мало!»** — числа
  без оценочного давления; вывод «мало это или много» остается читателю.
- Заявленный менеджером дефицит по правилу D4 — реальные числа набора; подсказки
  админки теперь прямо это требуют.
- Орфография D13: все новые строки без ё («отсчет», «счетчик», «действует»);
  случаев всё/все в новых строках нет.

## Строки в финальной форме

### Лендинг — блок дедлайна (рендерится только с реальной датой)

- Подпись: «Текущая цена действует до»
- Дата: «26 июля, 19:00» (`translatedFormat('d F, H:i')`; при времени 00:00 —
  только «26 июля»)
- Пояснение: «После этой даты стоимость будет выше.»

### Лендинг — блок мест (рендерится только с двумя реальными числами)

- Подпись: «Свободных мест:»
- Числа: «4 из 20» (свободные из всего; полоса заполнена долей занятых)

### Удаленные строки (фальшивая срочность)

- «Повышение цены через:» + отсчет Дн/Час/Мин/Сек
- «Доступно мест: … из …» с дефолтом 16/20
- «Осталось мало!» (пульсирующий ярлык)
- «Акция» (мигающий индикатор)
- «Забронировано N мест»

### Админка (Filament, оба блока)

- Секция: «Настройки дефицита (Дедлайн и Места)», описание: «Только реальные
  данные: что не заполнено — то не показывается. Выдуманных значений по
  умолчанию больше нет.»
- Поле даты: «Текущая цена действует до (дата и время)», подсказка: «Указывайте
  только реальную дату изменения цены. Не заполнено или дата прошла — блок
  дедлайна не показывается.»
- Поля мест: «Занято мест» / «Всего мест» — без значений по умолчанию.

## Decisions taken unattended

1. **Скоуп расширен на `course_streams_block`.** Handoff называет `price_block`,
   но тот же скопированный фальшивый дефицит (таймер +24 часа, 16/20, «Акция»)
   жил и в блоке потоков — machine-checkable floor «фальшивые фолбэки отсутствуют
   в исходниках» недостижим без него. Альтернатива — оставить вторую копию лжи —
   противоречила бы premise лейна.
2. **Фолбэк `webinar_date` удален, а не перемаркирован.** Альтернатива — честная
   подпись «Вебинар начнется …» — отвергнута: это работа hero-блока вебинарного
   лендинга, а не блока цены; дата вебинара не подтверждает утверждение о цене.
3. **Истекший `timer_end` скрывается молча** (раньше — вечные нули). Просроченная
   дата не факт о будущем изменении цены.
4. **Места — из конфига блока, не из живого набора.** Помеченный дефолт шага 3
   (нечисловая формулировка) применяется, когда реальным числам неоткуда взяться
   без запросов к наборам; здесь источник есть — числа менеджера, чьи подсказки
   теперь требуют реальности. Блок не привязан к курсу/группе (тарифы в нем —
   свободный текст), так что автоматический живой счетчик невозможен по
   конструкции.
5. **Пояснение «После этой даты стоимость будет выше.»** — семантика поля
   (бывшее «Повышение цены через:») сохранена как обещание роста цены; менеджер,
   ставящий дату, утверждает именно это. Нейтральное «изменится» отвергнуто как
   уклончивое.
6. **Бейджи «Хит продаж» / «Популярный» оставлены** — управляемое менеджером
   утверждение о популярности тарифа, не механика дефицита; в скоуп D4 не входят.
7. **Тест `block_renders_timer_and_seats_counter` переписан** — он утверждал
   фальшивое поведение (рендер отсчета) как норму; заменен на
   `block_with_real_deadline_and_seats_renders_honest_scarcity` + два негативных
   кейса. Новый [PriceBlockTest.php](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/tests/Feature/PriceBlockTest.php)
   закрепляет machine-checkable floor лейна: пустая конфигурация — ни отсчета, ни
   счетчика мест.
