## Mapping residual (precise)

There is **no metadata edge** tying any Systema course/lesson to
morphology-curriculum: the kosha manifest names Systema only as a *future*
consumer ("Systema/csl-guides quiz component (future, via the shared item
schema)"), and Systema's lyw reader keys packs by `(zan=config lyw.default_zan=1,
level, interest)` — all seven zan1 profile slots are occupied by Kochergina
занятие-1 content, whose syllabus (devanāgarī/script) is a different syllabus
from morphology lesson 1 (a-stems). Serving this pack therefore needs an MG
decision (GTD @DO row filed): (a) a dedicated zan for morphology, (b) a new
profile dimension, or (c) a separate route — plus the real course/lesson id to
bind it to. No ID was invented; the preview validates against zan1/base because
that is the only servable key today.

## Risks

- Syncretism items preserved as-is from the source (e.g. `artham` = m-acc =
  n-nom/acc; source prompts do not state the model) — flagged by a mnemonic in
  the text; editing answers/wording would violate "answers equal source".
- The `(rank, id)` selection leans on nominative/accusative cells (a lemma's
  most corpus-frequent cells) — honest beginner bias, documented in
  `selection_rule`; wider cell coverage is future packs' work.
- PHPUnit emits ~3.1k pre-existing deprecation notices suite-wide (PHPUnit 11.5
  on PHP 8.5) — same on baseline before this change; not introduced here.
- Local run needed `php -d memory_limit=2G vendor/bin/phpunit` (`artisan test`
  hits the 128M limit while building the suite) — environment fact, recorded.
