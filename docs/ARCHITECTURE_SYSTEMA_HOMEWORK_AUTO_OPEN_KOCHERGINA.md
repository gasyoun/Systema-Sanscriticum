# Архитектура: автооткрытие приёма домашних заданий

_Created: 27-07-2026 · Last updated: 27-07-2026_

Архитектурный слой плана
[PLAN_SYSTEMA_HOMEWORK_AUTO_OPEN_KOCHERGINA_2026H2.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/PLAN_SYSTEMA_HOMEWORK_AUTO_OPEN_KOCHERGINA_2026H2.md).

## Что меняется в модели данных

### Колонки на `lessons`

| Колонка | Тип | Зачем |
|---|---|---|
| `textbook_lesson` | `unsignedTinyInteger` nullable | «Занятие N» учебника, 1–40 (D7). Заполняет человек в Filament |
| `recording_attached_at` | `timestamp` nullable | момент, когда у урока ВПЕРВЫЕ появилось видео — точка отсчёта (D2) |
| `homework_opens_at` | `timestamp` nullable | вычисленный момент открытия (D3). Материализован, чтобы админ видел «когда», а не выводил в уме |
| `homework_auto_opened_at` | `timestamp` nullable | **маркер владения**: автомат открыл этот урок и только поэтому вправе его закрыть (D10) |
| `homework_closed_at` | `timestamp` nullable | приём закрыт правилом D8 |

Отдельного булева `homework_auto_managed` НЕ заводим: `homework_auto_opened_at IS NOT NULL`
и есть признак владения. Преподаватель, включивший ДЗ руками, оставляет колонку `NULL`, и
автозакрытие его урок не видит — это ровно D10, выраженное схемой, а не веткой в коде.

### Новая таблица `homework_access_grants` (волна 2)

Точечное открытие закрытого приёма для одного студента (D12). Форма скопирована с
существующей [`LessonAccessGrant`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Models/LessonAccessGrant.php) —
это уже принятый в репозитории способ выдать одному человеку то, что закрыто правилом.

| Колонка | Тип |
|---|---|
| `lesson_id` | FK `lessons`, cascade on delete |
| `user_id` | FK `users`, cascade on delete |
| `granted_by` | FK `users`, nullable on delete |
| `reason` | `string` nullable |
| `timestamps` | |

Уникальный индекс `(lesson_id, user_id)` — грант не дублируется.

## Границы компонентов

```
Lesson::saving  ──► ставит recording_attached_at при первом hasVideo()
                    и пересчитывает homework_opens_at

homework:auto-open (ежечасно)
        │
        ├─► HomeworkAutoOpener::due()      — какие уроки пора открыть
        │        └─ читает lessons, конфиг охвата (D4)
        │
        ├─► HomeworkAutoOpener::open()     — открыть один урок
        │        ├─ KocherginaExerciseSource::forLesson(N)  — текст условия (D5/D6/D14)
        │        ├─ закрыть предыдущий автооткрытый (D8/D10)   [волна 2]
        │        └─ HomeworkNotifier::opened()                  — Telegram/VK (D9)
        │
        └─► журнал: что открыто, что пропущено и почему
```

Единственная точка правды «открыт ли приём для этого студента» — метод на модели:

```php
Lesson::homeworkOpenFor(?User $user): bool
```

= `homework_enabled` **и** (`homework_closed_at` пуст **или** есть грант для `$user`).

Этим методом пользуются и [`HomeworkController::store`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Http/Controllers/HomeworkController.php)
(вместо нынешнего `abort_unless($lesson->homework_enabled)`), и
[`homework.blade.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/resources/views/student/partials/homework.blade.php).
Две копии этого условия разъедутся — как разъехались бы две копии зарплатной арифметики,
о чём предупреждает раздел Mutual Settlement в
[CLAUDE.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/CLAUDE.md).

## Расчёт момента открытия (D3)

```
opensAt = следующее 09:00 Europe/Moscow в момент или после (recording_attached_at + 12 ч)
```

Оба числа — из конфига, не из кода. Проверка на краях:

| Запись появилась | +12 ч | Открытие |
|---|---|---|
| вт 06:00 | вт 18:00 | ср 09:00 |
| вт 20:00 | ср 08:00 | ср 09:00 |
| вт 21:30 | ср 09:30 | чт 09:00 |
| вт 09:00 ровно | вт 21:00 | ср 09:00 |

Третья строка — единственный случай, когда «следующий день» превращается в «через день»:
запись, выложенная поздно вечером, проскакивает мимо утреннего окна. Это принятое следствие
D3, а не дефект; альтернатива (открыть в 09:30) нарушила бы ровный час рассылки.

Таймзона проекта прибита к `Europe/Moscow` в `config/app.php`, поэтому расчёт ведётся в ней
явно и не зависит от таймзоны сервера.

## Источник текста упражнений

`KocherginaExerciseSource` читает
[`Kochergina_unicode.mdx`](https://github.com/gasyoun/SanskritGrammar/blob/main/KocherginaUchebnik_1998/Kochergina_unicode.mdx)
по пути из конфига (`KOCHERGINA_SOURCE_PATH`, по умолчанию соседний клон
`../SanskritGrammar/KocherginaUchebnik_1998/Kochergina_unicode.mdx`).

Структура источника, установленная при аудите: занятия помечены строками `Занятие I` …
`Занятие XL`, блок упражнений внутри занятия начинается строкой `Упражнения` и тянется до
следующего заголовка занятия или до раздела текстов. Упражнения нумерованы римскими
цифрами (`I.`, `II.`, …). Занятия I–V занимают строки 229–1185.

**Текст в этот репозиторий не попадает** (D6-следствие 1): ни сидера, ни фикстуры с текстом
учебника. Тесты работают на синтетическом mdx-фрагменте, сочинённом для теста, а не на
куске книги. Если источник недоступен, `forLesson()` возвращает `null`, и открытие
происходит с отсылочной формулировкой — открытие никогда не блокируется отсутствием текста.

## Вердикт «строить или переиспользовать»

| Кусок | Вердикт | Почему |
|---|---|---|
| Приём, проверка, файлы, статусы работ | **переиспользовать** | `HomeworkService` + три модели закрывают весь жизненный цикл работы |
| Пуш в мессенджеры | **переиспользовать форму** | `pushReviewToMessengers` уже решает «после коммита, не в транзакции, ошибка не роняет» |
| Маршрутизация уведомлений | **переиспользовать** | `HomeworkNotifier` (H1729) — уже дом для «кому сообщать про ДЗ», добавляется метод |
| Состояние «условие ещё не задано» | **переиспользовать** | `awaitingPrompt` в blade уже есть, ничего не рисуем заново |
| Точечный грант | **строить по образцу** | `LessonAccessGrant` — образец, но про доступ к уроку, а не к приёму работ; смешивать нельзя |
| Планировщик открытия по времени | **строить** | `content:publish-due` — образец ежечасной команды, но про контент-календарь |
| Ключ «урок ↔ занятие расписания» | **переиспользовать** | `(course_id, group_id, lesson_date)` — тот же ключ, что у n8n и `syncTrialPlaceholderLesson()` |
| Извлечение упражнений из учебника | **строить** | оцифровка есть, парсера блока упражнений нет ни в одном репозитории организации |
| Автооткрытие ДЗ как таковое | **строить** | `hub_grep` по всем хабам: ноль прецедентов |

## Область действия (D4)

Конфиг `homework.auto_open`:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | аварийный выключатель всей фичи |
| `course_slugs` | пусто | какие курсы в пилоте; пусто = ни одного, фича спит |
| `textbook_lessons` | `[1,2,3,4,5]` | какие занятия учебника участвуют |
| `delay_hours` | `12` | выдержка после появления записи |
| `align_hour` | `9` | час МСК, на который выравнивается открытие |
| `notify_channels` | `telegram,vk` | D9 |
| `close_previous` | `false` | волна 2 включает D8 отдельно от открытия |

Механизм общий, включение — данными и конфигом. Ровно та же дисциплина, что у проверяющих
групп H1729: у кого нет строк — для того ничего не меняется.
