# Дисциплина оплаты: скор по студенту и по группе

_Created: 05-07-2026 · Last updated: 05-07-2026_

Куратор и преподаватель хотят видеть не только «должник / не должник» (текущий 🚩),
а **степень** платежной дисциплины — по каждому студенту и агрегированно по группе.
Это не замена существующего сервиса «Должники»
([`docs/debtors-manual.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/debtors-manual.md)),
а надстройка над теми же данными.

## Что уже есть (не переписываем)

| Кусок | Где | Роль здесь |
|---|---|---|
| Долги, обещания, рассрочки | [`app/Services/StudentDebtsService.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/StudentDebtsService.php), `PaymentPromise` | Источник сырых событий: какой блок оплачен вовремя/поздно, какое обещание выполнено/просрочено. |
| Conditional access | [`app/Services/ConditionalAccessGranter.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/ConditionalAccessGranter.php) | Источник сигнала «доступ в кредит» (`Payment::is_conditional=true`). |
| Флаг 🚩 (12-мес. окно) | `php artisan unreliable:recount`, `users.unreliable_*` | **Остается как есть** — быстро реагирующий бинарный триггер на 3+ просроченных обещания за 12 мес. Скор дисциплины — отдельная, вторая метрика, не замена. |
| Группы | [`app/Models/Group.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Models/Group.php) | Единица агрегации для группового скора (`Group::activeUsers()` + `course_group`). |
| Зарплата без учета долга | [`app/Services/TeacherSalaryService.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/TeacherSalaryService.php) переиспользует `DebtorsReport::paymentCovers` | Уже исключает неоплаченные блоки из расчета и пересчитывает при погашении долга — это НЕ меняется в рамках этой фичи. |

## Решения (MG, 05-07-2026)

1. **Составные сигналы, вес на «молчание».** Скор считается из четырех сигналов:
   - **On-time rate** — доля блоков, оплаченных до начала блока (реальный неconditional
     платеж), от всех блоков с момента зачисления.
   - **Promise-keeping rate** — доля обещаний/шагов рассрочки, выполненных `fulfilled`
     до/на `promised_at`, от всех когда-либо созданных обещаний.
   - **Credit-reliance rate** — доля блоков, которые открывались через conditional access
     хотя бы раз, от всех блоков.
   - **Silence events** — количество случаев, когда блок стал долгом и **ни одного**
     обещания по нему не было создано до истечения блока (студент не вышел на связь).
     Штрафуется тяжелее остальных трех сигналов.
2. **Композит — взвешенное среднее, не «худший сигнал».** Один скор 0–100, веса вынесены
   в конфиг (см. §Формула) — тюнинг после первого прогона на реальных данных, не жестко
   зашито.
3. **Окно — с момента зачисления, отдельно от 12-мес. флага.** Скор — lifetime-метрика
   (`joined_at` курса → сегодня), существующий `unreliable:recount` со своим 12-мес. окном
   не трогаем. Обе цифры показываются рядом; lifetime-скор в этой фазе **не меняет** порог
   авто-флага (это возможное расширение Phase 2, не Phase 1).
4. **Гранулярность — 3 уровня.** `Good` / `Watch` / `Poor`, пороги — конфигурируемые
   константы (стартовые `>=75` / `40–74` / `<40`), не hardcode в коде отображения.
5. **Групповой скор — простое среднее активных участников.** Без взвешивания по числу
   блоков в Phase 1 (см. §Не делаем — Phase 2 идея).
6. **Только advisory, не hard-gate.** Скор появляется на карточке студента, в строке
   «Должники» и на уровне группы — **как контекст для менеджера/преподавателя**. Он **не**
   меняет автоматически `Tariff::getDiscountPercentForUser()`, не блокирует рассрочку/
   conditional access и не меняет порог авто-🚩. Это остается ручным решением менеджера,
   как и сегодня.
7. **Кто видит.** Менеджерский дашборд (виджет «Дисциплина по группам», колонка в
   «Должники» и на карточке студента) + preподавательский отчет (свои группы, read-only).

## Формула (Phase 1, тюнингуемая)

```
silence_penalty   = min(silence_events * SILENCE_WEIGHT, SILENCE_CAP)   // напр. 25 за событие, cap 60
score = 100
      - (1 - on_time_rate)     * W_ONTIME     // напр. 30
      - (1 - promise_keep_rate) * W_PROMISE   // напр. 20
      - credit_reliance_rate    * W_CREDIT    // напр. 15
      - silence_penalty
score = clamp(score, 0, 100)

tier = score >= GOOD_THRESHOLD  ? 'good'
     : score >= WATCH_THRESHOLD ? 'watch'
     : 'poor'
```

Веса и пороги — в `config/discipline.php` (новый файл), не в коде сервиса.

## Архитектура Phase 1

### 1. `DisciplineScoreService` (новый сервис)

- `forUser(User $user): DisciplineScore` — считает 4 сигнала + композит по всем курсам
  студента с момента зачисления (переиспользует данные `StudentDebtsService` и
  `PaymentPromise`, не дублирует SQL).
- `forGroup(Group $group): array` — простое среднее `forUser()` по `activeUsers()`.
- Результат — легковесный DTO (`score`, `tier`, `signals[]`), **не персистится** в Phase 1
  (считается on-demand с кешированием на запрос); если окажется медленным на больших
  группах — кандидат на nightly-кеш таблицу, не строим ее заранее.

### 2. Отображение

- Карточка студента: новая вкладка/блок «Дисциплина» рядом с «Обещания оплатить» —
  4 сигнала + композитный скор/тир.
- Страница «Должники»: опциональная колонка «Дисциплина» (тир-бейдж), скрыта по
  умолчанию тогглом колонок — не перегружаем таблицу.
- Новый Filament-виджет дашборда «Дисциплина по группам» — таблица групп с их средним
  скором/тиром, доступна и в `admin`-панели, и (read-only, только свои группы) в
  преподавательском разрезе.

### 3. Конфиг

`config/discipline.php` — веса, cap, пороги трех уровней. Значения — starting point,
явно помечены как «требует калибровки после первого прогона».

## Не делаем (Phase 1)

- **Hard-gate скидок/рассрочки по скору** — Phase 2 идея, если после наблюдения за
  Phase 1 менеджер решит автоматизировать.
- **Влияние lifetime-скора на 12-мес. auto-🚩 порог** — Phase 2 идея (например, снижать
  порог с 3 до 2 просрочек для студентов с `Poor`).
- **Взвешивание группового скора по объему блоков на студента** — простое среднее
  достаточно для первого прогона; если окажется, что один студент искажает картину
  маленькой группы — добавим вес.
- **Персистентная таблица/nightly job** — считаем on-demand, пока не станет медленно.

## Done when

- `DisciplineScoreService::forUser()` / `forGroup()` покрыты фич-тестами на реальных
  сценариях (вовремя / просрочка / рассрочка / conditional / молчание).
- Вкладка «Дисциплина» на карточке студента и колонка в «Должники» работают.
- Виджет «Дисциплина по группам» показывает тир по каждой группе.
- `config/discipline.php` содержит веса/пороги с комментарием «требует калибровки».
- `php artisan test` зеленый; `./vendor/bin/pint` чистый.
- Обновлены [`debtors-manual.md`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/debtors-manual.md)
  (короткий раздел про скор дисциплины) и `.ai_state.md`.
