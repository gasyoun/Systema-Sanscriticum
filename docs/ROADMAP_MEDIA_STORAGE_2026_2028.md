## 1. Резюме

Три факта, задающие весь план:

1. **Сегодня проблемы ёмкости нет** — ~20 МБ. Есть проблема **отсутствия
   сигнала и границ**: до H1345 рост не измерялся ничем, а загрузка материалов
   занятий не имела потолка по количеству файлов.
2. **Вес придёт не из домашних заданий.** ДЗ ограничены 30 МБ × 10 файлов на
   отправку. Материалы занятий принимали видео по 100 МБ **без ограничения
   количества** — вот настоящий источник роста.
3. **Каждый мегабайт бьёт дважды.** `storage/app` целиком входит в
   еженедельный бэкап на Яндекс.Диск
   ([`config/backup.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/config/backup.php)),
   поэтому рост медиа линейно раздувает и объём бэкапа, и время его передачи.

Отсюда порядок: **сначала мерить и ограничить** (сделано, этап 0), **потом
выносить** — и только тогда, когда вынос что-то реально экономит.

**Два свойства сторожа, заложенные намеренно.** Он ничего не удаляет —

упёрся в предохранитель по числу файлов, это отдельная строка алерта, а не
молчаливо заниженная цифра.

## 3. Триггеры этапов

| Этап | Триггер | Что делать |
|---|---|---|
| 1. Замер и калибровка | первый алерт **жёлтой** зоны, либо через месяц работы сторожа | Сверить пороги с фактом. Сегодняшние потолки взяты «в 50–100 раз выше факта» и заведомо приблизительны (`@DECIDE MG`) |
| 2. Вынос материалов занятий в S3 | `public/lesson-materials` > 3 ГБ, **или** суммарный бэкап > 1 ГБ | Самый чистый кандидат: отдаются простым URL, приватности не требуют |
| 3. Вынос архивов сертификатов | `public/archives` > 300 МБ | Генерируемые ZIP, восстановимы — терять не страшно |
| 4. Вынос ДЗ в S3 | `homework` > 1 ГБ | Последним: приватность + миграция построчная (см. §6) |
| — | свободного места < 2 ГБ | Это уже инцидент, а не рост: разбираться сразу, вне этапов |

## 4. Почему не VK как соцсеть

MG предложил заливать медиа на vk.ru, где у студентов есть аккаунты. Как
хранилище для **работ студентов** это не годится, и причины не вкусовые:

- **Приватность и 152-ФЗ.** ДЗ — персональные данные (имя, голос, содержание
  работы). Передача третьей стороне требует согласия; сейчас файлы лежат на
  приватном диске и отдаются через проверку прав.
- **Потеря контроля доступа.** Документ VK доступен любому, у кого есть ссылка.
  Это понижение с «приватного хранилища» до «секретного URL» —
  [`HomeworkController::download`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Http/Controllers/HomeworkController.php)
  сейчас проверяет «владелец / преподаватель курса / админ», и эта проверка
  просто исчезает.
- **API не делает того, что кажется.** В проекте уже есть
  [`VkDeliveryChannel`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Messaging/VkDeliveryChannel.php),
  и он умеет только `docs.save`. Аудио-API закрыт для сторонних приложений с
  2016 года, видео требует отдельных токенов.
- **Долговечность.** VK может удалить контент; ссылки протухают. Работы нужны
  для проверки и возможных разбирательств.

**Рассмотрено отдельно: VK-документы для фотографий (запрос MG).** Ослабление
по типу файла не помогает — дело не в том, картинка это или видео, а в том, что
фотография домашней работы **остаётся работой студента**. Фото рукописного
упражнения — такие же персональные данные, как и голосовой ответ. Единственный
случай, где VK-документ уместен: **публичные** материалы, которые и так
раздаются всем (лид-магниты, открытые методички) — там «доступ по ссылке» не
понижение, а ровно то, что нужно. Такой случай уже реализован в
`VkDeliveryChannel` для лид-магнитов.

Отдельная законная форма исходной идеи — **студент сам заливает видео в своё
облако и присылает ссылку**. Это ничего не стоит и не требует API; годится как
запасной путь для длинных видео, если этап 2 покажет, что видео дорого. Не
внедрено: сейчас 30 МБ в форме хватает.

## 5. VK Cloud и Yandex Object Storage — как включать

Правильная форма идеи «хранить на стороне VK» — это **VK Cloud Object
Storage**, S3-совместимое хранилище. Приватность при этом сохраняется
полностью: bucket закрытый, отдача по подписанным временным ссылкам, контроль
доступа остаётся у нас.

Диск в
[`config/filesystems.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/config/filesystems.php)
**один** — провайдер выбирается переменными окружения, потому что оба говорят
на одном протоколе:

| | VK Cloud | Yandex Object Storage |
|---|---|---|
| `AWS_ENDPOINT` | `https://hb.ru-msk.vkcloud-storage.ru` | `https://storage.yandexcloud.net` |
| `AWS_DEFAULT_REGION` | `ru-msk` | `ru-central1` |
| `AWS_USE_PATH_STYLE_ENDPOINT` | `true` | `true` |
| Порядок цены | ~1–2 ₽/ГБ·мес | ~2 ₽/ГБ·мес |
| Уже используется в проекте | — | Яндекс.Диск (WebDAV) для бэкапов — аккаунт есть |

Довод за Yandex: аккаунт Яндекса уже заведён под бэкапы, то есть меньше новых
сущностей. Довод за VK Cloud: дешевле на объёме и ближе к экосистеме, в которой
уже сидят студенты. Выбор — `@DECIDE MG`, но **не раньше этапа 2**: пока
переносить нечего, решение можно не принимать.

## 6. Что сломается при переносе — знать заранее

Не «переключить диск в конфиге». Три места читают файл как локальный путь и
упадут на удалённом диске:

- [`SendLeadMagnet.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Jobs/SendLeadMagnet.php) — `Storage::disk('public')->path(...)`;
- [`CourseMaterialsArchiver.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/CourseMaterialsArchiver.php) — то же;
- [`GenerateCertificatesArchive.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Jobs/GenerateCertificatesArchive.php) — пишет по `storage_path()` напрямую.

Плюс два свойства архитектуры:

- **ДЗ мигрируют построчно.** Диск пишется в каждую строку `homework_files.disk`,
  поэтому это перенос данных, а не флаг. Зато отдача уже уважает записанный
  диск — код скачивания менять не придётся.
- **`Storage::download()` на S3 погонит файл потоком через PHP.** Нужно
  заменить на `temporaryUrl()`, иначе трафик и память сервера не экономятся, а
  добавляется лишнее плечо.

## 7. Открытые вопросы (`@DECIDE MG`)

1. **Провайдер S3** — VK Cloud или Yandex. Решать на этапе 2, не раньше.
2. **Калибровка порогов** `config/storage_watch.php` после месяца измерений.
3. **Срок хранения работ студентов.** Самый дешёвый способ не расти — не
   хранить вечно. Вопрос не технический: сколько лет должны лежать сданные ДЗ
   после окончания курса. Пока не решено, ничего не удаляется.
