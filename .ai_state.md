## 🧠 Dev Notes & Hypotheses

- **ЛОКАЛЬНЫЕ ТЕСТЫ РАБОТАЮТ:** XAMPP php CLI с включёнными `intl/zip/gd` в `C:\xampp\php\php.ini`. Запуск: `/c/xampp/php/php.exe artisan test [--filter=...]` (в bash `php` не на PATH — звать полным путём или через PowerShell). `.env` из `.env.example` + `key:generate` (gitignored). `openssl_pkey_new` на Windows падает без openssl.cnf — тестовые RSA-ключи фиксируем константой, не генерим в рантайме.
- **ВАЖНО — фронт нужно собрать перед тестами:** layout'ы (`layouts/promo.blade.php`, `layouts/articles.blade.php`) используют `@vite`. Без `public/build/manifest.json` директива бросает исключение → **500** на homepage/лендингах. Это причина «фейлов» `ExampleTest`/`LandingListingVisibilityTest`/`CourseStreamsBlockTest` — НЕ seed и НЕ регрессия. Лечится один раз: `npm install && npm run build` (оба artifact'а gitignored). CI собирает ассеты сам.
- **Cast-ловушка `casts()` — УСТРАНЕНА** (ветка `chore/roadmap-next-wave-and-user-casts`): на **Laravel 10** касты задаются ТОЛЬКО свойством `protected $casts` — метод `protected function casts(): array` появился в Laravel 11 и здесь молча игнорируется (`HasAttributes::getCasts` читает только свойство). `User` и `Announcement` были на методе → касты не работали. Переведены на свойство. **Урок на будущее: в этом проекте всегда `protected $casts = [...]`, не метод.** Ручные `Carbon::parse()`/`(int)` в коде оставлены — они идемпотентны и безвредны поверх активных кастов.
- **«Оплачено» = `['paid','success']`**, не только `'paid'`. Канон `Payment::PAID_STATUSES`/`scopePaid()`. Все инлайн-литералы сведены к канону (#108/#172/#179) — при новом коде использовать `scopePaid()`/`PAID_STATUSES`, не литералы.
- **CodeQL не умеет PHP.** `Analyze (php)` падал на каждом PR. Исправлено в #107 (php→только javascript). **Урок:** grep по локальным рабочим деревьям ≠ origin/<default> (клоны устаревают / трекают не ту ветку — нужен `git pull`).
- **Локальные TG-миграции (2026-06-29):** полный `artisan migrate --force` доходит до БД, но блокируется старой unrelated миграцией `dictionary_words` → FK на `dictionaries`; Telegram support migrations применять точечно через `--path`. Стартовых `support_topic_rules` — 8.
- **MadelineProto 8.7 live-sync — устойчивые грабли (2026-06-30):** (a) `API::__construct()` требует `?SettingsAbstract` — array-настройки дают TypeError до логина; `TelegramSupportSyncService` строит `danog\MadelineProto\Settings` + `getAppInfo()->setApiId()/setApiHash()`. (b) перед конструктором создать родительскую директорию сессии (`dirname(base_path(config('services.telegram_support.session')))`). (c) первый логин **интерактивный** (QR/телефон/2FA) — noninteractive stdin даёт `PHONE_NUMBER_INVALID`, делает пользователь в терминале. (d) первый логин может вернуть `AUTH_RESTART` → sync ретраит fetch один раз. (e) аккаунт с сотнями диалогов ловит `Flood, waiting` на `getDialogs/getHistory` → `TELEGRAM_SUPPORT_DIALOG_LIMIT` (дефолт 20, локально 10). (f) runtime-логи Madeline → `storage/logs/madelineproto.log`; импорт не предполагает `users.telegram_id` в частично мигрированной БД.
- **TG contact linking (2026-06-30):** приватные incoming могут не иметь `from_id` — нормализатор берёт `peer_id`/chat id как `telegram_user_id`, не плодит пустые контакты; `telegram-support:repair-contacts --apply` чинит уже импортированные пустышки. `SupportContactUserAutoLinker` привязывает по точному `users.telegram_id` или структурному `users.telegram_username` (обогащая из Madeline `history.users`/`getInfo`); **ручные `linked_user_id` всегда побеждают** (sync не перетирает, линк контакта поднимается на chat). Рискованные фолбэки через `users.note`/полное имя убраны; legacy `Telegram: @...` мигрируются один раз `telegram:backfill-usernames-from-notes --apply`. Есть admin Filament resource для ручных линков.
- **Academy import safety (2026-06-30):** `students.csv` содержит дубли email при разных ФИО (`users.email` unique) — `ImportAcademyData` мёржит по email только если phone/Telegram тоже подтверждают личность, иначе создаёт отдельный профиль с placeholder-email; пустой Telegram в CSV не стирает существующий `telegram_username`. Для тестов/разовых прогонов есть `--students-file=` (прод-дефолт `storage/app/imports/students.csv`), тесты пишут в `storage/framework/testing/imports` — активный CSV не трогается.
- **Support subsystem ground-truth map (2026-07-01):** wrote [docs/support-subsystem-map.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/support-subsystem-map.md) as the agent-facing companion to the strategy doc [docs/jivo.md](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/docs/jivo.md) — jivo.md's "current state" claims are Jivo-help-sourced and unreliable; verify against the map before touching support. **Three landmines any support work must respect:** (1) **`SupportConversation` name is taken** — it is a per-day analytics rollup (`conversation_date`, counts, `is_unanswered`, `first_response_seconds`), NOT an operational thread; building "the conversation model" under that name collides. Rename it `SupportDailyRollup` or name the operational object `SupportThread`/`SupportCase`. (2) **Two divergent message stores** — `ChatMessage` (web: flat, `answered_by`, `is_read`, no grouping/status) vs `TelegramSupportMessage` (rich: `direction`, `responder_user_id`, `responder_type`, `ai_state`, `raw_payload`, chat-grouped). Don't merge tables; upgrade the web store toward the Telegram shape under a read layer. (3) **External identity is 3+ unreconciled mappings** — `users.telegram_id/vk_id/max_user_id` (outbound bot sends), `SocialAccount(provider,provider_id)` (OAuth login), `TelegramSupportContact.telegram_user_id→linked_user_id` (import). Consolidate, don't add a 4th `external_identity` table. Support infra that **already exists** (don't rebuild): topic taxonomy (`SupportTopicRule`+`SupportTopicAssignment`), AI event log (`SupportAiReplyEvent`), responder mapping (`SupportResponderMapping`), per-message `ai_state`. The `TelegramSupport*` stack is integrated Eloquent models in this app — there is no separate `telegram-support-analytics` subdirectory despite jivo.md's framing.
