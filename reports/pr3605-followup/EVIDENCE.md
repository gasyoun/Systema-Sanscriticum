# PR #3605 follow-up: снятие инлайн-компенсации `!important` — живая проверка

Дата: 07-11-2026 · Машина: verifier-seat (локальный PHP 8.3.36 CLI, `php artisan serve`,
SQLite-база с одной сеяной записью, никакого прод-данных).

Сценарий: админ-панель → «Слоты Календаря» → клик по обложке слота
«Проверка зума PR3605» (файл 1200×1500, 4:5) → зум-модалка.

Замер — `getBoundingClientRect()` модального `<img alt="Обложка слота">`
и его inline-`style` из живого DOM:

| Состояние | inline style | Рендер (w×h) | max-height |
|---|---|---|---|
| **До** (HEAD, компенсация #3605) | `width:auto!important;height:auto!important;max-width:100%!important;max-height:80vh!important;…` | **640×800** | 800px (80vh) |
| **После** (acommit aca4dda4, без `!important`) | `width:auto;height:auto;max-width:100%;max-height:80vh;…` | **640×800** | 800px (80vh) |

Вывод: после скоупления глобального хака `.fi-main img` → `.curator-media-picker img`
(PR #3625, H7487) обычного инлайн-стиля достаточно — рендер байт-в-байт тот же
(640×800 = max-height:80vh при вьюпорте 1000px), картинка 4:5 не сжимается до 150px.

Файлы: `zoom-before.png`, `zoom-after.png`.

Оговорка о скриншотах: в автоматизированном браузере (ZCode in-app) окно модалки
Filament не раскрывается клиентским Alpine-морфом (`fi-modal-open` ставится, но
вложенный `x-show`-div остаётся `display:none`); обёртку пришлось раскрывать вручную
(`style.display=''` на предках с inline `display:none`) — DOM, стили и картинка при
этом серверные, подлинные. Часть страницы на скриншотах отрисовывается без части
CSS того же браузера. Решающие доказательства — inline-`style` из живого DOM и
вычисленный рендер 640×800 в обоих состояниях (см. таблицу).

Примечание: TOTP-секрет/резервные коды на скриншотах не попадали; аккаунт
локальный одноразовый (`pr3605-check@example.test`), база SQLite сеяная, не прод.
