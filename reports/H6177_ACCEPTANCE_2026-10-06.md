## Что считает инструмент

Единица учёта — **одно событие разбора черновика** (минутный журнал программы H6120: «Заполняется человеком или агентом по факту; каждая запись датирована»), записанное поверх СУЩЕСТВУЮЩЕГО механизма — журнал `support_ai_reply_events` (`App\Models\SupportAiReplyEvent`) и словарь источников очереди черновиков (`SupportAnswerSuggestion::SOURCE_*`), без параллельного механизма записи:

- **Исходы разделены:** `accepted_minor` (принят как есть / с мелкой правкой) · `substantial_edit` (существенная правка) · `reject` (отклонён). Знаменатель «Принято черновиков» = все черновики периода, **включая отказы** (правило метрики H6120: «выборка включает отказы»).
- **Отправка НЕ выводится из принятия:** `sent_n` считается только по независимому флагу `sent` — принятый черновик может не уйти (отправка не следует из принятия), отправка может случиться без «принятия как есть» (существенная правка + отправка).
- **Минуты трёх категорий:** `review` (проверка черновиков) / `correction` (исправления) / `incident` (инциденты).
- **Отрицательное время запрещено:** запись с любым отрицательным или нечисловым временем отклоняется целиком (атомарно), ничего не пишется.
- **Дедупликация событий:** повтор того же `event_key` не создаёт вторую строку и не растит счётчики; двойная подача пачки в `tally()` идёт в `duplicates_ignored`.
- **Без текста учеников:** строки журнала несут только дескриптор события (ключи, вердикт, флаг, минуты, время) и счётчики агрегата; агрегат — одна строка на окно (`draft_review_aggregate`), повторное сохранение идемпотентно.

Реализация: [`app/Services/Support/DraftReviewMinutesLedger.php`](https://github.com/gasyoun/Systema-Sanscriticum/blob/main/app/Services/Support/DraftReviewMinutesLedger.php) (+ константы `EVENT_DRAFT_REVIEW_MINUTES` / `EVENT_DRAFT_REVIEW_AGGREGATE` в названной точке входа `app/Models/SupportAiReplyEvent.php`). Длины новых `event_type` (20 и 22 символа) держит штатный `SupportAiReplyEventTypeLengthTest` (reflection-обход всех `EVENT_*`).

## Границы и риски

- Инструмент **ничем не вызывается** в прод-коде: ни роутов, ни джобов, ни команд, ни флагов — добавлены только сервис + константы модели + тесты + этот отчёт (нулевой прод-след).
- Строки живут в общем журнале `support_ai_reply_events`: существующие потребители фильтруются по `event_type`; `SupportObservability` покажет новые типы отдельными строками (ожидаемо, это страница-инвентарь событий).
- Вердикт minor vs substantial — субъективный вход рецензента: инструмент принимает его как запись и не вычисляет из магнитуды правки (у существующего механизма `facts.edited` бинарен — величина правки не фиксируется; выдумывать правило классификации запрещено границами юнита). Честная классификация — за процессом разбора (H6120 / human-минутный журнал).
- Запись минут — ручная/агентская поверхность ввода (`recordEvent()`): без заполняемых записей измерение остаётся «нечем измерить», не нулём (правило H6120).
